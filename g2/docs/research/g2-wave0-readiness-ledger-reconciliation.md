# G2 Wave-0 readiness-ledger reconciliation

This software-only audit replaces several stale or overlapping presentation
totals with disjoint readiness masks. It changes no firmware, provider,
package, flash address, signature, or hardware state. Project-authored audit
code and manifests are MIT-licensed; retained vendor payload authority remains
unresolved.

## Disjoint component equations

| Component | Production source | Generated | Candidate, not routed | Typed retained/external | Unclassified | Total |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Apollo main (Apple authority) | 415,344 | 476,036 | 0 | 3,065,088 | 0 | 3,956,468 |
| Apollo bootloader (Apple authority) | 59,009 | 16,846 | 0 | 87,985 | 0 | 163,840 |

| Touch | 0 | 512 | 14,510 | 19,442 | 0 | 34,464 |

The Apollo-main release-blocking partition is exactly 3,065,088 typed retained
bytes, with zero candidate-only bytes. All three NemaVG stroke-cap entries are
production-routed over 6,614 stock bytes: 1,668-byte `draw_start_cap`,
1,640-byte `draw_end_cap`, and 3,306-byte `draw_caps`. The current retained
unanchored-function mask is 613,302 bytes and contains no stroke-cap candidate
subset. The exact routed address-set digest and empty retained-endpoint digest
are pinned by the current Apollo-origin accounting manifest.

Two corroborating values are deliberately non-additive:

- 17,800 bytes are the Apple flash-plan label reconciliation. They are already
  controlled source/generated bytes and are not additional retained payload.
- 885,418 known physical bytes come from complete-object closure evidence. That
  evidence overlaps the authoritative origin/readiness mask and must never be
  added to a component or aggregate total.

The bootloader's 87,985-byte retained complement is derived from all current
current, contiguous core-manifest intervals. The two 52-byte clock-manager
stock leaves are production-routed source evidence, not candidates; they add
zero bytes to the candidate bucket.

## Touch semantic mask

The former 19,442-byte coarse Touch complement is now an exact disjoint
address-set mask. It contains 15,854 bytes in the code span and 3,588 non-code
bytes: 192 vector bytes, 1,640 string bytes, and 1,756 configuration/table
bytes. The code complement is further split into the mixed CapSense/CAT2
provider, owner-unresolved CFG/dispatch bytes, referenced literals, typed data,
NOP padding, return tails, and the deliberately unresolved zero-halfword
alignment/data boundary. Every row carries address-set and content SHA-256
digests plus its explicit unresolved sub-boundary in
`tools/manifests/g2-touch-final-physical-byte-buckets.tsv`.

This is classification completeness, not source or production completeness.
The 14,510 source bytes remain candidates and the external/resident boundaries
remain unavailable for open production routing.

## EM9305 and GX8002

EM9305's 1,240 reviewed MIT concrete-source stock bytes are production-routed
through the checked ARCv2-EM overlay. The emitted provider accounts them as
1,174 compiled-source bytes plus 1,226 generated/reconstructible bytes; the
remaining 210,584 bytes stay typed retained/external and release-blocking.

The GX8002 external-provider boundary is exactly 326,000 bytes: 190,912
executable bytes, 5,124 initialized runtime-data bytes, 9,164 gxNPU command
bytes, and 120,800 proprietary model bytes. An external provider must
authenticate exact identities. This boundary does not claim that any of those
payloads are openly available or redistributable.

## Dual-profile authority limit

The canonical Apple profile remains the sole current per-byte ownership-mask
authority. Linux has exact component/package totals and three exact
`typed_mixed_profile_ownership` spans, but
`per_byte_ownership_mask_complete=false`; no Linux per-byte ownership is
inferred or fabricated. The current aggregate includes the production-routed
EM9305 frontier and the fully routed NemaVG stroke-cap endpoints; current package
sizes and release-blocking totals are:

| Profile | Source | Generated | Candidate | Retained | Unclassified | Payload |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Apple | 475,527 | 494,744 | 29,396 | 3,749,965 | 0 | 4,749,632 |
| Linux | 257,897 | 411,980 | 29,396 | 4,050,343 | 0 | 4,749,616 |

The checked dual companion must be refreshed only through its explicit
maintainer route after all canonical inputs are quiescent. This audit does not
write that companion or the generated completion report.

## Reproduction

Run the focused software audits from `g2/`:

```sh
python3 -m unittest \
  tests.test_analyze_g2_apollo_origin_accounting \
  tests.test_analyze_g2_first_party_frontier \
  tests.test_analyze_g2_touch_final_frontier \
  tests.test_em9305_source_readiness \
  tests.test_gx8002_source_readiness \
  tests.test_analyze_g2_completion_readiness
```

All operations above are read-only except the explicit Touch manifest writer;
none signs, flashes, publishes, contacts hardware, or uses the network.
