# IAR DLIB math and errno source candidate

Scope: official G2 `2.2.6.10` Apollo-main image.  
Status: source-recreated, cross-toolchain/emulation-qualified, and production
integrated in the reviewed Apple and Linux profiles.

## Result

The final four retained IAR-runtime code units now have a clean-room source
candidate in
[`iar_runtime_math_errno.S`](../../components/apollo_main/core_overlay/candidates/iar_runtime_math_errno.S).
This closes semantic source recreation and production integration for all ten
code units in the bounded runtime census without claiming an exact EWARM
release or copying proprietary DLIB implementation source.

The selector-isolated source is 2,625 bytes, MIT, and hashes to
`b5288643766f14f62a2452f445f58e0e3ec8e09c229f4f9c572b8dd1c5c0f59c`.
Apple Clang 21 and Lorelei Linux Clang 22.1.8 emitted identical function
sections:

| Candidate | Bytes | Unrelocated SHA-256 | Stock contract |
|---|---:|---|---|
| `open_cfw_iar_sqrtf` | 28 | `7fb8c75c9889a4c4d92014218c546be5744eb7bdadaf2f4f5382691c1dd8e888` | hard-float `s0` input/result; negative or unordered input returns stock quiet-NaN bits and sets EDOM |
| `open_cfw_iar_domain_error` | 20 | `a95dc7521a542f97ed53f483e6aa2889d22e128799535f979dfe742f447ed16d` | store 33 at `0x20074F14` while preserving `r0-r3` and the return path |
| `open_cfw_iar_range_error` | 20 | `83e8d326849245389ee02362fd8694d7eedcba34b8ea6330dbdf7ab92048a518` | store 34 at `0x20074F14` while preserving `r0-r3` and the return path |
| `open_cfw_iar_errno_address` | 10 | `86dcc309589b8b5348ab0c836b92cb168f22d3914daf11800ae21fe92e1e8f1b` | return `0x20074F14` in `r0` |

Only `sqrtf` has a relocation: a tail `R_ARM_THM_JUMP24` to the source-owned
domain-error candidate. The other three sections are relocation-free. The
candidate deliberately reproduces the stock BMI-after-`VCMPE.F32` behavior:
unordered NaN inputs take the domain path as well as negative values. This is
a stock-compatibility contract, not an assumption about generic libc `sqrtf`.

## Qualification

[`emulate_g2_iar_math_errno.py`](../../tools/emulate_g2_iar_math_errno.py)
maps the authenticated 3,523,396-byte firmware image and the candidate sections
in one Unicorn instance. Unicorn lacks a Cortex-M55 model, so the harness uses
its Cortex-M33 Armv8-M model for the bounded single-precision VFP instruction
subset. It patches only the candidate's declared tail relocation, initializes
the same core/VFP registers and errno word for stock and candidate executions,
and compares result bits, preserved ABI registers, stack, and errno state.

Lorelei passed:

- 4,000 `sqrtf` inputs, including positive/negative zero, infinities, normal
  values, maximum finite, quiet/signaling NaNs, and deterministic random 32-bit
  patterns;
- 500 randomized register cases for each of EDOM, ERANGE, and errno-address;
- identical section bytes from Apple Clang 21 and Linux Clang 22.1.8.

The candidate-vs-stock total is 5,500 executions. The earlier memory-provider
qualification remains separate at 6,000 executions.

## Production integration

Four full-span, stock-hash-guarded redirects now cover `sqrtf`
`[0x004397A8,0x004397C4)`, EDOM `[0x00439CA4,0x00439CB2)`, ERANGE
`[0x00439CB2,0x00439CC4)`, and errno-address
`[0x00439CC4,0x00439CD0)`. Apple places the four source sections at
`[0x007B42A2,0x007B42F0)`; Linux places them at
`[0x007B49EE,0x007B4A3C)`. The relocated `sqrtf` section hashes to
`6abbf2afeff99d74a786ae15daeae488123c52c8d14ea84292cbabcd74376c47`
under both profiles after its domain tail is resolved.

The twice-replayed Apple overlay/component/package pins are
`131020/3654416/4432910`, with package SHA-256
`86ddab7c751690e16e73bb7d0deb23a5fbdfffac532803f5a836f76a6ac84ca9`.
The twice-replayed Lorelei pins are `132888/3656284/4434778`, with package
SHA-256
`63d5cd1d1cbab2c3ece4a48f96b58a0cb14a7487917831f4c6d370b40ed41d90`.
No image was signed or flashed.

## Reproduction

```sh
python3 -m unittest -v tests.test_iar_runtime_math_errno_candidate
python3 tools/analyze_g2_iar_runtime.py --json
```

On a host with Unicorn, set `OPENCFW_RUN_UNICORN=1` for the optional target
test. The tracked emulator also accepts a candidate binary directory directly,
which is how the Lorelei 5,500-execution run was performed.
