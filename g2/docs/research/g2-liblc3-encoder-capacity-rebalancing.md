# G2 liblc3 encoder capacity rebalancing

Status: conditional software capacity proof; production move blocked and not
applied.

## Question and evidence boundary

The admitted non-HR liblc3 encoder still needs 101,616 aligned bytes at the
current Apollo-main end, while the authenticated interval below the update
record contains 71,100 bytes. This audit asks whether already source-owned
core bytes can close the remaining 30,516-byte shortfall without reclaiming
retained stock/data, crossing `0x007FE000`, or changing the PT/LTPF providers.

The machine-readable authority is
`components/apollo_main/liblc3_encoder/capacity_rebalancing_proposal.json`.
It pins the current Apple core component (`898d5efb...`, 3,885,668 bytes),
overlay (`8c80c3fa...`, 362,272 bytes), build report, core configuration, and
the admitted non-HR specialization. The audit does not rewrite, relink, emit,
or execute firmware and makes no live-hardware claim.

## Authenticated source-owned slot model

The current core already replaces complete stock-function spans with one
Thumb-2 `B.W` followed by generated `NOP` halfwords. Those bytes are not
retained stock behavior: the current image already routes entry to a compiled
source closure and retires the rest of the authenticated function span. A
candidate can therefore use its own stock entry as an in-place container only
when all of these conditions hold:

- exactly one full-span `B.W` patch targets the closure;
- the closure has `strict_relocation_contract: true`;
- its complete text/rodata closure fits the span at its required alignment;
- the final component bytes exactly match the recorded branch-plus-NOP patch;
- the span does not overlap PT, LTPF, or the update record; and
- every relocation and ingress remains explicit and encodable after rebasing.

The filter admits 609 slots. Sorting by descending closure size and descending
function name yields a deterministic minimal prefix. The first 81 closures
save 30,484 bytes and remain 32 bytes below the arithmetic target. The first
82 closures contain 30,598 source bytes in 61,648 authenticated patch bytes;
removing their appended copies and stably repacking the remainder saves 30,676
bytes after alignment.

The current relocated source-owned append region is 248,540 bytes at
`0x007AFF68..0x007ECA44`. Its link receipts include 1,886 bytes of inter-leaf
alignment, four bytes of closure-internal padding, and four bytes of isolated
padding. The selected old copies carry 76 bytes of preceding alignment. Their
stock containers currently contain 61,320 generated NOP bytes after the 82
four-byte branches; these generated bytes are authenticated as containers, not
counted as a separate contiguous append gap.

That conditional layout is:

| Item | Start | End exclusive | Bytes |
|---|---:|---:|---:|
| Repacked core append | `0x00794324` | `0x007E5270` | 331,596 |
| Specialized LC3 text | `0x007E5270` | `0x007EF220` | 40,880 |
| Specialized LC3 rodata | `0x007EF220` | `0x007FDDBC` | 60,316 |
| Alignment before data | `0x007FDDBC` | `0x007FDDC0` | 4 |
| Specialized LC3 data | `0x007FDDC0` | `0x007FDF54` | 404 |
| Remaining protected margin | `0x007FDF54` | `0x007FE000` | 172 |

This is a capacity result, not an authorized placement. It does not assign LC3
runtime imports, writable data, stock ingress, or service-audio lifetime.

## Relocation and ingress audit

The current 1,870 relocated-leaf report contains 5,677 relocations. Of those,
2,406 target another source-owned closure: 1,810 name the owner and 596 use a
fixed address which nevertheless lands inside one exact authenticated closure
interval. A rebalancing linker must remap those 596 records by owner-relative
offset; treating them as retained fixed addresses would be incorrect.

For the 82 selected closures, the audit finds 850 outgoing relocations and 102
incoming relocations. The incoming set comprises 62 calls, two wide jumps,
and 19 PREL MOVW/MOVT pairs; 39 relocation records use fixed targets rather
than `target_function`. Scanning every component halfword finds exactly 146
branches to the old selected entries: 82 generated stock patches and 64
relocation branches. A bytewise scan finds no raw 32-bit pointer to those
entries. The modeled maximum Thumb branch displacement is 3,846,602 bytes,
well inside the signed 16 MiB range.

A whole stable-order repack changes 5,501 relocation sites and 2,181 targets.
The PT interval remains exactly `0x0056F178..0x00577C3C`; the current
`open_cfw_box_uart_handle` closure would move from `0x007D4A80` to
`0x007CF0F4`, so its two source-UART calls would move to `0x007CF14C` and
`0x007CF188`. Both calls can still reach the fixed PT legacy entries, but the
post-link receipts must be regenerated. The LTPF text reservation
`0x00445664..0x00446C5E` and rodata reservation
`0x004FC648..0x004FD786` are excluded from all candidates and remain intact.

## Why the move is still blocked

The conditional stable-order repack would move 1,743 non-selected closures.
1,537 are presently marked strict; 206 are not. Recorded bytes and
relocation rows are not enough to silently promote those contracts. Therefore
the capacity proof cannot be treated as a production move plan.

The smallest unavoidable contract frontier is sharper than the 206-leaf
whole-repack count. Any contiguous shrink of at least 30,516 bytes places the
new overlay cutoff at or below `0x007E5310`. The seven closures which cross or
follow that cutoff are now all strict-authenticated:

- `open_cfw_runtime_strtod_bounded`
- `open_cfw_runtime_strtod`
- `open_cfw_runtime_scanset_match`
- `open_cfw_runtime_vsscanf`
- `open_cfw_runtime_sscanf`
- `open_cfw_runtime_iar_scanf_core`
- `open_cfw_runtime_iar_vsnprintf_engine`

Together they now account for 8,910 closure bytes and 44 relocations, including
the formatter engine's relocation-safe self-call. The minimum suffix blocker
set is therefore empty. That closes the contract frontier, but is not
permission to move bytes: a sparse packing plan still needs an exact link proof
before it may replace the broader conditional repack.

Remaining implementation gates are:

1. add a core-builder mode which places a closure at its authenticated stock
   slot, suppresses its generated branch, and does not touch other stock bytes;
2. implement exact append-hole packing or strict stable-order relocation replay,
   including owner-relative remapping for all fixed internal targets;
3. regenerate PT source-UART and post-link stage receipts; and
4. apply the specialized LC3 relocations, bind its 11 runtime imports, define
   the 404-byte writable-data policy, and add the service-audio adapter.

Until those gates close, `production_rebalancing_feasible_now` remains false,
no placement is assigned, and no OTA image is emitted.

## Reproduction

```sh
python3 g2/tools/analyze_g2_liblc3_encoder_capacity.py --pretty
python3 -m unittest -v g2.tests.test_analyze_g2_liblc3_encoder_capacity
```

The analyzer authenticates every input receipt, derives the candidate prefix,
checks source hashes, models all supported relocation kinds, round-trips every
modeled Thumb branch, scans executable and pointer ingress, verifies PT/LTPF
reservations, and fails if the blocked outcome is promoted without evidence.
