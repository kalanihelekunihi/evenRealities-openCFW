# FreeRTOS `vTaskMissedYield` source-boundary audit

## Result

Apollo main now source-owns the complete FreeRTOS-Kernel V10.5.1
`vTaskMissedYield` leaf. This is unequivocal upstream source reuse rather than
a clean-room reimplementation: the authenticated release body is exactly
`xYieldPending = pdTRUE`.

The upstream baseline is FreeRTOS-Kernel V10.5.1 commit
`def7d2df2b0506d3d249334974f51e427c17a41c`. The bounded adaptation is:

| File | Bytes | SHA-256 |
|---|---:|---|
| `components/shared/freertos/runtime_freertos_missed_yield.c` | 1,749 | `1f7ec93d00e35dcc4cf156d4559924493e46f6cc89c30de1ed7e53442177013c` |
| `components/shared/freertos/runtime_freertos_missed_yield.h` | 1,055 | `0008f68d1196ea92a33a8cfa7bee339733354ccf8d64b96279acf6a43a1a21af` |

The source retains the upstream MIT notice. G2-specific work is limited to
binding the recovered kernel-global address and authenticating the stock
function boundary, caller topology, and generated redirect.

## Stock function and state seam

The complete official leaf is:

| Property | Value |
|---|---|
| Stock span | `[0x004555E6,0x004555F0)` |
| Size | 10 bytes |
| Bytes | `0120dff8581608607047` |
| SHA-256 | `8cada1af8ad4973f2ad647d45c8a0ac9c56fdf2d8b270607844b7940eb7d5d2d` |
| Recovered state | `xYieldPending` at `0x20074A44` |
| Released operation | one volatile `BaseType_t` store of `pdTRUE` |

The official instructions materialize one, load the recovered compatibility
word address, store the value once, and return. No additional read, mask,
hook, scheduler call, or configuration-dependent branch exists in this leaf.
The adapter therefore exposes exactly one volatile store to fixed RAM
`0x20074A44`.

The only direct callers are `BL` instructions at `0x00441FA2` and
`0x00441FD8`. Complete scans found no alternate or interior control-transfer
target, narrow branch, or stored even/Thumb pointer into the stock span.
Replacing the public entry consequently preserves the complete known caller
closure.

## Scope and hardware caveat

This increment owns only the missed-yield request setter. It does not claim
the scheduler transition that consumes `xYieldPending`, the full task
scheduler, the Apollo STIMER/tickless port, or all writers and readers of the
kernel-global word.

All evidence is offline. No G2 was flashed, reset, attached to a debugger, or
used for runtime validation.
