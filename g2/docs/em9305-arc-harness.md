# ARC execution check for em9305 units (wave 25)

Runs the stock lowered asm unit (`git show HEAD:` version) and a C candidate in Synopsys QEMU (arc-2026.03, `arc-sim`, cpu `arcem`) on identical random inputs, and diffs the results.

- Image: `.waves/qemu-arc/Dockerfile` (docker `opencfw/qemu-arc`). Harness: `.waves/qemu-arc/h/` (start.S, call.S, link.ld at 0xc00000, driver.c).
- Run: `.waves/qrun.py <unit.c> <candidate.c> [--orig FILE] [--n N] [--verbose] [--stkw N] [--install]`; batches via `.waves/qbatch.sh <log> <n> files...` (env `QX=--install`). Exit 0 = equivalent.
- Per test: 64 KB PRNG-seeded RAM at 0x800000 and 4 random args. Compared: r0, ordered extern call log (id + args hash), memory hash, callee-saved registers and sp.
- Externs are mocked: function stubs hash id and args and return pointer-safe pseudo-random values; memcpy/memmove/memset are real; data externs are 256-byte buffers. Stub arity comes from the candidate's `extern` prototypes (extra arg registers are zeroed). Stack-pointer args are compared by pointed-to words (`--stkw`).
- Limits: stub side effects on memory are not modelled; MMIO is not modelled; coverage is random-input, not exhaustive. A negative-control mutant (`.waves/emc/neg/n.c`) is caught.
- Results: 7 wave-24 units and 14 gen4 units verified equivalent at 300-600 tests each. gen4 are installed.

## Wave 27 additions (QP/C 6.5.1 verification)

`.waves/w27/q.sh NAME CAND.c [qrun opts]` runs `.waves/qrun.py NAME.c CAND.c --orig .waves/w27/orig/NAME.c` with the qpc-port include paths. The stock side is generated by `.waves/w27/mkorig.py NAME start-end [...]` (lowered stock asm, upstream QP names, `QEP_reservedEvt_` as rodata, module-name symbols shared with the candidate). `NAME` may be a combined stock unit (e.g. `QActive_start_all` = start + activate + QK_sched_, run with `--sym QActive_start_` or `--sym QK_activate_`) so that both sides execute the real callees.

New options: `--clamp "i=mask,|i=orbits"` (arg masks/ORs; `4=,5=,6=` address r4..r6 with `--args7`), `--chunks` (RAM chunk dump), `--handlers` (function-pointer mocks), `--mockobj` (valid QHsm/QActive-like object + event for r0/r1), `--noevt` (keep r1), `--mockeq` (`temp == state`, counting mock top-state so hierarchy walks terminate; needed for `QHsm_dispatch_`), `--mockact` (valid `QF_active_[]` mock objects, `QK_attr_` initialised with intNest 0), `--args7`, `--rename`, `--cflags`, `--sym`, `--nor0` (void functions).

Harness behaviour worth knowing: pinned QP globals (`QF_active_`, `QF_maxPool_`, `QF_pool_`, `QK_attr_`, `QF_maxPubSignal_`, `QF_subscrList_`) are linker `PROVIDE`s at the stock SRAM addresses; the stub `Q_onAssert` aborts the test at the first assert (the real one never returns, so continuing is undefined) and an aborted test compares as ret=0xabcd0000; QEMU-ARC lacks the vendor `log2p1` instruction, so both sides use a software bit-length (`OPENCFW_QEMU_SOFT_LOG2` for the candidate, a substituted loop in the stock orig; harness only, never in the firmware build); the memory hash collapses code/rodata pointers so link layout does not matter.

Results: all 19 QP/C 6.5.1 functions in the stock image (`QActive_ctor/get_/post_/postLIFO_/start_`, `QF_add_/gc/newX_/poolInit`, `QMPool_get/init/put`, `QK_sched_/activate_`, `QHsm_ctor/top/init_/dispatch_`, `QEQueue_init`) are EQUIVALENT at 300-400 random tests each. `QF_bzero`, `QF_init`, `QF_run` are stock deviations from upstream and stay hand-written.

## Wave 28 additions (residual asm to C)

`.waves/w28/q.sh NAME [qrun opts]` compares `orig/NAME.c` (lowered stock) with `cand/NAME.c`; `pre_NAME.h` is an optional pre-hook (`cx`, `rnd()`, `RB=0x800000` in scope) that shapes the inputs so deep branches are reached; `run_<name>.sh` carries `--rename`, `--arity`, `--outb name:argidx`, `--nor0` (void fns), `--handlers`. `TL=<n>` sets the tail length. `conv.py convert ADDR NEWNAME CAND DEST` removes the residual block, renames references, installs the C and registers it in sources.json. Lessons: the ARC delay slot runs before the branch/callee; check coverage with mutants (change a `>=` or constant and confirm MISMATCH) and tune the pre-hook until the mutants die.

`mpywhl`/`mpywhul` (ARCv2 DSP, major-6 opcodes 0x301c/0x301e) cannot run in QEMU; the harness (`dspsub` in `.waves/qrun.py`) replaces them with sext16/zext16 + `mpy`: `mpywhl d,x,y` = low32(int32 x * int16 y[15:0]); `mpywhul` = low32(uint32 x * uint16 y[15:0]). Public ISA docs do not pin the result slice; it was settled from firmware usage (scale/µs constants, a 64-bit multiply composed with mpydu, the Core-spec supervision-timeout rule). An earlier [47:16] model was wrong (see the correction row in C-RECONSTRUCTION-PROGRESS.md). Unproven on silicon.

### em_system handler family (wave 28, e1..e57)

Workflow per handler: `fam.sh TAG START END NEWNAME 'extra renames' 'extra arities' [qrun opts]` (STOCK addresses) lowers the stock extent to `orig/TAG.c`, writes `run_TAG.sh` with the baked options, and runs it (100 tests; a docker run times out at about 90 s, so keep N <= 100). `mut.sh TAG 'sed-expr'` applies a mutant to `cand/TAG.c`, runs, and restores from `/tmp/mut_TAG.good`; `mut2.sh` does the same for two edits. `dis.sh NAME START-END` prints the lowered disassembly (offsets are lowered offsets, not stock offsets). `inst_em.py TAG...` installs through `conv.py` from the table `S` (header text, name, description) and drops the extent from the stock_residual_code.c header; `inst_small.py` does the same for tiny functions that were compared by compiled instructions only. `chkref.py` must print `bad 0` (every `opencfw_em9305_stock_X` / `L<hex>` reference must still be defined; interior labels referenced from C need a `.global`/`.type`/symbol triple before the `L<addr>` label).

ROM mocking: ROM routines are reached through `opencfw_em9305_rom_*` facades in `em9305_link_closure.c`. Harness recipe: `--rename 0x102588=opencfw_em9305_rom_em_cmd_reply_102588,...` maps the stock `bl` target onto the facade name on the orig side, and `--arity name=N` gives the stub its argument count; an unresolved callee shows up as `UNRES_<addr>` and must be renamed to `opencfw_em9305_stock_<addr>` with an arity. Stubs hash up to 8 arguments (`a..h`; args 5/6 go through `stub_hit(id+3000, e, f, 0, 0)`).

Options added in wave 28:
- `--stkw N` hashes N words at stack-pointer arguments.
- `--mmio` models MMIO reads/writes as part of the compared state.
- `--deref name:NWORDS[:idx=hexmask]` hashes words pointed to by an argument.
- `--outp name:argidx:nbytes[:argidx:nbytes]` hashes an out-buffer after the call; set bit 0x1000 in nbytes (e.g. 4116 = 0x1000+20) to skip hashing the incoming bytes when the buffer is an uninitialised stack struct.
- `--stubret name:v1:v2...` makes the stub return a fixed sequence and also fills any `--outp` buffers (drives deep branches).
- `--derefb name:argidx:nbytes:hexmask[:...]` hashes only the masked bytes of an in-parameter buffer (uninitialised padding); combines with `--outp` and `--stubret`; zeroes those args in the call hash.
- `--arity`, `--rename`, `--args7`, `--nor0` as before.

Pitfalls: `ldb.ab r,[r2,n]` loads from the original address and then adds n; `ldb.x` is a sign-extended byte load; `mov_s` does not change flags; `bl.d` runs the delay slot before the callee (its arguments are set there); lowered sizes differ from stock sizes. Always check mutants (boundaries, constants, flag bytes) and tune the pre-hook until they die; some arms are unreachable while a flag byte is fixed (two such survivors in EMSRC_TransmitterTestEnd are documented in C-RECONSTRUCTION-PROGRESS.md). A mutant left applied after an interrupted run must be undone: `cmp /tmp/mut_TAG.good .waves/w28/cand/TAG.c`, then copy the good file back. Never run a mutant and a normal run on the same candidate at once (different candidates may run in parallel).
