## New discovery: custom serialized LVGL bitmap fonts

11 coherent main-image descriptor/cmap/glyph/bitmap chains at loaded addresses `0x77F374`, `0x77F414`, `0x77F428`, `0x77F450`, `0x77F464`, `0x77F478`, `0x77F48C`, `0x77F4B4`, `0x77F504`, `0x77F518`, `0x78001C`. These are custom static resources, not sfnt/TTF/OTF containers. All use 4 bits per pixel; ten have byte-aligned rows (format 3), one continuous packed bits (format 0). A 20-byte descriptor points to 20-byte short-enum cmaps and 16-byte large glyph records `<IIHHhh` (bitmap index, 1/16-pixel advance, width, height, signed offsets). Layout hypotheses are tied to the local upstream LVGL definitions and recovered 32-bit/short-enum ABI configuration; pinned core identity is `344c7c318047b7348e1be8572a9fd4260c251cfa`. Source-file hashes preserve the exact inspected definitions.

Every cmap list is bounds-checked, sparse relative Unicode lists are strictly sorted/distinct, codepoint/glyph mappings are enumerated, reserved glyph zero is zero, glyph bitmap indices are monotonic, and each glyph bitmap lies within the locked main payload. Each descriptor, cmap, sparse/offset list, full referenced glyph table and bounded bitmap store has original SHA-256, payload/bundle ranges and translated loaded addresses. Exact mapped codepoint counts are respectively 102, 401, 299, 13, 399, 314, 100, 13, 16, 11, 157. These include Latin, Greek/Cyrillic and supplementary codepoint candidates; Unicode ranges alone are not claims of visible characters or licensed source font identity. Cmap intervals are half-open and sparse coverage uses the explicit `codepoints` list. The referenced bitmap store may include gaps/unmapped glyphs; per-font stores overlap and must be unioned.

65 resource spans union to **204,732 bytes**, comprising **204,695 previously unknown bytes and 37 suspected bytes** in the baseline. No confirmed-code overlap. This is the major new evidence, not a recovery percentage. All 11 chains now have corroborated font-root and callback joins: six original 36-byte `lv_font_t` records in flash, five in authenticated `apollo_main:decoded:20000000`. Descriptor callback `0x4B26A4`, bitmap callback `0x4B239C` and cmap resolver `0x4B2774` instructions are byte-checked against the locked original (1,342 total instruction bytes). They corroborate `font.dsc@24`, descriptor pointers at 0/4/8, mode halfword@18, bpp bits9..12, format bits14..15, 16-byte glyph indexing, dimensions@8/10, 20-byte cmap indexing and type@18. Root addresses, dimensions and hashes appear in `fontRootRecords`. No static execution occurred; reconstructed C is supporting evidence, not the sole proof. Original instructions and partial independent prior review outputs remain hash-pinned. Callback naming in older candidate C misleadingly says FreeType; these exact callbacks access static LVGL fmt_txt structures, distinct from actual FreeType callbacks around `0x529858`.

The stock aligned 4-bit loop increments a pointer after each low nibble and again after a row when its post-loop bit index is nonzero. This produces `floor(width/2)+1` source stride, including an extra byte for even-width rows. Upstream inspected code has the same progression; the original decoder confirms it. The first-wave renderer incorrectly used mathematical ceil(width/2), causing the unclear U+1F600 raster; corrected decoding visibly shows an outlined smiling circular face. No emoji UI role or font identity is asserted. Its 16-entry opacity table `[0,17,...255]` at `0x786950` is authenticated through the callback literal at `0x4B2694`. FORMAT0_FULL zero offsets indicate missing codepoints except relative zero; corrected exact mapped counts above remove 39 formerly overcounted codepoints.

Twenty glyph PNGs were rendered statically with bounded reads and all 20 inspected through `glyph-contact-sheet.png`; row-major index mapping is in `glyph-sheet-manifest.json`. Observations include A, zero, question marks, geometric rectangular glyphs and the smiling face. Root/ABI joins are closed for this finite set. Fonts are corroborated data in an orthogonal overlay; exclusive baseline remains unchanged to avoid mixing this new detailed ledger into the established partition without a complete updated classifier/conflict reconciliation. No claim of whole-font source reconstruction, source-font identity, kerning completeness, UI caller binding or hardware rendering correctness.
