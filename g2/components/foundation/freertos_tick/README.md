# Actual tick defer, timeout expiry and delayed-list rollover

This provider replaces the `xTaskIncrementTick` fixture in the linked resume/ready/radio simulator. `tasks_tick.c` retains two unchanged MIT-licensed FreeRTOS V10.5.1 function texts from commit `def7d2df2b0506d3d249334974f51e427c17a41c`: increment-tick and a private reset-next-unblock helper. Compatibility macros supply authenticated global cells, preemption/time-slicing behavior and delayed-list swapping. This is a bounded kernel subset, not a complete scheduler or firmware image.

When suspended, a tick increments the deferred-count word and returns false without advancing the clock or releasing tasks. Otherwise it advances the 32-bit clock, swaps delayed/overflow list pointers at zero rollover (requiring the old active list empty), increments the overflow counter, and removes every due state item plus any linked event item. Released state items enter their priority ready lists before the current index. It updates the next-unblock tick to the next deadline or 0xffffffff.

Higher-priority release requests a switch through the return value. Equal-priority time slicing also returns true when the current-priority ready list has more than one task. Existing yield-pending makes an unsuspended tick return true; this function does not itself clear or set that flag for an ordinary expiry. Native resume propagates a true result into its yield flag and PendSV request. No task has necessarily run when either function returns.

Tick count: 0x20074a34; pended ticks: 0x20074a40; overflow counter: 0x20074a48; active/overflow delayed pointers: 0x20074a24/28. Values are ticks; no tick frequency or millisecond mapping is inferred. Call under the kernel exclusion precondition; no masking is added by this function. Tests invoke it with BASEPRI 0x30 directly or through native resume. The actual stock SysTick vector/wrapper is statically identified, not dynamically executed by this target.

Build: `make -C g2 rtos-tick-wsf-simulator`. Run `simulator/verify.py` with the installed OpenCFW Python, the ELF and a fresh output filename. This target compiles tick/resume/list/new-provider objects with an **O0 simulator profile**, preserving target ABI and fwrapv; other linked objects retain their earlier profile. Optimized runs exposed emulator instruction-state divergence. The successful profile is semantic test evidence, not intended firmware optimization or compiled-byte equality. Exact flags/input hashes are bound in the analysis build provenance.

Physical tick interrupts, startup, frequency, task selection/context switch, full object creation/deletion and hardware remain unverified. Queue timeout unlinking does not free the borrowed EventGroup used by queued callbacks. See `g2/analysis/rtos-tick-wsf-2026-10-05/REPORT.md` for comparisons, prior evidence reuse and remaining boundaries.
