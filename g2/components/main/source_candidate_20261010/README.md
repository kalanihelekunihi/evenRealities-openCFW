# Source-owned Apollo main candidate archive

Run `python3 g2/components/main/source_candidate_20261010/build.py` from any directory. This builds fifty-six source translation units for Cortex-M55 and creates `g2/build/source-candidates/20261010-main/main-candidates.a` plus a relocatable combined object. Actual include dependencies, source/header hashes, tool identities, commands, output hashes and unresolved link symbols are recorded in `receipt.json` beside the outputs. The builder reads only declared component sources, their headers, and compiler headers; original firmware is confined to separate validators.

The archive contains ten bounded IAR helpers, one SMP dispatcher, one storage wrapper, two diagnostic-flags getters with an SMP callback adapter, five kernel tick/context functions with a storage adapter, the SMP comparator, five WSF queue/critical functions, the bounded WSF buffer free provider, the bounded SMP CCB lookup, the bounded SMP DB service, the WSF trace wrapper, two logger guard helpers, the SMP state-machine transition tail, and the bounded full smpSmExecute body. Three normal-level logger policy helpers, the non-null logger append primitive, the logger output wrapper, module-length/stack-fill functions, a config-token substring search, fixed five-byte timestamp formatting, the logger postformat suffix, SMP-only extended-log formatting, a bounded integer/string logger formatter with selected width/precision/flag forms and measured 64-bit decimal conversions, a restricted entry-to-return quiet logger path, a bounded all-category-mask/color/token SMP source, a five-row logger module policy, and stock eight-argument SMP plus bounded one-, three-, and four-word logger ABI adapters are also included as lower subcontracts. Their behavioral evidence is in `g2/analysis/extended-log-policy-20261010`, `extended-log-append-20261010`, `extended-log-output-20261010`, `extended-log-memory-20261010`, `extended-log-token-20261010`, `extended-log-time-20261010`, `extended-log-postformat-20261010`, `extended-log-smp-format-20261010`, `extended-log-common-format-20261010`, `extended-log-module-policy-20261010`, and `extended-log-whole-smp-20261010`. The direct logger `0x43d574..0x43d976` remains open; direct SMP body coverage is 10/11. The general variadic formatter at `0x44b76c`/`0x481836` for formats beyond the validated integer/string and 64-bit decimal subset, especially FP64 float formatting, fatal/null-module branches and general caller-format breadth remain before a direct logger claim; actual output transport, fatal target, and initialized shared state remain external boundaries. Behavioral evidence for older units lives in `g2/analysis/iar-runtime-c-candidates-20261010-sol`, `smp-dispatch-candidate-20261010`, `flashdb-c-wrapper-20261010`, and `diagnostic-flags-candidate-20261010`. The ten IAR bodies cover 388 original bytes; SMP covers 402, storage 132, and flags 12. Tick and comparator remain separately bounded source candidates; their reports record original extents and tests. These extents are module denominators, not accepted image coverage.

The storage wrapper short-event-log target is now a four-byte Thumb tail branch to the audio-owned `audio_log_simple` source provider. Its lower policy, lock, formatter and state boundaries remain explicit. The Main relocatable object has nine unresolved symbols: `audio_log_simple`, `g2_fal_flash_device_count`, `g2_fal_flash_device_table`, `g2_fal_partition_rows`, `g2_flashdb_candidate_log`, `g2_flashdb_db_rows`, `g2_flashdb_print_buffer`, `g2_flashdb_print_sink`, and `g2_flashdb_vformat`. The FlashDB `_fdb_db_path`, `get_kv`, FAL-mode `_fdb_flash_read` and `_fdb_flash_write`, `find_kv` routing, no-cache find wrapper/callback, KV iterator routing and next-sector/next-KV arithmetic, magic-word scan, sector-cache lookup/update, KV and sector readers, FF continuation, and one-bit status decoder/writer, 64-row `cache_update`, `cache_lookup`, and CRC32 bodies are source-defined and stock-compared; FAL device selection and indirect read/write callbacks remain lower contracts. The FlashDB literal table owns five exact diagnostic strings and relocates its database-base slot to that external object; the pinned get-blob local body is source-defined with lookup, name and print left as lower contracts. SMP and IAR callbacks remain explicit behavioral dependencies even where function pointers produce no unresolved linker symbol. Production ABI adapters, source-owned provider implementations, RAM initialization/data placement, producer code generation, whole-image linking and byte equality remain open. The generated archive is neither a firmware payload nor a flashable image.
