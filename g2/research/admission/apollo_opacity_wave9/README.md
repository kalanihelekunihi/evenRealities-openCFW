# Apollo opacity wave 9 boundary

This software-only research record closes the complete actionable static
closure rooted at `0x0051A8EC`: four functions and 3,308 official opaque
bytes. Every function envelope, decoded range, call edge, terminal, interior
island, and direct support-data island is authenticated against the checked-in
official image and decompiler corpus.

The first three bodies implement bounded elliptical-arc, cubic-segment, path
command, and stroke geometry behavior. Their topology is consistent with the
already recorded vector-path community, but the checked-in Nema provenance
does not resolve any of their exact function identities. The public Apollo5
archive was generated by GCC and is explicitly not byte-identical to the
IAR-generated stock. The original IAR archive/private source remains absent.
No Nema license is therefore assigned speculatively.

`0x00563F40` has a complete single-precision tangent-compatible body, including
range reduction and a pinned coefficient table. The exact IAR DLIB release and
maintained implementation source are unavailable, so the semantic role does
not become a source or license claim. It remains a proprietary-runtime-source-
unavailable external boundary.

The root contains 12 bytes of literals/padding between decoded ranges; those
bytes are already included in its 2,090-byte envelope. Five merged support-data
islands contain another 124 physical bytes and are outside the four official
function envelopes. Both partitions add zero bytes to the opacity subtraction.
The eleven terminal callees are reconciled to earlier waves, the parent
first-party bucket, or the existing clean-room `sqrtf`, and likewise add zero.

All four new bodies remain typed external boundaries. No callable replacement,
binary overlay, signing, flashing, probing, or hardware operation is performed.
