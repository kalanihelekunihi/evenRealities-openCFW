The original body supports three selected SDK-style behaviors: method >=18 returns before table dispatch; zero processor skips dispatch; len below the selected minimum returns before processor dispatch. The method compare is signed BGE, but the method has already been narrowed to a byte derived from a byte opcode, making the described >=18 test equivalent over this input domain. The minimum-length comparison zero-extends len to uint16 and uses unsigned BCC. The timer call precedes that comparison; both short matched fixtures record the timer hook and no processor hook. The positive WRITE/MTU controls record timer then processor, matching minimum lengths 1/3.

Processor hooks log fields and return without parser behavior or changing event status. Thus “stops timer before reject” should be read as “calls the timer-stop provider before rejecting,” not validated cancellation or asynchronous timer behavior. Source projection agrees with the newer SDK guards; no compiled old/new C comparison or full producing-version identity follows.

Readable backing memory exists even for len0, and opcode is read at packet+8 before the minimum-length guard. This receipt cannot claim safety for unreadable or physically truncated packet memory, a vulnerability fix, general malformed-input safety, or validity of methods13..17/minimum-table reachability.
