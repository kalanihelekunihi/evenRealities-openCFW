# RTC setter owner contract and overlap correction

Use the direct setter at 0x4D3ADC. r0 points to ten little-endian uint32 words in field order shown in fixtures.json; every supplied word is constrained to uint32. +0 read-error is ignored. +4 weekday is independently validated 0..6 and never recomputed. +8 century is not validated and only its low bit reaches CTRUP bit 28. Remaining fields are year +12, month +16, day +20, hour +24, minute +28, second +32, hundredths +36. Do not route through application DRV_RtcSetTime because its separate weekday provider changes the test dependency graph.

Public source provenance: registered HAL commit 5efc0228528a8adce5eae0d226fac85d2551eb3b, source and header am_hal_rtc.c/.h. Source has Ambiq BSD three-clause terms. Authenticated SDK 5.2 ZIP member has identical functional C after comments/whitespace removal; source hashes are retained in static-receipt.json. No licensed SDK content is redistributed. This establishes available candidate source, not unique producing-source identity or full linked-byte equality.

[22 fixtures](fixtures.json) and [oracle](oracle.py) supply exact status and ordered writes. Failed validation returns 1 with no MMIO; successful validation returns 0 and writes WRTC on, CTRLOW, CTRUP, WRTC off. MMIO addresses independently read from locked literal words 4D3CD4/4D3CD8/4D3CDC are 40004800/40004820/40004824. CTRLOW packing masks hour 0x3F, minute/second 0x7F and hundredths 0xFF. CTRUP masks century 1, weekday 7, year 0xFF, month 0x1F and day 0x3F at shifts 28/24/16/8/0. Year 100 passes validation and uint8 BCD conversion yields 0xA0, producing year field 00A00000. It is not a claim that physical RTC/calendar accepts this date.

Each valid fixture starts control with nonzero sentinels: first store is control OR 1, final store is control AND ~1. CTRLOW/CTRUP replace whole words rather than preserve their previous sentinel values. A WRTC-already-set fixture records repeated first store and final clearing. Gregorian consistency is intentionally absent: February 31 is accepted by this software validator. Null pointer access is not a valid API-contract fixture; it must not be converted into a invented status return.

Model assumptions: registers are deterministic word storage with write recording; no counter advancement, autonomous write-busy changes, oscillator state or concurrent actor. Compare full 40-byte input retention and guarded stack/buffer writes. Execute the real stock validator and BCD helper; no provider substitutions. Authenticate exact masks, BL targets and instruction write PCs before execution. Candidate oracle is a source-contract prediction, not already passed stock behavior.

Correction: emulator docs/rtc-register-audit.md already documents execution of the identical 190-byte setter hash at relocated 0x4E4918, including weekday 0..6, weekday 7 rejection, ordinary BCD and four-write sequence. The initial opportunity search missed that execution because it searched selected old addresses. Therefore the general setter is NOT a wholly new execution target and adds zero new address coverage. Novelty is bounded to additional validation/year-100/ignored-field/sentinel cases absent from the inspected prior producer tests. This is not an exhaustive all-tests absence proof; owner should check any current receipts before running. Existing register-model tests concern separate peripheral behavior. Do not add another 190 bytes to coverage.
