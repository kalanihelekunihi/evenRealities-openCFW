# SDK 5.2 delay discriminator: independent audit

A newly available SDK source change gives a finite discriminator for an already authenticated dependency. Stock `am_hal_delay_us` at `[0x4807a0,0x4807f0)` uses floating-point scaling and HP adjustment 24. SDK 5.2 `am_hal_utils.c` uses `us * 83 + (us + 1) / 3` and HP adjustment 25. The pinned 5.1 source computes HP adjustment `(13 * 250 / 96 + 40) / 3`, which is 24. This excludes unchanged SDK 5.2 delay behavior at this selected stock function; it does not exclude the entire SDK or establish a complete producer version.

[Receipt](receipt.json) independently authenticates the stock extent, adjustment instruction and 250/96 literals from the locked payload, and the actual SDK source formula. Existing [disassembly](../../ambiq-critical-2026-10-05/original/disassembly.txt) provides the instruction interpretation. Existing [delay investigation](../../ambiq-critical-2026-10-05/original/README.md) records the stored scatter input and static decoder mirror. No sealed test was rerun, firmware executed, source implemented, or canonical ledger edited.

A finite next owner goal is compare the pre-loop iteration count in both clock modes for microsecond inputs 0, 1, 2, 3, 4, 10, 100 and selected floating-point rounding boundaries. At HP input 1, pinned source produces 83 minus 24 = 59 iterations; SDK 5.2 produces 83 minus 25 = 58. Capture entry to ITCM 0x40 as the comparison boundary. Complete runtime scatter initialization is a separate requirement for claims about executed loop behavior. Physical time, oscillator calibration, bus/cache latency, and hardware exception delivery remain unmeasured.

The gap is not missing public source or missing ROM bytes. The full floating-point conversion and initialization contract was explicitly left as a simulator seam in the existing critical-provider report. The new source release narrows lineage without closing that semantic gap. No new duplicate hardware or audio coverage is claimed.

DSI is not promoted to a G2 goal: the consolidated hardware reference documents panel transfer through MSPI0 QSPI, and this audit has no bound DSI consumer. ITM disable mask and FPU disable fixes in SDK 5.2 are other authentic source deltas, but lack selected stock bindings here; they remain candidate-search leads, not evidence of stock bugs. Thus useful static research is not universally exhausted. The next step is bounded delay-contract analysis; unbound DSI/ITM/FPU changes do not justify a broad test campaign.
