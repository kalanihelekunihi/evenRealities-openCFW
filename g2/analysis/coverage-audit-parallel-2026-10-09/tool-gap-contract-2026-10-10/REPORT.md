# New-tool audit: build gap and finite TLSF contract

The current gate remains P2 recovery/review. New tools can accelerate address/type/call-graph evidence and comparison, but installation does not pass corpus freeze or authorize early production C implementation. The target remains all six payloads and the locked outer bundle. A modifiable compatible image and a byte-identical source rebuild are separate outcomes; existing isolated emulator profiles are not a full deployable image.

## Tool-specific value and current evidence boundary

Ghidra MCP's installed source documents decompilation, cross references, typing, P-code/data flow and debugger operations. Use read-only byte/disassembly/callee/type queries against a copied hash-authenticated program to replace manual bundle searches and expose missing indirect callees. Retain program hash, image base, processor/language, Ghidra version, query arguments and raw returns. No tool names from this server were callable in this audit's active tool metadata; installation/activation verification belongs to the other track. Do not mutate active projects or treat a successful server health check as a correct image import.

Ablation source documents ARM32 and ARC EM/HS support plus function profiling/CFG/semantic search. Its installed core/launcher verification is inherited from the delegation; no firmware-specific raw/Thumb/M55 import has been validated here. Use a bounded independently decoded function first: authenticate VA-to-file mapping, Thumb state, every instruction and literal target against the existing receipt. Semantic similarity ranks candidates; it does not prove source identity. Its advertised table does not list C-SKY; do not infer codec support from generic ELF parsing. ARC support still requires the vendor-extension operation boundary already recorded in QP evidence.

REA source describes an analysis/orchestration layer over existing Ghidra/Hopper/IDA engines, with evidence/limitations and workflow registration. Useful role: preserve query lineage and keep hypothesis, disassembly, source, comparison and unresolved callees together. Its activation is not yet confirmed in this audit. It does not provide licensed original compilers, hardware register semantics or source completeness merely by orchestrating the existing engine.

These statements are based on local installed README/source, not marketing capability independently tested on G2. No installations/configuration/projects were changed or live-debug/device operations attempted.

## Strong finite build-oriented hypothesis

Test main TLSF provider behavior against genuine pinned v3.1 source before broad new-source acquisition. The BSD-3-Clause source at registered pin deff9ab509341f264addbd3c8ada533678591905 is already retained with acquisition hashes. Existing bootloader source-layout evidence establishes 32-bit 24x32 control geometry/0xC74 for that payload only. Do not transfer geometry to main without checking it. [Four-entry receipt](TLSF-ENTRY-RECEIPT.json) authenticates main create-with-pool 4D06EC, malloc 4D0722, free 4D0808 and realloc 4D0868 plus their direct callees.

Existing audio file-close tests use actual stock TLSF providers on both sides; they explicitly do not independently reconstruct the whole allocator. Their 48 wrapper comparisons must not be relabeled as source-provider validation. Bootloader allocation implementation exists historically and remains a separate owner's scope. This proposal targets main source/layout and allocator provider closure, not repeat audio lifecycle tests. Bounded report searches found no whole-main stock-versus-pinned-TLSF-source comparator; that is not an exhaustive absence proof. Check the current owner's inventory before running.

Use the new tools first to bind actual main control size, block-header fields, alignment, bit scans, assert/log providers and every transitive allocator callee. Reject the hypothesis if those contracts conflict with public source. Do not mask unexplained fields or substitute arithmetic/providers merely to obtain a pass.

## Validation contract: five separate receipts

1. Source attribution: pin/hash/license, authentic main function extents and transitive call/field evidence. Matching names/source paths or geometry alone gives a candidate, not producer identity.
2. C compilation: unchanged public-source offline comparator only, recorded 32-bit target ABI/compiler/options/generated headers. Capture layout assertions and undefined symbols. No production firmware C admission before the gate.
3. Link closure: list every relocation and undefined/called provider with genuine supplied implementation or explicit external boundary. Native host size_t/pointer width cannot stand in for the ARM32 contract. Abort on unknown external calls.
4. Original-byte equivalence: compare complete linked function extents/literals after separately evidenced address binding. Distinguish behavioral equivalence from byte match; preserve mismatches and no silent masked relocation/discarded-tail equality.
5. Behavior: finite stock/source allocator sequences in guarded 64KiB arenas: empty initialization; sizes 0,1,3,4,5; split/reuse after free; adjacent free/coalescing in both orders; allocation failure; realloc shrink, adjacent grow and move with retained contents. Compare arena-relative returned offsets, complete arena metadata/data and guard bytes. Assert alignment/failure/provider boundaries from original instructions. These are deterministic software fixtures, not live concurrency/cache/heap safety or hardware compatibility.

The new tools' concrete first acceptance test is identical bytes/CFG/callees for 4D06EC and its children against the existing static receipt. Only then use them to accelerate the remaining allocator layout. No canonical admission or recovered-byte counter changes arise from this proposal. Remaining full-build evidence includes complete reviewed corpus, compiler/runtime/configuration identities, transitive link composition, assets/container reconstruction and whole-bundle equality; physical compatibility additionally needs actual device behavior under separately authorized testing.
