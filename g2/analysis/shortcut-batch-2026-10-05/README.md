## How the pieces fit

This is a set of microcontroller programs, including a single Apollo RTOS image with linked libraries and product services, not a desktop OS plus separable userland. Boot ROM/SBL and scatter/init establish memory, interrupts and executable entry. FreeRTOS and compiler runtime provide task/list/queue/TLS contracts. Ambiq HAL and board glue configure GPIO, IOM/UART/MSPI, DMA, power and cache. Vendor middleware supplies BLE, display acceleration, filesystems, fonts and DSP. Product integration connects those layers, including asynchronous buffer ownership. EvenHub and UI feature services sit above them but still call hardware-facing policies; a purely app versus hardware partition is not necessarily disjoint.

`dependency-interface-map.json` records 11 reusable families with grade, source/version, role, consumer, interface addresses, reuse recipe and missing dependencies. Historical exact or normalized archive matches, source/config lineage and unknown ownership remain separate. Selected pins are comparison baselines unless producing-source identity is proved. Detailed original evidence cited by consolidated references may have been pruned; those findings are not silently promoted to newly reauthenticated matches.

**No absolute Even-authored byte count is justified.** A historical `first-party` module label or a name such as EvenHub is positive product association, not proof of who authored each instruction. Vendor adaptations, contractors and copied library code can live inside product modules. The small held-out source-correspondence test strengthens vendor attribution only for its bounded behavior; unmatched code remains unknown.

## Practical vendor-blob route versus final goal

A practical experimental firmware can preserve legitimate vendor bytes/resources and link known source around them if their ABI, relocation, startup, lifetime and licensing contracts are satisfied. This batch neither builds nor certifies such an image. Official firmware/derived artwork rights are not granted by root MIT; EM controller and Nema/other vendor archive redistribution remains unestablished. Consult each actual distribution's terms before distribution, not a mirror or top-level SDK license.

The separate final goal remains a blob-free source build byte-identical to the locked bundle. Passing through executable blobs, opcode arrays or licensed archives does not meet that goal; preserving non-executable data also requires an explicit source/resource provenance policy rather than disguising code as an asset. Compiler/linker/object order, private runtime variants, missing ROM/NOR inputs and closed implementations remain boundaries. No new source-built payload, global C percentage or byte-identical claim follows from this batch.
