# CASE legacy no-action branch, bounded source comparison

The original CASE image `g2/blobs/official/g2-2.2.6.10/firmware_box.bin` is authenticated as SHA-256 `36ca0c13558f252af286ae2b36b5e576d087d21d37b15d778e7da9f502a70374`. `verify.py` runs stock legacy entry `0x08000928` on a Cortex-M0-compatible Unicorn model and independently compiled ARMv6-M `case_legacy_default_branch`. The isolated source is `g2/components/case/legacy_default_candidate_20261010/default.c`. The comparison passes **117 cases** over 13 no-action opcodes (`0x00`, `0x01`, `0x7f`, `0xa6..0xa9`, `0xac`, `0xad`, `0xb1`, `0xd5`, `0xe0`, `0xfe`), three logical lengths and log-state bytes `0`, `1`, `0x7f`. Return value, log and control state bytes, lower-call absence and non-stack writes match. The source body does not read original firmware.

The previous switch table correctly identifies target `0x080009fa` for its `0xaf` table slot, but the full entry handles opcode `0xaf` earlier at `0x080009b8`; a test with that opcode reached logger `0x08009170`. Thus `0xaf` must not be classified as a universal no-action command. The current child is purposefully narrower than the public legacy handler, whose outer frame dispatcher accepts arbitrary payload opcodes. It is **not integrated** as `case_legacy_command`. The two direct handler imports and lower `case_vformat` remain open. Completion stays **10/12 direct CASE contracts**.

**Archive delta:** zero; retained deterministic baseline is **43 objects, 70 provided symbols, three unresolved imports**, archive SHA-256 `3fd6b453372e695c75fbb4a057217031809c5fd989dead729b1d43f18c0f9951` from `case-tx-complete-provider-20261010`. Remaining bounded contracts: one full legacy command handler (ten table targets plus high-opcode branches), one binary command handler (at least fourteen visible values), and one variadic formatter. The next branch proof should cover `0xaf` including its logger call and then the remaining table/high-opcode children. There is no defensible duration estimate from the current corpus. Hardware reset, standby, physical output and whole-image linkage remain separate.
