# Independent review: notification to PCM consumer

**Disposition: bounded source and evidence accepted with stated limits.** I checked the source against the captured stock disassembly and literal values, reviewed the scoped-hook comparison, and independently ran 13 stock/source cases on the linked ELF. The spot checks covered enqueue success and full-queue failure boundaries, mode 1 callback dispatch, fresh mode 0 consumer dispatch, queue FIFO filling, unsigned tick rollover at ages 40 and 41, and a staged sequence with RX partial rearm followed by TX busy return 9 and age-40 consumption. The last sequence uses explicit synthetic peripheral progress and PCM mutation, not a claim about real DMA timing.

The source matches the bounded execution order. The notifier constructs a 12-byte type/reserved/tick message and enters the queue send path; successful queue acceptance stops before the thread-flags provider, while failure stops before the logging provider. The consumer reads the message tick, uses unsigned modular `now - tick`, accepts ages below 41, calls the real selected-buffer getter, increments the counter, and dispatches mode 0. The original dispatcher narrows mode to a byte, checks null pointer/zero length, tests the selected table row’s callback and mode byte, rereads callback before the indirect-call boundary, and sends unregistered mode 0 to the DSP entry. The authenticated literal at `0x57b3b4` resolves to table `0x20073c20`, as used by the source.

The disposition label `AUDIO_WAKE` denotes queue acceptance and the next flags-provider boundary; it is not evidence of a task wake or context switch. Likewise `AUDIO_QUEUE_LOG` denotes the queue-failure branch stopped before logging. The header identifies these as observation boundaries. The report correctly leaves scheduler unblock, flags handling, callback/DSP bodies, initialized dispatcher RAM, and actual routing out of the executed scope.

The comparison passes 328 calls and traces 1,312 distinct original instruction bytes. A broad Unicorn memory-hook profile skipped an original post-copy load and misadvanced the 12-byte queue write pointer; the retained scoped profile executes that load and matches final queue bytes/pointers. This instrumentation-sensitive diagnostic is disclosed and receives no coverage credit. Queue payload bytes are compared after calls, although the final profile deliberately does not instrument each queue/stack memcpy access. That limits instruction-by-instruction copy observations while preserving the checked post-call state.

No blocking implementation issue found. Remaining limits include synthetic coherent queue/peripheral state, unexecuted wait/unblock/flags providers, unexecuted callbacks and DSP, no boot-authenticated dispatcher table, no real task scheduling, and no PCM ownership/lifetime, cache coherence, or physical DMA claim. The source prefixes return new observation descriptors at explicit cuts rather than claiming the stock callback/ISR ABI.
