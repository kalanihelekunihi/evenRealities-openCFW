# CASE039 and waves056–060 independent available-evidence review

Scope is pinned by `../input-manifest.json` (422 file hashes; all matched at review time). This is a bounded source/evidence review. It makes no global admission, formal corpus, image, hardware, or physical-acceptance claim.

## Findings

1. **Callback call type does not match registered callback definitions.** The recovered trampoline calls `pair[0]` through `void (*)(uint32_t)` and supplies `pair[1]` (`g2/components/case/startup_candidate_20261011/application_boot_transport_trampoline_candidate.c:23-25`). The six timer callbacks registered at `application_boot_transport_start_candidate.c:12-17,27-32` are declared/defined as `void(void)`: `case_boot_transport_cb_9d70` at `application_boot_transport_clock_callback_candidate.c:9`, `_bb4c` at `application_boot_transport_toggle_callback_candidate.c:6`, `_9684` at `application_boot_transport_cb_9684_candidate.c:16`, `_b7ec` at `application_boot_transport_cb_b7ec_candidate.c:13`, `_bb90` at `application_boot_transport_cb_bb90_candidate.c:17`, and `_ab70` at `application_boot_transport_idle_callback_candidate.c:7`. Calling a definition through an incompatible function type is undefined behavior in C. On the intended ARM AAPCS the extra R0 argument is ordinarily ignored by these bodies, which explains why the entry-cut comparisons pass; those comparisons do not validate the C function type or callback bodies. **Suggested repair:** change the six declarations and definitions to accept one `uint32_t` argument and explicitly discard it where unused. Then rebuild the source ELF and rerun the affected checks. This is a source-contract defect, not evidence that the native trampoline passes the wrong register value.

2. **Wave060’s aggregate is target-level, not use-site closure.** Recomputed from its pinned `verification.json`, it has 51 distinct RAM target keys and 366 sampled operand PCs: 260 PCs have exactly the expected constant on all modeled syntactic predecessors; 106 are unresolved or include `null`. For example target `0x20000892` has 11 unresolved examples out of 12; `0x2000087e` has 6/12. The checker labels a target confirmed if *any* example for it is confirmed (`check.py`, final aggregation), so `51/51` means each target has at least one resolved sample, not that every use has a proved base. The artifact itself does list the per-PC uncertainty and explicitly limits claims; keep those site-level counts visible anywhere the `51/51` headline is reused.
