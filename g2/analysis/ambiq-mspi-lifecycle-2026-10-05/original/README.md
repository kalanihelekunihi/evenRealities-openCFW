# Apollo MSPI disable and deinitialize evidence

This bounded packet authenticates the specified 118-byte disable body at `0x4c0ea8` and 56-byte deinitialize body at `0x4c0f24`, plus selected authenticated callers. Reproduce the hash/address checks and disassembly with `~/.local/share/opencfw/venv/bin/python verify.py`. The script checks the official OTA and decoded Ghidra image hashes, cross-checks function records and exact named caller hashes, verifies direct callsites and pinned source-file hashes, and emits `disassembly.txt`. It creates `results.json` exclusively; remove only that generated file before a deliberate rerun.

Official input: `g2/blobs/official/g2-2.2.6.10/ota_s200_firmware_ota.bin`, 3,523,396 bytes, SHA-256 `36c5b0e499a68ac2493a497bdab9740fd3e7027730c26a9094eca47268a27863`. Ghidra's image is the OTA payload after the 32-byte preamble, size 3,523,364, base `0x438000`, SHA-256 `19044a72bdfeb04c6b1b104d87da7b98e13cc18928528d84d999b6bcc0ba9701`. Thus decoded offset = runtime address − `0x438000`; OTA file offset adds 32. Exact half-open ranges and hashes are in `results.json`.

The disable body validates a non-null handle prefix against literal `0x01bebebe` at `0x4c0f68`; invalid returns 2. It tests enabled bit 25. Already disabled returns success (0). Otherwise it refuses with status 3 if either word at handle offsets `+0x840` or `+0x20` is nonzero. If the word at `+0x18` is nonzero, it calls `0x4bfd62` (command-queue disable); any nonzero result is returned immediately. On success it calls `0x4bfc86` (queue termination). It then clears bit 25 in the handle prefix, reads module index at `+0x04`, and checks bit 0 of the register at `0x40060000 + module*0x1000 + 0x90` (DEV0XIP XIP enable). If set, it loads a delay value from `+0x8cc` and calls `0x4807a0`. Otherwise it skips the delay call. Successful paths return 0.

The deinitialize body validates the same magic (invalid returns 2). If enabled bit 25 is set, it calls disable at `0x4c0ea8` but does not branch on or preserve its returned status. It then clears prefix bit 24 and zeros the module word at `+0x04`, returning 0. The instructions therefore show that deinitialize ignores a busy/error result from disable and proceeds with these handle writes; no additional claim is made about what happens to external queue state in that case.

Field offsets above are direct word offsets recovered from these authenticated instructions. Their labels are corroborated against the pinned SDK private state definition, but this note does not assert a complete private structure layout. Source comparison: pinned `g2/build/foundation/ambiq-upstream/am_hal_mspi.c` disable/deinitialize at lines 2277–2360; the private state fields include `pTCB`, `ui32NumCQEntries`, `ui32NumHPEntries`, and `ui32XIPOffMinDelay`. `am_hal_global.h` defines the handle prefix bitfields (`magic` 24 bits, `bInit`, `bEnable`); the binary's clear masks align with `bEnable` bit 25 and `bInit` bit 24. Source and header hashes are in `results.json`.

Authenticated caller evidence is limited to call instructions and checked decompilation. `FUN_00470d7c` calls disable at `0x470d86`, then only on success attempts device reconfiguration and restart. `jbd4010_power_off_sequence` (`0x593200`) calls disable at `0x59326a` before later device control calls. `am_devices_mspi_device_reconfigure` calls disable at `0x59c87e`, then on success continues with device configuration/restart. `FUN_0046fb0c` calls deinitialize at three cleanup sites (`0x46fc20`, `0x46fc96`, `0x46fcf6`) after initialization/configuration failures. The exact caller hashes and direct callsite bytes are in `results.json`.

These are static observations; no runtime state transition or hardware behavior was tested. Pinned SDK source supports behavioral correspondence, not compiler/version/options reproduction or byte-identical source build.
