# Early PCM buck override and registered dispatch closure

**Six newly recovered providers**: buck override 0x47FE6C; before-override 0x480358, before-enable 0x48036E, after-enable 0x480384, TON-initialize 0x4803AC and TON 0x4803C2. Source is [dispatch.c](../../components/audio/early_pcm_dispatch_offline/dispatch.c) with [interface](../../components/audio/early_pcm_dispatch_offline/dispatch.h).

Buck control performs three ordered read-modify-writes at MCUCTRL.VRCTRL 0x40020060: SIMOBUCKOVER bit16, CORELDOOVER bit0, MEMLDOOVER bit5. Each follows low bit of byte-narrowed input, preserving other bits. This changes override controls; it does not establish actual rail readiness, timing or power completion. Public Ambiq Apollo510 pwrctrl source supplies the matching three-bit sequence, pin 5efc0228528a8adce5eae0d226fac85d2551eb3b.

Callback registry base is 0x20073270. Slots +14/+18/+1C/+20/+24 select those five dispatches. Existing offline symbol names are compatibility labels and some are semantically wrong: pcm_before_enable_dispatch selects before-override; pcm_after_enable_dispatch selects before-enable; pcm_tempco_suspend_dispatch selects after-enable; pcm_lp_switch_initialize_dispatch selects TON initialization. Use address/slot identities, not those names, until an additive corrected-interface successor is built. Null returns zero; non-null body return is forwarded. Each slot is read for check and again for invocation. TON narrows both inputs to bytes. This volatile registration indirection is not a static binding proof.

**442 PASS comparisons** =410 provider fixtures +32 early GPU on→off compositions. Known real before/after/TON/LP children execute in the source-only native region. The fixture called suspend is actually after-enable dispatch at0x480384, populated synthetically with a no-op child and stopped before that child. It proves neither suspend behavior nor actual registration. Other known-child fixtures likewise inject callbacks deliberately; actual stock registration is separately recorded by the preserved registration batch.

**748 additional PASS comparisons** =608 reused variant-initializer cases +28 initializer→GPU and112 initializer→temperature compositions. Initializer0x5A08E4 was already sealed in audio-trim-initialization-closure; no duplicate initializer source is retained or counted as new. Reused initializer eagerly caches major/version/date while stock reads conditionally/repeatedly: comparisons require stable synthetic fields and do not claim identical volatile read traces. Across both suites, only172 new compositions extend existing bodies; repeated validation is not distinct function coverage.

All results match the exact final ELF recorded in exact-build-validation.json. Passive MMIO, synthetic callback registration and static factory fields remain limits. Reached-PC guards establish exercised source-only paths, not all unused ELF functions. Remaining unused STIMER accessor is already documented in audio-platform-callbacks-closure, so it is not a new missing-source claim.

Follow-up registration inspection shows the true tempco-suspend slot is table index10 (+0x28), wrapper0x4803DC. The preserved stock registration model assigns no index10 entry in any tested family, whereas public SDK registration does under NO_TEMPSENSE_IN_DEEPSLEEP. Thus public PCM2.0 suspend source is not evidence of an active stock suspend callback; compile-configuration difference is a concrete lead, not an established live gap. LP-auto initialization is index12 (+0x30), wrapper0x4803F2, not the tested0x4803AC. Full low-power initializer and physical calibration/scheduling behavior are separate boundaries. No hardware patch safety, source-complete firmware or byte equality is asserted.
