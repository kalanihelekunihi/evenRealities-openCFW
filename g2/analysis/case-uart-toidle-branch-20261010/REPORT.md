# CASE TOIDLE/no-DMA public-entry branch comparison

The locked CASE image is SHA-256 `36ca0c13558f252af286ae2b36b5e576d087d21d37b15d778e7da9f502a70374`. `toidle_no_dma.c` is an isolated C expression of one stock `HAL_UART_IRQHandler` branch, reached through the **public entry** `0x08005f50` when reception type is TOIDLE, ISR.IDLE and CR1.IDLEIE are set, error and RX-ready flags are clear, and CR3.DMAR is clear. It is not a full handler and is not linked into the CASE archive.

`verify.py` compiles that source and the already source-owned no-op `HAL_UARTEx_RxEventCallback` for Cortex-M0+ with warnings as errors. It executes both the complete stock public entry and the isolated source branch under Unicorn, without redirecting stock control flow. **256 original/source fixtures pass** across four transfer sizes, four remaining counts, two initial PRIMASK states, two additional CR1 states and four additional CR3 states. The synthetic UART handle and MMIO region are coherent and identically initialized. The comparator checks all 148 handle bytes, 36 UART register bytes, ordered MMIO writes with PRIMASK at each atomic CR1/CR3 write, event callback arguments, restored PRIMASK, stack restoration and return PC. `results.json` retains every fixture and source/ELF hashes. The script regenerates temporary objects/ELF; they were removed after the receipt.

For partial non-DMA reception, stock/source clear ICR.IDLE, atomically clear RXNEIE/PEIE and EIE/RXFTIE, set RxState ready and ReceptionType standard, clear RxISR, atomically clear IDLEIE, set RxEventType IDLE, and call the no-op event callback with the observed received count. No-partial cases return after ICR.IDLE. Some count/size combinations are arithmetic stress fixtures rather than plausible physical DMA/UART states; physical FIFO timing and interrupt races are not modeled.

The retained official STM32G0 HAL source explains the same branch, but this first isolated source does not implement error/DMA abort, TOIDLE with DMA circular/normal transfer, wakeup, TX-ready, transmission complete or FIFO callbacks. The full public handler still requires branch and callback contracts listed in `case-uart-full-irq-frontier-20261010/REPORT.md`. The two synthetic IRQ imports remain unresolved, the CASE archive remains 37 objects/61 symbols/five imports, and direct coverage remains **8/12**. This first receipt closes one selected branch comparison, not the whole stock handler or hardware behavior.

## TOIDLE with DMA continuation

`toidle_dma.c` adds a separate isolated branch candidate for the public-entry domain with CR3.DMAR set. `verify_dma.py` compiles it, the existing source no-op event callback, and `dma_fixture.c` for Cortex-M0+. The original call to `HAL_DMA_Abort` at `0x0800487a` redirects to that **same compiled fixture provider**; source calls the provider directly. The provider records argument/count and returns a chosen status. No DMA engine, transfer completion, or stock abort body is claimed.

**1,280 original/source public-entry fixtures pass**: four transfer sizes, five DMA remaining counts, circular/normal CCR, two PRIMASK states, two CR1 states, four CR3 states, and two abort returns. The comparator checks the complete 148-byte UART handle, 36-byte UART register window, 64-byte DMA handle, eight-byte DMA channel, ordered MMIO writes and PRIMASK, event callback arguments, provider calls/arguments, stack restoration and return PC. `dma_results.json` retains the fixture matrix and source/ELF hashes. Compiled objects/ELF were removed after validation; the script regenerates them.

The first attempt followed the retained HAL source's circular full-count event branch. Stock instructions at `0x080060b0..0x080060b6` instead return when the DMA count is zero or greater than/equal to the requested size; a stock/source fixture with size=1, remaining=1, circular CCR set had no stock event while the first source emitted one. The final source follows the authenticated stock condition and passes the full matrix. This is a source-version/configuration discrimination: the pinned HAL body is a structural lead, not a verbatim proof of this product's complete handler.

The normal-DMA partial path atomically clears PEIE, EIE, DMAR and IDLEIE, sets RxState ready and ReceptionType standard, calls the abort provider and then the event callback. Circular-DMA partial path retains transfer state and emits the event. Zero/full/excess remaining counts return after ICR.IDLE. Some count/size combinations are arithmetic stress fixtures, not plausible live transfers. Error/DMA-abort-on-error, wakeup, TX, FIFO and physical DMA timing remain outside this TOIDLE branch. No CASE archive import was resolved; direct completion stays **8/12**.

## Error-triggered DMA abort callback

`error_dma.c` is a third isolated selected branch: stock public IRQ entry with ORE set, RXNEIE enabled, DMAR set, no RX-ready flag, and a nonnull DMA handle. It source-defines the observed ORE flag/error update, `UART_EndRxTransfer`, atomic DMAR clear, installed abort callback and immediate callback invocation when `HAL_DMA_Abort_IT` returns nonzero. Its callback follows stock `0x080086e0`: read parent UART handle from DMA `+0x28` and clear the halfword counts at UART `+0x5e` and `+0x56`. Stock then calls weak `HAL_UART_ErrorCallback` at `0x08005f42`, a no-op in this image; source omits that no-op call under this fixed-image boundary.

`verify_error_dma.py` compares **64 public-entry original/source cases** across abort result 0/1, initial PRIMASK 0/1, reception type 0/1, initial error 0/4, two CR1 and two CR3 settings. Original `HAL_DMA_Abort_IT` at `0x080048e6` redirects into the same compiled `error_fixture.c` provider that source calls. The stock callback body and compiled source callback each execute on the error-return path. The comparator asserts callback installation to the correct respective code address, normalizes only that code pointer, and compares all 148 UART-handle bytes, 36 UART-register bytes, 64 DMA-handle bytes, ordered MMIO writes with PRIMASK, abort provider count/argument, callback entry count/argument, restored stack and return PC. `error_dma_results.json` retains the per-case receipt; transient objects/ELF were removed after the run.

The ORE fixture was initially one error class. The expanded enabled-error matrix below covers the other flags and combinations. The two synthetic IRQ imports and the 37-object/61-symbol/five-import archive state are unchanged; direct CASE completion remains **8/12**.

## Complete enabled-error flag combinations with RX mutation

`case_uart_error_dma_matrix` extends the isolated source branch to PE, FE, NE, ORE and RTO, retaining the original ICR write order and error-code bit mapping. `error_fixture.c` now supplies a compiled RX callback that XORs a selected mask into `ErrorCode` before the handler reloads it for its blocking decision. `verify_error_matrix.py` starts **both sides at their public IRQ entry** with DMAR and all five error interrupt enables set, a nonnull DMA handle, and the same compiled abort provider. It checks every nonempty subset of the five flags (**31 masks**), RX-ready off/on, abort result 0/1, PRIMASK 0/1, reception type 0/1, initial error 0/4 and RX mutation 0/0x20/0xff: **2,976 original/source fixtures pass**. The previous 64 ORE fixtures were rerun after the source addition and still pass; they overlap this domain and are not an additive coverage total.

The comparison includes all handle/UART/DMA bytes, ordered ICR/CR1/CR3 writes with PRIMASK, RX callback count, abort provider count and arguments, installed abort callback identity, immediate callback count/arguments, SP and return PC. `error_matrix_results.json` retains per-case traces. This verifies simultaneous-flag precedence under the all-enabled configuration, including RX mutation before the blocking test. It does **not** prove selective-enable masking when some error interrupts are off, a callback that modifies live CR3 or handle pointers, null/delayed DMA completion, or hardware interrupt interleaving.

## Selective enables, live DMAR mutation and mixed flags

`verify_error_selective.py` adds **7,168 public-entry original/source fixtures** with initial DMAR set and a nonnull DMA handle. It varies seven error masks, four CR1 enable configurations, four CR3 enable configurations, RX-ready, an RX callback that optionally XORs `ErrorCode` and live CR3.DMAR, IDLE/TXE flags with their enables, and both abort returns. The compiled callback writes CR3 only when mutation is requested, so MMIO and PRIMASK traces represent the selected fixture. Every case passes, including error-gated paths where the RX callback clears live DMAR before the stock handler decides whether to abort DMA. The stock weak error callback is a no-op in this image; the isolated source follows its observed error reset and return behavior.

`error_selective_results.json` retains the complete matrix, source/ELF hashes, callback/provider traces and ordered MMIO writes. The comparator also checks full UART, peripheral and DMA windows, installed callback identity when present, stack and return PC. These cases overlap the previous 2,976 and 64 error cases; their counts are separate receipts, not a summed coverage claim. The earlier comparators were rerun after the source and fixture change and still pass.

## Null DMA and deferred installed callback

`verify_error_null_delayed.py` compares **64 further public-entry fixtures** with initial DMAR set, ORE or all five error flags, two CR1 and two CR3 configurations, optional RX-ready, abort status 0/1, and DMA handle pointer null/nonnull. The stock null-pointer branch clears DMAR after ending RX and calls the image's weak no-op error callback; the isolated source now follows that branch. With a nonnull DMA handle and successful abort request, the comparator first records the state after IRQ return, then explicitly invokes the installed stock or compiled abort callback in the same emulator and compares the resulting state. The callback clears the UART receive counts at `+0x5e` and `+0x56`. Callback identity is checked before its address is normalized for memory comparison. `error_null_delayed_results.json` retains per-fixture handle, MMIO, PRIMASK, provider and callback traces and source/ELF hashes. The prior 7,168, 2,976 and 64 error comparisons were rerun after this source edit and pass.

This is an explicit later callback invocation, not a simulation of DMA hardware timing, interrupt races or callback scheduling.

## Wakeup branch

`wakeup.c` source-defines the selected no-error/no-RX/no-IDLE/no-TX public IRQ continuation. Stock `0x080061ae..0x080061c2` tests ISR.WUF bit 20 and CR3.WUFIE bit 22, writes ICR.WUCF bit 20, and calls fixed-image weak `HAL_UARTEx_WakeupCallback` at `0x08005efe`. `verify_wakeup.py` compares the complete stock public entry against that isolated source in **40 fixtures**: WUF off/on, WUFIE off/on, CR3 extras, disabled IDLE/TXE flags and both initial PRIMASK states. It checks the 148-byte handle, 36-byte UART window, ordered MMIO writes with PRIMASK, stack/return and stock weak callback count/argument. The callback has no observable state effect in this fixed image; the source expresses that no-op. `wakeup_results.json` retains the per-case receipt and hashes. The null/deferred error, selective error and both TOIDLE comparators were rerun after this addition and pass.

## TX-ready indirect ISR

`tx_ready.c` adds a selected public-entry continuation for ISR.TXE/TXFNF bit 7 with CR1.TXEIE bit 7 or CR3.TXFTIE bit 23. It loads `TxISR` from handle `+0x78`, tests null, and calls the pointer with the UART handle. `tx_ready_fixture.c` is the same compiled callback for stock and source; it records call count and argument and XORs a receive-count halfword to expose the call's state effect. `verify_tx_ready.py` compares **48 public-entry fixtures** across flag/enable combinations, null/non-null pointers, disabled IDLE flag and both PRIMASK states. The full 148-byte handle, 36-byte UART register window, callback state, ordered MMIO writes, stack and return PC match. `tx_ready_results.json` retains per-case receipts and hashes. The wakeup, null/deferred DMA, selective error and both TOIDLE comparators were rerun and pass.

## TX-complete finalization

`tx_complete.c` expresses the selected quiet public-entry path at stock `0x080061e0..0x0800620c`: when ISR.TC and CR1.TCIE are set, it atomically clears CR1.TCIE, sets handle `+0x88` to ready (`0x20`), clears the `TxISR` pointer at `+0x78`, and calls a lower completion provider with the handle. `verify_tx_complete.py` redirects only the stock lower call at `0x08006776` into the same compiled `tx_complete_fixture.c` provider that source calls. The provider records count/argument and mutates a handle halfword to expose the call. **48 public-entry fixtures pass** across flag/enable combinations, disabled extra IDLE/wakeup flags, CR3 extras and both PRIMASK states. Full handle/UART bytes, ordered CR1 MMIO write and PRIMASK, provider state, stack and return PC match. `tx_complete_results.json` retains cases and hashes. TX-ready, wakeup, null/deferred DMA, selective error and both TOIDLE comparators were rerun and pass.

The lower `0x08006776` body is an explicit fixture boundary; this receipt does not source-own its production callback effects.

## FIFO weak callbacks

`fifo.c` expresses the selected quiet continuation at stock `0x0800620e..0x0800622c`. ISR.TXFE bit 23 with CR1.TXFEIE bit 30 calls the fixed-image weak no-op callback at `0x08005efc`; otherwise ISR.RXFF bit 24 with CR1.RXFFIE bit 31 calls the weak no-op callback at `0x08005e6c`. When both are enabled, TXFE takes precedence and returns. `verify_fifo.py` compares **40 public-entry fixtures** across both flags/enables, simultaneous flags, disabled IDLE flag and two PRIMASK states. It checks the 148-byte handle, 36-byte UART window, ordered MMIO writes, stock callback target/argument, stack and return PC. `fifo_results.json` retains all rows and hashes. TX-complete, TX-ready, wakeup, null/deferred DMA, selective error and both TOIDLE comparators were rerun and pass.

## Mixed-family precedence and callback mutation

`mixed_tail.c` composes the no-error/no-IDLE wakeup, TX-ready, TC and FIFO continuations in stock order. `verify_mixed_tail.py` passes **2,048 public-entry original/source fixtures**: all 32 combinations of WUF, TX-ready, TC, TXFE and RXFF flags; eight enable configurations; initial PRIMASK 0/1; null or compiled `TxISR`; and optional callback mutation of live CR1 and the handle's `TxISR` pointer. The same compiled TX-ready and TX-complete fixture providers run on both sides. The comparator checks full handle/UART bytes, ordered MMIO and PRIMASK, provider counts/arguments, weak callback target/argument, stack and return PC. The stock/source data comparison and an independent expected priority check agree: wakeup, then TX-ready, then TC, then TXFE, then RXFF. `mixed_tail_results.json` retains all rows and hashes. The TX-ready standalone verifier was rerun after the callback fixture extension and passes.

`verify_mixed_error.py` adds **896 public-entry fixtures** where ORE or all five error bits are enabled while IDLE, wakeup, TX-ready, TC and FIFO flags/enables are also varied. Its source is the separately validated error continuation; RX callback optionally changes live CR3.DMAR and `ErrorCode`. The complete stock public entry takes the error path before these later branches in all passing cases. `mixed_error_results.json` retains the rows and hashes. This comparison does not mean that all errors or enables have been composed with the later source into one function.

## RX-ready and disabled-error fall-through

`rx_fallthrough.c` composes the selected no-error RX-ready path and the disabled-error fall-through into the previously verified mixed tail. `verify_rx_fallthrough.py` passes **1,024 public-entry original/source fixtures**: either no error with ISR.RXNE and CR1.RXNEIE, or all five error flags with their enables off; all 32 combinations of wakeup/TX-ready/TC/TXFE/RXFF flags; initial PRIMASK 0/1; null/non-null RX and TX callbacks; and optional RX callback mutation of live CR1, CR3, its handle callback pointer and a receive-count halfword. The same compiled RX, TX-ready and TX-complete providers run on both sides. Full handle/UART bytes, ordered MMIO/PRIMASK, callback/provider state, stack and return PC match. `rx_fallthrough_results.json` retains all rows and hashes. In the no-error RX-ready domain, stock returns after the indirect callback, including when its pointer is null. With all error enables off, it reaches the later priority chain.

## TOIDLE with later flags and unified public entry

`verify_toidle_mixed_dma.py` passes **288** public-entry stock/source fixtures with TOIDLE/IDLE enabled, DMAR set, simultaneous later wakeup/TX-ready/TC/TXFE/RXFF flags/enables, two sizes, three remaining counts, circular/normal DMA, both PRIMASK states and both common abort-provider returns. `verify_toidle_mixed_no_dma.py` passes **72** analogous non-DMA fixtures across size/count/PRIMASK and later flags. The stock entry returns from the IDLE continuation before those later branches in the selected domain. The two receipts retain per-case memory/MMIO, callback and provider traces and hashes.

`irq_unified.c` then composes the previously verified error, RX-ready, TOIDLE DMA/no-DMA and mixed-tail sources into **one compiled public-entry function**. `verify_unified.py` links that function with explicit common fixture providers for `HAL_DMA_Abort`, `HAL_DMA_Abort_IT`, the lower TX-completion body, RX/TX callbacks and the source-owned no-op RxEvent callback. It compares **1,264** stock/source public-entry fixtures: later-family combinations; no-error RX callback; disabled-error fall-through; all 31 nonempty enabled-error masks with optional RX mutation and both abort outcomes; TOIDLE with DMA/no-DMA, normal/circular and zero/partial/full/excess counts; and null/non-null error DMA handle. Full 148-byte UART handle, 36-byte UART register, 64-byte DMA handle and eight-byte DMA channel windows match, together with ordered MMIO/PRIMASK writes, callback/provider state, stack and return PC. `irq_unified_results.json` records source/ELF and image hashes plus exact case-family counts. This is a bounded RAM-fixture proof for one unified entry, not physical DMA or peripheral timing.

The archive originally imported the synthetic `case_uart_other_irq` and `case_uart_dma_boundary` continuation names. The next section establishes their call-site contract and records their source integration. The lower abort and TX-completion implementations remain explicit provider boundaries, and delayed callback scheduling is simulated rather than proven on hardware.

## Archive continuation integration

`uart_error_atomic_offline/uart.c` contains the only two call sites. `case_uart_other_irq(h)` is reached after the prefix has returned from enabled errors and ordinary RX-ready handling; it receives the same one-word UART handle pointer in R0. It must continue with disabled-error RX-ready fall-through, TOIDLE and tail families, without replaying the prefix. `case_uart_dma_boundary(h)` is reached only after `case_uart_end_rx(h)` has already cleared reception interrupts and state while live CR3.DMAR remains set. It must clear DMAR, install the abort callback and invoke `HAL_DMA_Abort_IT`; calling the public handler again would duplicate the prefix's ICR/error/end-RX effects. These synthetic names have no stock entry addresses. The source `irq_continuations.c` implements the two distinct one-argument continuation contracts and the stock abort callback's count clearing; it calls the previously verified TOIDLE/tail source leaves.

`verify_composed_archive_entry.py` compiles the **archive's actual prefix and four new source files** for Cortex-M0+ with `-Os`, together with explicit lower fixture providers. It compares the composed entry at `case_uart_error_irq` against stock public `HAL_UART_IRQHandler` across **1,264** coherent cases. All full handle/UART/DMA/channel bytes, ordered MMIO/PRIMASK writes, provider calls, callback identity/effects, stack and return PC match. The independent `irq_unified.c` public-entry comparator was rerun and also passes 1,264. `irq_composed_results.json` and `irq_unified_results.json` retain exact case-family counts and hashes. This proves the synthetic call-site mapping within the tested RAM domains; the two continuations are not aliases to the public entry.

The four continuation/leaf source files are now in `g2/components/case/source_candidate_20261010/`, and `build.py` compiles them. The deterministic whole-archive relocatable link passes with **41 objects, 67 provided symbols and six unresolved imports**: direct `case_legacy_command` and `case_binary_command`, and lower `case_dma_abort`, `case_dma_abort_it`, `case_tx_complete_provider`, `case_vformat`. Archive SHA-256 is `9b5e8c4640014b8bba779f4d67bf8286c6555820303c8f757ba75e2d52ea4e1d`; relocatable SHA-256 is `657d81a0b1bf5a1a1000e78eb53682c222ad883d2c21369460d310c2d26a53bd`. Direct CASE coverage is now **10/12**. This is a source archive with lower providers outstanding, not a flashable image or hardware proof.

The later DMA abort provider closure source-defines both lower abort imports and replaces the common abort fixture in a 1,264-case whole-IRQ comparison; see `case-dma-abort-20261010/REPORT.md`. That report holds the current 42-object/69-symbol/four-import archive receipt. The earlier six-import values above are the archived intermediate step.
