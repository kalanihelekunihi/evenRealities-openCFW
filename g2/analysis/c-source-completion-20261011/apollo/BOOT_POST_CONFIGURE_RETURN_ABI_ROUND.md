# Boot post-configure return-register correction

Locked stock SHA-256: `f89a4c4657537cec6bfc572bdb8318866309b90a5d180c4307680d39824167b5`.

Native entry 0x422ba8 pushes R3/R4/R5/R6/R7/LR, computes an R0 status through its object/configuration paths, and returns through `pop {r1,r4,r5,r6,r7,pc}` at 0x422c76. Thus the high AAPCS return word R1 is the caller's incoming R3. The selected post-configure adapter previously tail-branched to the C power-apply body, which could clobber R1. Its named Thumb wrapper now uses `push {r3,lr}; bl opencfw_boot_control_power_apply; pop {r1,pc}` and is declared with a 64-bit return. The selected caller retains the low status word after the implicit conversion to its status aggregate. Native direct callers 0x41f846 and 0x41f8ba pass R0 object, R1 operation (0 or 2), and R2 enable=1, do not deliberately initialize R3 at the call, and consume only R0. The separate uncatalogued native post-bringup body 0x41f612 sets R1=0/R2=0 before its 0x422ba8 call, matching selected `post_bringup.c` operation0/enable0. These caller argument mappings are source/instruction evidence, not complete runtime equality.
