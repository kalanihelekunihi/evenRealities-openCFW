# Boot GPIO callback and STIMER source round

## GPIO callback body and table ownership

Stock `0x41e09a..0x41e10d` callback service uses two seven-bank GPIO ranges (`56..62`, `125..131`), scanning the low set status bit, loading callback/argument from base addresses `0x20023600` and `0x20023d00`, invoking non-null callbacks, and retaining error 7 for absent entries. Selected `initializer_callbacks/gpio_irq_runtime.c` matches this flow. `boot-gpio-service-current-oracle.json` passes 64 stock/current selected ELF cases with synthetic callback entries/arguments and visits 110/116 body bytes. Six unvisited bytes are not claimed exercised.

The authenticated source zero scatter record at `0x4330dc` clears `0x2000055c..0x200271c8` before registration. Four consecutive 896-byte tables for callback and argument banks occupy `0x20023600..0x20024400` inside that extent. `gpio_descriptors.c` writes the same bank addresses for channels 0/1/2, and the service reads them. `boot-gpio-callback-table-ownership.json` records exact stock record fields, table extents, and source hashes. Product descriptor data is source-owned and 1,164 bytes match the selected build receipt, but real installed callback values and asynchronous interrupt delivery remain unqualified.

Previous selected C cached a single interval and used C division/modulo. Selected `initializer_callbacks/stimer_irq.c` now performs four ordered reads with a named target `UDIV` instruction, matching the native divide-by-zero instruction behavior under the bounded CPU fixture. `boot-stimer-current-oracle.json` passes seven wrap, tick, wake, and zero-divisor cases; it visits all 114 body bytes and observes four interval reads per case. The fixture cuts child timer/critical calls and cannot prove physical timer or IRQ timing.
