# Boot IAR exponent source correction

Stock Thumb `0x41f270..0x41f2b2` updates its 32-bit exponent with `asrs r4,r4,#1` at `0x41f2a4`. The prior selected `opencfw_fp_pow10` used an unsigned exponent and logical `>>=1`, which terminates for negative bit patterns while stock continues with sign extension. The selected C now declares `int32_t exponent` and computes the arithmetic-shift bit pattern explicitly with unsigned operations; the caller declaration and positive scale call arguments were updated to the same typed interface. No fabricated limit or early return was added for the native nonterminating negative domain.

An isolated Cortex-M55 target compile of the corrected source shows the expected sign-bit preservation as `AND 0x80000000` plus logical shift and OR. The full Boot candidate `boot-coplacement-pow10-signed-round/receipt.json` is a source-coherent `PASS_BOUNDED_LINK`: 374 selected units, 1,011 providers, three genuine ROM imports, 34 callback relocations and 158,836 file bytes. It does not prove native floating point equality; multiplication rounding/FPSCR and the negative infinite path were not executed as a stock/current-source runtime oracle in this round.

Other newly bound selected bodies: FIFO write `0x423e40` has a current-source-hash 496-case stock/source receipt; spot-timer start `0x41cc48` was matched structurally to its full native Thumb body and its selected PCM2.2 source. Physical MSPI/timer behavior and final firmware layout remain open.

Direct native Thumb review of IOM interrupt-status getter `0x42c672` found one handle module read at `0x42c692`, despite Ghidra printing the expression twice. Selected C reads it once and matches the guard, optional INTEN mask and output store. This is structural attribution, with no new runtime oracle. The full candidate's existing source-owned data checks remain in its receipt; this round did not resolve additional scatter bytes or ROM behavior.

The 98 are proof leads, not a count of missing C bodies.
