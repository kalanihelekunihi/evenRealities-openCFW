# Source-backed audio receive/cache handoff

The new callable source integrates the full stock selected-buffer query **0x590b6c..0x590b92** and full audio getter **0x57a7e0..0x57a80e** with the unchanged reconstructed cache provider. Source and interfaces are `g2/components/foundation/audio_cache_handoff/handoff.c` and `handoff.h`. Build with `make -C g2 audio-cache-handoff-simulator`. The isolated O2 ELF is not a patched firmware image or stock-linked binary.

The getter reads the handle pointer at 0x2007450c, selects channel0's pointer, invalidates an authenticated **3,200-byte** range using flag 0, then publishes address and length. It returns the selected address in R0. This borrows a buffer: no PCM bytes are copied, and no allocation/ref/free, lock, exclusive ownership or safe DMA reuse interval is provided. Its real query/cache callees execute in the comparison; no executable callee stubs replace them. A synthetic context mutation after pointer selection confirms snapshot behavior only, not a demonstrated hardware race.

**Validation:** 282 original/source cases pass, plus 1,157 separate tests of a **new** checked policy. The stock tests cover query selector-byte truncation, sentinel/double-buffer states, cache enabled/disabled, misalignment, output aliasing, register/barrier/publication order, guards and preserved ABI. Source R0 was initially reconstructed incorrectly as 3200; original instructions restored the selected address during the epilogue. That failed candidate and ELF remain preserved. Independent final review passed 13 native representative cases and verified final source/ELF/result hashes.

The new capacity-check interfaces fail before cache effects for missing/invalid/wrapping bounds, unsupported operation, nonpositive signed length or a range outside supplied storage; checked handoff additionally rejects null/aliased outputs and null handle. Failure leaves output words unchanged; success returns 0. Raw getter behavior remains separate, including aliased-output publication. These policy tests do not count as stock equivalence or original-byte coverage. Caller-supplied bounds do not prove mapped storage, allocation liveness, physical cache geometry or exclusive DMA ownership. Nonnull descriptor, output and handle pointers still require mapped aligned words, and the fixed global handle cell must be readable. The checked policy validates scalar bounds; it cannot turn arbitrary invalid pointers into safe memory. No arbitrary maximum work length is introduced: sufficiently large supplied storage can still admit a large positive length.

The previous huge raw-cache fixture length 0x7fffffff is retained and classified as an **execution-budget limit**, not a demonstrated source mismatch, overflow or unsupported input. Twelve original/source prefixes reached 30,000 instructions and agreed on the common maintenance-write sequence. The length-plus-misalignment sum cannot overflow uint32 for these inputs; signed-boundary crossing occurs before subtraction 32 restores a positive continuation counter. A completed run would require 67,108,864 writes for alignment 0/1 and 67,108,865 for alignment 31. Full huge executions remain **unverified** and receive no completed-path coverage. Legitimate raw inputs have not been relabeled invalid or silently dropped: they remain explicit prefix diagnostics. The display validator checks pointer presence, not a length ceiling; authenticated real allocation extents are absent. Audio's known 3,200-byte call is fully exercised.

Saved fresh aggregate: 44 modules, 228 methods, 222 passed, 6 method skips and 1 setup skip, 0 failures/errors. Affected tests: 15 passed. Unique instruction accounting adds 84 new query/getter bytes to 6,732; 76 of 160 traced bytes overlap the existing cache provider. Final total **touch 234 + Apollo 6,582 = 6,816**. Original trace addresses/bytes, current source/ELF identities, review and test hashes are pinned in validation-summary.json/build-provenance.json. No new byte-identical compiled match or complete source-built payload is claimed.
