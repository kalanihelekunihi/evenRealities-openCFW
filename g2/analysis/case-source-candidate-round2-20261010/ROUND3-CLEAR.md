# CASE event clear continuation

The complete original wrapper at `0x0800a7d2..0x0800a814` is retained in `case-frame-dispatch-closure-2026-10-08/original-disassembly.txt`. It rejects null event or high-eight flag bits with `0xfffffffc`, branches on IPSR, calls task-context clear at `0x0800c44c`, or in ISR snapshots bits at `0x0800c4cc` before queuing clear at `0x0800c478`. An enqueue failure returns `0xfffffffd`; success returns the prior snapshot. `evidenced_providers.c` now implements that wrapper exactly at the C branch/call level. `verify_evidenced.py` checks original instruction markers and source branch/call sequence. The prior frame-dispatch closure compared the original clear wrapper through the actual original kernel peer; it did not execute this new C body against original, so the new validation is static only.

The wrapper resolves `case_clear_event` but introduces three explicit kernel imports: `xEventGroupClearBits`, `xEventGroupClearBitsFromISR`, and `xEventGroupGetBitsFromISR`. Consequently the archive has 27 global provided symbols and 26 unresolved symbols. This is one completed source wrapper, not a claim of fewer total dependencies. `provider-census.json` gives those three original entries and concrete remaining blockers; the task-context clear body is partly disassembled, while the ISR get/clear queue bodies require full extraction and coherent critical/timer queue semantics. No implementation based solely on FreeRTOS upstream names is included.

This continuation used exact retained CASE instructions, not a source-name search. Remaining minimum is 26 provider compatibility/body checks plus the eventual linked-image and integrated behavior gates. The immediate next small task is original-byte extraction for the three kernel imports; at least one critical-state and one timer-daemon ownership study are needed to make their source behavior coherent.

## ARM behavior comparison

`build_behavior.py` compiles the new provider source together with the independently reconstructed event-set wrapper into a Cortex-M0+ ELF using the pinned local ArmGNU 13.3 compiler. `verify_behavior.py` executes original CASE firmware entries and candidate ELF entries with Unicorn 2.1.4 under `/tmp/iar-c-runtime-venv/bin/python` (pyelftools 0.33). All **1,152 original-versus-source comparisons pass**: 384 clear-wrapper, 384 event-post alias, and 384 forwarding alias cases. Inputs cross null/valid event pointer, zero/valid/high-bit masks, thread/ISR IPSR, two PRIMASK states, kernel enqueue failure/success, wake flag, and old event bits. Results compare return registers, ordered kernel calls/arguments, ICSR writes, and final PRIMASK/IPSR. This upgrades the wrapper and alias paths from static-only to bounded behavior verification.

Both sides intercept only the actual kernel child entries (`0x0800c44c`, `0x0800c478`, `0x0800c4cc`, `0x0800c4de`, `0x0800c568`) and supply identical explicit result models. The results **do not** validate any kernel provider body, event object lifetime, timer-daemon execution, or physical interrupt interleaving. `behavior-build-receipt.json` contains the exact compiler command, source/linker/ELF hashes and compiler identity. `behavior-results.json` contains result counts, firmware hash, emulator versions, child boundary addresses and scope. Reproduce with `/tmp/iar-c-runtime-venv/bin/python g2/analysis/case-source-candidate-round2-20261010/build_behavior.py` followed by the same interpreter on `verify_behavior.py`.
