# CASE source candidate: round 2

## Result

Eleven existing independent CASE C modules compile with `/usr/bin/clang` for `arm-none-eabi`, Cortex-M0+, Thumb, soft float, freestanding C11, and `-Os`. `arm-none-eabi-ar` creates `libcase_source_candidate.a` from the eleven objects. The exact command, compiler version, SHA-256 of each source and archive, and all stderr are in [receipt.json](receipt.json). [nm.txt](nm.txt) is the complete object symbol listing. An inspected object is ELF32 little-endian ARM EABI version 5, and its decoded instructions are Thumb. This is a concrete source/object/archive composition, **not a linked or flashable firmware**.

The archive defines 24 global symbols and leaves 27 external provider names unresolved. The provider census is generated from all object files, subtracting archive-local definitions. The unresolved list includes original HAL callbacks, event group kernel operations, critical section/scheduler hooks, case transport/control handlers, and unimplemented whole product boundaries. It is a symbol census, not 27 independent tasks or proof all signatures/semantics are correct.

## Source selection and behavioral support

Included: binary forwarding, deferred consumer and event producer, event flag wrapper and waiter body, frame callback/dispatcher, selected local commands, corrected atomic UART error/end RX, UART receive helpers and start API. Each has an existing per-module report in `g2/analysis/case-*-closure-2026-10-08/REPORT.md`, with original-versus-independent comparisons and explicit entry contracts. The corrected UART module supersedes the old atomic masking scaffold. This round verifies target compilation and archive composition; it does not rerun prior behavioral suites or claim an integrated behavior comparison. No new function was inferred from merely matching an external provider name.

A real CASE image still requires the precise linker map, startup and interrupt vectors, compatible RTOS/HAL provider objects, all product handlers, and end-to-end state/ownership verification. The current candidate cannot link standalone: among the 27 names, `xEventGroupSetBits`, `case_binary_command`, `case_legacy_command`, `case_bulk_receive`, `case_event_post`, and `case_send` represent substantive paths, not safe zero-return stubs. The existing forwarding source also reads `p[2]` before its logical length check and is valid only under its documented allocated-buffer contract. Composition cannot make that path general-purpose safe.

## Remaining estimate and boundary

Minimum mechanical integration work: classify all 27 unresolved provider symbols against exact original objects/signatures (27 checks), reconstruct or bind at least the six substantive paths named above (six implementations/bindings), integrate startup/linker and execute a complete image link (one gate), and rerun end-to-end tests with coherent shared memory and queue scheduling (at least one test campaign). These are lower bounds, not an exact project completion percentage or time estimate; some providers have multiple paths and lifecycle states. This round found no original-byte evidence to implement the missing providers with justified behavior, so it leaves them explicit. Source-only candidate is complete within this round's bounded composition scope; firmware implementation remains open.

No gate ledger, stock image, or prior analysis file was changed.

## Round 2 provider audit and reproducibility

[provider-census.json](provider-census.json) classifies **all 27** unresolved names. Every entry points to exact CASE caller line(s), its retained original-comparison report, and any source-name hit in foundation/bootloader. The audit searched source under both component trees. Only `xEventGroupSetBits` has a source-name hit: the FreeRTOS V10.5.1 based foundation event group subset. Its [README](../../components/foundation/freertos_event_group/README.md) explicitly retains scheduler/list/queue/lifetime boundaries and is grounded in a WSF/radio handoff, while CASE's selected event ABI and original object/provider compatibility are not established for a direct link. No other name has a C definition in those two component trees. Names alone do not qualify any provider for inclusion; therefore the CASE archive remains at 11 objects and 27 unresolved names.

The receipt now includes every compiler reported `-MD` dependency and SHA-256 (including local headers), SHA-256 plus version strings for compiler, `ar`, and `nm`, exact commands, and an `ar rcsD` deterministic archive rebuild comparison. The second archive was byte identical to the first. `classify.py` regenerates the per-symbol census from the current receipt and caller sources. This narrows reproducibility drift; it does not validate target execution or compiler equivalence to stock IAR.
