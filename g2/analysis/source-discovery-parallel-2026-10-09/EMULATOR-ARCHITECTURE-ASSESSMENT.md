Read-only source inspection of exact requested repository atf30527c0b7e6fa6e9be06e7067e49468197fa258; no rerun of tests or saved campaign claims. Current-file hashes are retained. No buzzer work, per repository AGENTS.md.

## How it executes

There are distinct paths; do not merge their accuracy claims. **Renode full-application path**: renode/boot.resc includes C# peripheral models, creates a machine, loads platforms/g2-apollo510.repl, installs explicit synthetic-right unlocked OTP fixture, loads artifacts/mainapp.bin at438000, and loads image-derived ITCM helper24bytes at40. It sets VTOR438000, resets CortexM55, then explicitly setsSP2007FB00/PC5FB8AB. This substitutes the application handoff, not secure-ROM/bootloader execution. Source comments say IAR scatter helpers normally populated by earlier boot phase; image-derived overlay supports that narrow precondition. Secure boot/authentication, production OTP and loader lifecycle are not validated by this launch.

firmware.lock.json distinguishes stock2.2.9.22 OTA SHAa03fbea9...c561 from canonical **g2flash-patched** OTA55fdfb81...ce277. Default main executable is patchedf0bf809a...ceb0d7 (3738440bytes); stock mainc9634919...9a9d (3697252bytes) is separate. scripts/run-renode.sh permits stock/patched selection with fresh firmware output. “Unmodified guest” in reports refers to the selected pinned image, and does not mean default guest is original manufacturer firmware. OpenCFW locked2.2.6.10 main is a different image; identical peripheral payloads must be checked separately. EM9305andcodec hashes match OpenCFW, allowing byte/reference reuse for those payloads but not proving they execute here.

platform file7+ uses Renode CPU.CortexM,cpuTypecortex-m55,NVIC,250MIPS virtual performance. Pinned Renode/tlib modifications handle M-profile caches, memory/PC witnesses and MMIO progress; these are backend fixes/instrumentation, not MCU firmware patches. Memory:ITCM0(size40000),MRAM400000(size400000),DTCM20000000(size80000),systemSRAM20080000(size300000),OTP/info42000000+,externalflash60000000/80000000. Geometry corroborates OpenCFW Apollo map; this is **Apollo** memory, not NationalChip100/200alias proof.

**Unicorn injected-block path**: src/g2emu/unicorn_harness.py docstring, CfwUnicornHarness821+ and hook_import891+ execute actual Arm bytes of the injected g2flash block but replace registered stock calls with deterministic host callbacks. RecoveredStockFirmware491+ and HarnessAllocator440+ are host substitutes for imports such as malloc,send,displaycopy,pbdecode etc. Escaping without registered import fails closed. This can verify bounded patch logic under supplied contracts; it does not execute the full stock caller/hardware for those substituted imports. **Python harness.py** includes separate protocol/display behavioral dispatch/demo logic; generated pixels from that path are not automatically firmware instruction execution.

## Models and I/O

controller.resc adds controller-peripherals to the boot path. G2EM9305.cs is a stateful H4/HCI SPI behavioral model, with ready/reset handling and explicit synthetic remote/bond state; it does not run an ARC CPU or controller archive. IOM6SPI/GPIO wiring is based on exact2.2.9.22Arm accesses/datasheet corroboration, as detailed in bleif-em9305-architecture.md. OpenCFW's older IOM-unresolved note is a finite cross-version contradiction to check, not automatically corrected physical wiring.

C# GPIO/timer/IOM/MSPI/power/sensor/touch/ADC/Nema/display models mediate MMIO and modeled register side effects. Sensor stimuli and calibration/self-test results depend on profile/fixtures; host service models are not execution of private ICMEDMPROM. Touch model is not PSoC firmware CPU. No case MCU, ARC controller or C-SKY codec execution was found in inspected platform. PDM/I2S IRQ44/45/48 and clock-domain behavior exist, but platform220+ explicitly supplies no PCM/external source clock by default; audio notes forbid manufactured GX8002replies. This agrees with OpenCFW physical audio/static boundaries.

G2Apollo510_SystemTimer.cs42+ uses shared virtual ClockSource; comparator outputs route toNVIC32–40. GPIO banks/timers route additional documented lines; unrouted lines intentionally remain absent. This permits deterministic interrupt ordering and guest RTOS execution, but250MIPS/virtual time, modeled polling latencies and event scheduling are not cycle-accurate physical oscillator/bus timing. Core/cache models abstract performance/coherency; unseen DMA/cache interactions require explicit tests.

NemaGpu executes supported command/raster **models**, while shader producer research separately executes unchanged public SDK Arm objects under Unicorn. Matched command producer bytes do not establish completeGPUISA. Known unknown streams remain unsupported; proprietary internal header/source and general shader behavior still missing. Panel_capture.py:save_a4_png/capture records modeled framebuffer/display output; protocol scripts, paired.resc and input profiles drive touch/sensor/BLE events and expose traces/images/JSON tohost. Host-visible rendering is valid only for modeled commands, geometry and source resources.

## What its tests can establish

Existing tests cover source model behavior, firmware loading/scatter identity, bounded Unicorn imports, protocol/paired scenarios, IRQ/timing contracts and pixel/resource/transaction regressions. Some tests skip unless archives/resources/backends exist; skips are not passes. Saved docs describe many bounded runs, but referenced generated/research and official-OTA audit artifacts are missing here, so this inspection cannot freshly authenticate all historical outcomes. CI/suite/file count does not imply complete-chip or firmware code coverage. Source/hash changes invalidate old pinned-campaign results until rerun.

Reliable use: address-bound Arm control/dataflow under exact selected image and explicit model state; register/protocol expectations; deterministic corner cases; supported UI/pixel paths; differential component/provider clues when original hashes match. These complement OpenCFW independently authenticated spans and accepted pseudocode; they do not substitute for them.

Cannot establish alone: physical board wiring/state, oscillator/power/audio reality, completeGPU/EDMPsemantics, secure boot/signing, C-SKYCPUaliasing, ARC log2p1arithmetic/flags, producing compiler/version, blob-independent completeCbuild or byte-identical OpenCFW rebuild. High-level controller fixtures can make Arm tests progress even where genuine controller behavior remains unimplemented; each result must state that seam.
