## Where normalization loses evidence

G2Apollo510_MSPI.cs Exchange (around739) calls peripheral.Transmit(byte); it carries no command/address/data lane-width metadata. SendInstruction and address serialization feed this byte channel. AdvanceIdleCycles(cycles,isWrite) separately preserves the header/data boundary and dummy count, including zero cycles, but conveys no lane count, phase mode bits or actual pin-level clock edges. Controller configuration may retain lane settings internally; a byte-only NOR subordinate cannot prove that6C arrived inSIO with4SIO address bytes and4-lane output, or distinguish a same-byte capture generated with incompatible QPI/lane settings. QE and SPI/QPI state checks inside the subordinate cannot restore missing physical phase metadata. Idle counts must not be confused with fake MOSI bytes or measured wall-clock time.

Remaining limits: resolve stock bit5 versus sample0x40 four-byte acceptance; bind address-length/lane enum configuration and caller state to the old HAL before claiming complete1-1-4 compatibility; inspect copied configuration values against producing source/version; actual hardware timing/electrical/QE/mode state remains unmeasured. This bounded comparison does not prove all flash commands or source completeness. Canonical evidence, emulator and index remain unchanged.
