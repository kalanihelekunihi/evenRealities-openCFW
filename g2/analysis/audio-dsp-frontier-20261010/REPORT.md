## New bounded source candidate

`dsp_clamp.c` defines the 34-byte clamp contract in C with a narrowly scoped ARM `VCMP.F64`/`VMRS` helper. GCC's ordinary C comparison emits `VCMPE.F64`, which differs from stock for quiet-NaN IOC; the inline compare retains stock's FP exception semantics. `verify_clamp.py` recompiles with ARM GCC for Cortex-M55, hard-float FPv5-D16 at `-O0`, extracts the ELF `.text`, and runs both stock and compiled helper in Unicorn with D0–D2 inputs. All **72/72** comparisons match both D0 output bits and FPSCR, including ordered interior/outside/equality, signed zero, infinities, quiet and signaling NaNs in each operand, subnormal, reversed bounds, and four initial FPSCR presets. The body hash, toolchain, flags, and per-case values are in `clamp-receipt.json`. The ARM object has no undefined symbols and declares VFP-register arguments in its ELF attributes.

The candidate now covers **return-value and FPSCR behavior under these bounded inputs**, including signaling NaNs. It is still intentionally isolated: the compiled helper uses ABI-allowed stack traffic and clobbers caller-saved registers, whereas the stock helper is a leaf with no stack traffic. The optimized pure-C form also emitted `VSELGT`, which this Unicorn setup cannot execute; the reproducible comparison uses `-O0` and inline ARM assembly only for FP comparison/status transfer. No M-class Unicorn FP mode is used. Enabled FP traps, full register/memory equivalence, hardware execution, and the larger DSP chain remain unproven. A production integration should use this as a bounded helper provider only if the archive's ABI and inline-assembly policy accept it.

## `asin` source frontier

Stock `0x43c260` is a double-precision `asin` routine consistent with the main image's IAR DLIB-family compiler/runtime provenance in `g2/docs/reference/toolchains.md` and `g2/docs/reference/libraries.md`; its exact library object/release is not independently identified. The corresponding source is not retained, and IAR DLIB is proprietary, so this pass found no attributable public repository or justified submodule pin. The authenticated Ghidra body is 254 executable bytes in two ranges, with 16 literal bytes between them; its contiguous 270-byte body-plus-literals SHA-256 is `b69e1f84d2bade8702adfb2fd50ac4cb218a8d50af0fbc28a9c8f92d7692b558`. The routine also reads a coefficient/offset table beginning near `0x43c370`, outside that body. Its observed interface is D0 input/result, FPSCR effects, and `errno` at `0x20074f14` through the existing domain setter for invalid arguments.

`verify_asin_frontier.py` directly executes stock `asin` in Unicorn for **768** input/FPSCR combinations (256 unique double bit patterns under three initial rounding presets). It records exact D0 bits, FPSCR, and errno in `asin-frontier-receipt.json`. For finite inputs in [-1,1] at default FPSCR, host `math.asin` has exact matching result bits in only **156/246** cases; the other 90 differ by one or two raw-bit steps. Stock `asin(±2)` writes errno `33` and returns `0x7fffffff00000000`; stock quiet NaN preserves its payload without errno, while the tested signaling NaN enters the domain path. These are original-instruction observations in a synthetic RAM map, not a source implementation.

The bundled GNU Arm toolchain has newlib `libm.a` symbols `asin` and `__ieee754_asin`; `newlib_asin_probe.c` links the latter only as a diagnostic alternative. `compare_newlib_asin.py` finds exact output bits in **389/768** matching cases and exact D0/FPSCR/errno state in **0/768**. Even zero input differs in FPSCR (`0x20000000` for newlib versus `0` stock); the newlib IEEE entry does not supply stock's domain errno contract. Its compiled algorithm is also substantially larger (648-byte comparison ELF including shim) and is not attributable as the stock IAR source. `newlib-asin-comparison.json` records the per-case differences.

No `asin` source candidate is admitted from these observations. Reproducing the stock polynomial/rational table from opaque image constants would violate the source-ownership rule; using host or newlib math would fail exact result and FP-status behavior. The next discriminating input is an authenticated IAR DLIB math source/library package with exact release and license provenance, or an independently derived and explained approximation with a complete bit/FPSCR/domain-state proof. Until then the bounded DSP composition retains the stock `asin` oracle and is not source-only. Estimate **1–3 days** for source attribution and algorithm reconstruction if a lawful attributable source becomes available; without it, this is a finite provenance blocker rather than a schedulable archive integration task.

Production call-site format/pointer ownership (5,718 static calls to the short logger entry), initialized sequence state, concurrent changes to shared logger state, enabled FP traps, and downstream output transport remain outside this proof. ## Short formatter output ring and state provenance

`short_log_output.c` reconstructs the entire local stock `0x43ca50..0x43cb83` body (308 bytes; SHA-256 `debf15ecef87bec0076f05cc733e9f5d59fc902f3e2e2549476bea31a244c0f5`). The stock literal at `0x43d0e8` addresses a four-word RAM ring descriptor at `0x200004c8`: base pointer, capacity, read index, write index. The literal at `0x43d0e0` addresses the lock-state word at `0x20074388`. In thread mode with nonzero lock state and successful lock acquisition (timeout 500), it checks both indices against capacity, calculates free bytes with one slot reserved, copies a 16-bit-truncated length into the ring (including wrap), advances the write index, and tests 236/4096-byte flush thresholds selected by flags. It unlocks, then conditionally checks readiness/busy state and notifies. In interrupt mode or without a lock state it returns before touching the ring.

`verify_short_log_output.py` compiles Cortex-M55 source and compares stock/source public entries for **2,646/2,646** fixtures. The oracle compares all 16 descriptor bytes, 8,192 ring-buffer bytes, and ordered lock/flags/flush callback arguments. Cases include zero/invalid/small/large capacities, varied read/write indices, lengths 0/1/4/16/239/256, wrap and no-wrap copies, flags 0/1/4/5, readiness/busy outcomes, IPSR 0/3/15, null lock state and failed lock acquisition. The stock memcpy body executes; source copies are C loops. `short-log-output-receipt.json` records source, ELF, body and provider bindings. This is a bounded local source candidate only; lock, flags, flush readiness/busy/notify and their concurrency remain explicit lower providers.

For RAM provenance, stock flash contains exactly one literal each for the descriptor (`0x43d0e8`), lock state (`0x43d0e0`) and formatter sequence byte (`0x43d108` → `0x20074f9f`). Direct references in this logger cluster read/write the descriptor through `0x43c7fa`, `0x43c8d2`, `0x43ca50`, and the periodic drain at `0x43d040`; the sequence byte has one direct literal reference at formatter `0x43cbe0`. A direct uncompressed literal scan did not reveal the ring initializer; the reset constructor and compressed payload that initialize it are established below. Source linker placement and independently attributable initializer content remain separate.

## Production short-logger domain and boot-state audit

`classify_short_logger_calls.py` inventories **5,718** direct `BL 0x43ce9e` sites in the authenticated main disassembly. A conservative, at-most-12-instruction, straight-line register/literal trace resolves the `r1` format pointer to an ASCII stock flash string at **5,187** sites (**4,523** distinct strings); **531** remain indirect, earlier, ADR-derived, or branch-dependent in this pass. `short-logger-call-domain.json` retains every site, resolved pointer and format or an explicit unresolved record. This is pointer provenance for syntax only: it does not establish each caller's variadic argument values or that all branches execute.

`verify_short_formatter_actual_literals.py` selects **500** of those resolved stock strings with at most four conversion markers and no `%s`/`%f` pointer/value assumption, then runs the stock and source formatter public entries with synthetic token/arguments. **500/500** packet/sequence/FPSCR comparisons pass. This is a held-out syntax corpus from actual callers, not whole-caller behavioral coverage. The prior 10,344 tested synthetic/seeded cases remain valid. The finite production gap is 4,687 resolved sites not individually executed under their real arguments, plus the 531 unresolved format pointers; syntactic similarity does not close either.

The sequence state byte is at RAM `0x20074f9f` through stock literal `0x43d108`; the formatter's `0x43cbe0` is the only direct literal reference found in the fixed flash, and it reads then increments the byte modulo 256. Stock reset zeroes this address through its constructor table as documented below. The reset path also enables CP10/CP11 at `0x5e4270` and writes FPSCR **`0x02040000`** at `0x5e4288`. The other four `VMSR FPSCR` instructions in the full disassembly are paired save/restore sequences around FP operations at `0x4d42e0/0x4d42ec` and `0x59d2ea/0x59d2f6`; no direct static write that enables FP exception traps was identified. This is a finite image scan, not proof against an external debugger/boot stage changing FPSCR.

`verify_short_formatter_bootfpscr.py` compares stock/source public entries for **36/36** `%f`/`%F`/`%f %d` cases under that observed startup FPSCR preset, spanning the same 12 FP64 encodings as the earlier float matrix. Packet and FPSCR match. The tested presets leave exception-enable bits clear; enabled traps and physical fault delivery remain untested.

The short output provider's public ABI is `void(const void *packet, uint32_t length)` in `r0/r1` at `0x43ca50`; it truncates length to 16 bits locally. Its ring RAM word at `0x200004c8` and lock word at `0x20074388` are exact stock literal addresses, and its lower lock/flags/flush callbacks remain explicit. The 2,646-case stock/source output receipt covers this bounded ABI and effects with synthetic state. Stock initialization of the ring and sequence byte is now identified, but no independently attributable source owns the compressed initialized payload or linker placement. The extended logger `0x43d574` is a separate direct body.

### Stock reset constructor provenance for short logger state

`verify_logger_startup_state.py` checks the authenticated wrapped image SHA-256, reset vector `0x438004 → 0x5e4233`, constructor entries at `0x75d3c8`, and executes two stock constructor routines in Unicorn with sentinel RAM. The zero routine `0x5fa01e`, descriptor `0x75d3cc`, returns the next descriptor `0x75d3e0` and clears `[0x20004558,0x20075048)` and `[0x2013be70,0x2037ce44)`. This changes the formatter sequence byte `0x20074f9f` and policy byte `0x20074fa1` from sentinel to zero; the low ring descriptor remains untouched. The sentinels just beyond both zero ranges remain unchanged.

The subsequent low-RAM decompressor constructor is at table entry `0x75d3f0`, descriptor `0x75d3f4`, and calls stock `0x43a11e`; it returns `0x75d400`. Its descriptor points to a compressed flash payload at `[0x79189e,0x79430e)` and destination `0x20000000`. Original execution writes exactly `[0x20000000,0x20004558)` and yields SHA-256 `df1a1fdf7b2792a7c4ef7a2c5cc6d1423bc7833b556fdfcedb8d6d927fbbb743` for those 17,752 output bytes. The resulting four words at ring descriptor `0x200004c8` are `{base=0x200ccbd8, capacity=0x8000, read=0, write=0}`. The base plus capacity equals the drain's stock end pointer `0x200d4bd8`. `logger-startup-state-receipt.json` binds the input, descriptors, byte ranges, output hash and state assertions. This proves **stock runtime initialization**, not that the opaque compressed payload has source ownership or that a source linker/startup layout already reproduces it. The production lock-state lifecycle and later writes to the policy byte remain open.

The following shared-RAM record at descriptor `0x75d404` invokes the same stock decompressor and returns `0x75d410`. A sentinel-filled `[0x200ccbd8,0x200d4bd8)` becomes all zero in its 32,768 bytes; the low-RAM descriptor stays unchanged. Thus the stock initializer establishes both descriptor values and an empty backing store. This is a bounded, original-instruction observation, with no logger transport or concurrent-writer claim.

The decoder already has an independently written C body at `g2/components/audio/startup_unpack_offline/unpack.c`. `g2/analysis/audio-dispatch-initializer-closure-2026-10-08/REPORT.md` records original/C/Python agreement over all 17,752 bytes of this same low-RAM record and identifies its token format. The zero routine has an isolated C candidate in `g2/components/main/iar_runtime_candidates_20261010/runtime.c`, with synthetic descriptor comparisons in its own report; this pass adds a stock execution over the real descriptor but does not claim source-versus-stock whole reset equivalence. The retained Ambiq SDK IAR linker example (`g2/analysis/coverage-audit-parallel-2026-10-09/sdk-runtime-link-review-2026-10-10/iar/linker_script.icf`) places `readwrite` in MCU_TCM and `SHARED_RW` in shared SRAM, consistent with descriptor `0x200004c8` and backing store `0x200ccbd8`. It does not fix these exact offsets or prove the private production link order. A source structure can express the four meaningful descriptor fields and a zeroed ring array, but no retained source or production map independently attributes their declarations or exact placement. The remaining finite blockers are the logger-owned C declarations/configuration, exact section and linker placement, and source ownership for the other initialized bytes in both compressed records. Full image equality and producer compression settings remain outside this bounded component.
