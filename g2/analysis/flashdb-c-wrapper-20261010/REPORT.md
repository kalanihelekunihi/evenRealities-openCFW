# Source-defined Apollo FlashDB wrapper candidate

Completed bounded candidate: one function, SVC_FlashDBBlobRead at [0x54116e,0x5411f2), 132 original bytes. New source and explicit ARM32 callback contracts live in g2/components/main/flashdb_candidates_20261010. No canonical gate, coverage, build integration or full storage completeness claim.

Native original disassembly and retained adapter receipt establish index byte masking, database base/stride, length halfword masking, 20-byte blob layout, saved.len branch, ordered flag getter calls, diagnostic arguments, tick calls and unchanged provider return. Candidate leaves saved metadata uninitialized exactly as the original does before the provider; contract requires provider to initialize saved_len. Its externally provided literal table is populated from authenticated original data during comparisons. This table is an unresolved authentic source/link input for the full firmware build.

Eight independent original/candidate executions PASS using Unicorn 2.1.4. Original-byte SHA and whole Apollo SHA are authenticated in verify.py. Both executions use the same compiled C callback bodies: bounded fixture payload copy and saved length assignment, trace-recording tick/flag/log/compress callbacks. Calls redirect into actual compiled callbacks while preserving LR and stack arguments, rather than intercepting callbacks to supply canned register returns. Fixtures cover zero/nonzero source lengths, truncated output, byte/halfword wrap, index255 and diagnostic flag combinations 0/1/2/4/7. Exact returned value, 64 output bytes and ordered callback arguments match; stack pointer returns exactly. Callback storage is fixture RAM, not hardware/FAL/actual FlashDB provider semantics. These callbacks are test providers and cannot satisfy production storage closure.

Candidate compiled freestanding Cortex-M55 with Apple clang21, O1, warnings-as-errors. Fixture compiled Cortex-M33: M55 fixture generated an instruction unsupported by Unicorn even after disabling vectorization; preserved chosen compatibility recipe in build.sh. M55 candidate itself executes successfully against original under this oracle. Source-defined ELF has no embedded executable stock bytes. Original code is loaded separately as the comparison oracle, never linked into candidate. source.relocations.txt exposes six unresolved provider/literal contracts in the standalone candidate object; candidate.elf is only the fixture composition. Producing IAR options/compiler and authentic image placement remain unresolved. Exact byte equality is not asserted.
