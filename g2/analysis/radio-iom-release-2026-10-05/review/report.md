# Independent review: IOM release and command-queue termination

The refreshed comparison passes 336 cases and records 348 unique original instruction bytes; all 190 bytes attributed to the new local IOM consumer bodies were executed. I independently reran eight native original/source/model cases across term, disable, and uninitialize behavior, including valid and invalid command-queue handles, busy-pending disable, ignored disable failure during uninitialize, invalid IOM prefix, and a wrapping queue-index case.

The reviewed code has no executable stubs in the relevant path. It reuses the pinned `am_hal_cmdq_term` and real PRIMASK provider. The local handle’s queue pointer at `+0x828` is cleared even if command-queue validation returns an error; the buffer and opaque state remain unchanged. Disable checks validity, enabled bit, and pending word in order; if it proceeds, it clears IOM register bits 0 then 4, attempts forced queue termination, and clears the enabled flag regardless of that status. Uninitialize ignores a busy disable result and clears the initialized flag, which can leave the enabled bit set. These are faithfully bounded source behaviors; they do not imply hardware quiescence.

The stock wrap path and the current optimized source have one observable raw-store difference inside the critical helper. For a representative wrap, stock writes `curIdx=0x1ff` then `curIdx=0xff` with PRIMASK set; the current O2 source writes only `0xff`. The verifier records and separately asserts each side’s raw sequence, then canonicalizes only the contiguous `curIdx` writes for semantic comparison. All other RAM writes, ordered MMIO, masks, and final objects remain strict. I accept that treatment for the stated synchronous call-contract and final-state scope, with a material limitation: it does not prove exact internal-RAM write-trace equivalence if a concurrent observer or DMA could inspect `curIdx`. The evidence explicitly makes no internal-RAM/DMA-observer identity claim, so this limitation is documented rather than hidden.

The no-argument critical-entry hook has a residual R0 difference across original and source; the verifier normalizes only that non-argument register observation. The actual PRIMASK instructions and final PRIMASK are compared. The representative rerun also independently checked the raw `curIdx` sequences before normalizing them.

The IOM consumer names/layout remain inferred stock-specific code, not Ambiq SDK attribution. The test covers mapped synchronous nonaliasing states only. It does not establish buffer allocation/free, callback or expiry draining, asynchronous ownership lifetime, DMA quiescence, pending interrupt cleanup, complete transport shutdown, or production byte equality.
