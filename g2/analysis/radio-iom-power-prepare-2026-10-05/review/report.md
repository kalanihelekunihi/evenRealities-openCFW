# Independent review: IOM power-prepare prefix

The final aliased comparison passes 812 cases and records 708 unique original instruction bytes. I independently reran 11 native original/source/model cases against the refreshed ELF. These include genuine invalid-handle and busy early returns, retention values that truncate to zero/nonzero bytes, a CQ-pause path, the disable-then-prepare sequence, and aliased/non-aliased descriptor cases. The source manifest in the result has 20 entries and all hashes match current files.

The descriptor pointers and pause mask now come from authenticated Apollo table rows at `0x6C0F40`; I checked the mapped rows for modules 0, 1 and 7 against their register aliases. The success prefix reads the status register only when enabled, checks pending state before snapshot writes, copies the 13 modeled words in original order when the retention byte is nonzero, conditionally disables the command queue, writes the retained byte, then clears IOM config bits 0 and 4 in order. The existing CMDQ disable code and PRIMASK helper execute directly without stubs. The dynamic dispatch beyond this cut remains outside the model.

The successful original fragment is stopped at `0x55CA72`, the first instruction of the downstream power-domain call sequence. The verifier uses a synthetic caller-stop endpoint for this cut; on success, the stock fragment retains its stack frame while the reconstructed helper returns a preparation status. Thus the zero result means “prepared through this cut,” not that stock has completed a full power operation or that power-down succeeded. The genuine stock early error returns are executed and compared.

The disable-then-prepare adapter preserves that sequence and ignored status behavior, but does not implement the subsequent power callbacks. Tests use nonwrapping hardware-index values and do not close the preceding `curIdx` intermediate-store limitation; no internal-RAM or DMA-observer equivalence is claimed. The tests also use synchronous mapped state and do not establish buffer freeing, callback draining, NVIC cleanup, quiescence, physical power transitions, or complete shutdown safety.
