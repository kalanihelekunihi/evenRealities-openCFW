# Fixed IOM power-down preparation

The reconstructed operation-2 preparation prefix is implemented in `g2/components/foundation/radio_iom_power_prepare/power_prepare.c` and its interface header. It follows actual stock instructions at `0x55c7e8`, with operation fixed to 2, through the success boundary `0x55ca72`. Stock early errors return through the real epilogue. The C helper's zero status means **prepared for the downstream providers**, not powered down; it is a new bounded ABI, not the original whole-function success contract.

Handle validation uses `(prefix & 0x01ffffff) == 0x01123456`; null/invalid returns 2. When enable bit25 is set, `(IOM.status248 & 6) == 4` and pending word24 must be zero, otherwise return3. A disabled handle skips those ready/pending checks. A nonzero low retention byte snapshots 13 registers in order, conditionally invokes the actual CMDQ-disable provider through the local wrapper, and sets byte868 to1. Zero retention leaves old snapshots/flag unchanged. Finally the helper separately clears bit0, then bit4 of register11c. There is no outer atomic block, release, free, callback drain, or physical-power operation.

The wrapper `opencfw_iom_disable_then_prepare` preserves the bounded stock release ordering, including ignoring the previous disable status. It calls the existing source-backed disable/queue-termination consumers and unchanged Ambiq CMDQ/PRIMASK providers. It does not reconstruct the complete radio-release function.
