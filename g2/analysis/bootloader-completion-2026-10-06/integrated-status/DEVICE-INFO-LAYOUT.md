# Device-info layout and storage limit

The mode1 helper41d294 returns a 16-word device record through41d792. Locked bytes establish reads/writes and shifts; local Apollo510 SDK `am_hal_mcuctrl.h`/`am_hal_mcuctrl_device_t` independently identifies the field order. `device_info_layout.h` provides a64-byte C declaration with offset assertions.

Words0–5: chip part number, chip IDs0/1, revision, vendor and SKU. Word6 is set to1. **Word7 (NVM/flash size) is untouched**, preserving the caller's incoming bytes. Words8–11 are ITCM, DTCM, shared SRAM and MRAM sizes in bytes. The helper shifts the table's KiB halfwords by10, and the storage cache consumes word11 at offset44. Thus the existing source symbol/section `opencfw_boot_device_clock_factors`/`.boot_device_clock_factors` is a historical naming error: that24-byte table contains memory-size values, not clock factors. Its name is retained during current image validation to avoid changing frozen source identities; interpret it by the recovered layout.

The four low-SKU-bit memory tuples are `(128,256,1024)`, `(128,256,2048)`, `(256,512,2048)`, `(256,512,3072)` KiB. SKU bits[3:2] select MRAM1024/2048/3072/4096KiB. Words12–15 combine the ordered core-debug byte/nibble reads into JEDEC part/JEPID/revision/CID fields, with ten raw delay calls. The source and original direct profiles compare the complete record including untouched word7 and ordered reads/delays.

Cache-miss range validation calls query(selector1,64-byte temporary), caches word11 at200270c8, rejects addresses below4000 and accepts only size strictly below the cached MRAM byte count. Its computed end address is not used: this is **not** a proof that address+size lies within MRAM. The callback called erase only validates a4-byte range; programming rounds bytes to words and discards ROM status. Future patches should treat those as actual stock semantics, not a stronger safety contract.

Mode0 construction and wait-selector gates are source-recovered and tested separately. The downstream4213e6 helper is an INFO/OTP word-read service, not an event wait: local SDK am_hal_info.h establishes selectors CURRENT_INFO0/CURRENT_INFO1/OTP_INFO0/OTP_INFO1/MRAM_INFO0/MRAM_INFO1 and offset/count in32-bit words. Its native source is separately tested and source-ready; the shared image still uses a numeric alias for this mode0 branch. Resident ROM read48 body remains absent. Neither synthetic device registers nor this source/layout work verifies real silicon capacities or timing.

Selector0 returns a different **16-byte feature record**: four one-byte memory-kind enums, seven capability/MVE bytes, untouched padding byte11, and a32-bit trim-version field at12. This is important compiler ABI evidence: default32-bit C enum fields would give the wrong layout. The provided header uses explicit uint8_t fields and static assertions. Local SDK am_hal_mcuctrl_feature_t identifies capability fields HP/MIPI/GPU/USB/secure-boot/FPU/MVE and trim bits minor[7:0],major[15:8],valid16,PCM17. Stock mode0 reads one CURRENT_INFO1 word at offset0x244 and combines it with chip-revision nibble tests into that trim version; it is not a scheduler event or power-mode timeout.
