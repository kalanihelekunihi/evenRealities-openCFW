# Manager-task slice review

Reviewed `manager_task.c`, its header, the verifier, and README against the locked image (`f89a4c4657537cec6bfc572bdb8318866309b90a5d180c4307680d39824167b5`, load base `0x410000`). Capstone inspection confirms the comparator at `0x42E224` loads `0x007FE000`, logs it, and returns true only for exact `0x55555555`. The task at `0x42E2F8` performs the startup calls in this order: `BL 0x42E254` (`0x42E2FE`), `BL 0x42E276` (`0x42E302`), `BL 0x42E278` (`0x42E306`), `BL 0x42E2EA` (`0x42E30A`), then the flag comparator. It builds and sends 40 bytes with word zero set from that comparison, logs the branch, waits with mask `0x00FFFFFF`, options zero and timeout `60000`, then reads ticks. A positive flag below `0x80000000` calls `0x42E39A` (`BX LR`) and restarts the wait; other results compare unsigned `now - previous` with `60000` and update only the local baseline.

The first review found a call-order gap: source omitted stock `0x42E276` (`BX LR`) and the verifier did not observe its entry. This has since been corrected. `manager_task.c` now calls noinline `opencfw_boot_manager_setup_noop` between the `0x42E254` and `0x42E278` providers; the verifier observes the raw original entry at `0x42E276` and the source function entry and compares their `setup-noop` events without replacing either body. The README now describes the call as reconstructed and observed. The call is state-inert, but call ordering is now directly tested.

The refreshed `manager-task/comparison.json` receipt is PASS10/214 and all listed source hashes match current files, including the explicit no-op call and verifier update. It covers exact flag decisions for five values and six bounded loop inputs, including high-bit results and tick wrap; logger, MRAM, setup/signaling, sender, flag-wait, tick-accessor, and original memset are synthetic/intercepted. The seventh wait bounds the infinite loop. The tests compare logger arguments, the complete outgoing 40-byte message, wait parameters, tick calls, handler-entry R0, and original/source events. The mainloop does not show a periodic external action. The raw `60000` is a tick count; no tick rate or physical interval is established. MRAM at `0x007FE000` is outside the locked image, so the test fixture says nothing about actual device contents, queue acceptance, update execution, or application boot.
