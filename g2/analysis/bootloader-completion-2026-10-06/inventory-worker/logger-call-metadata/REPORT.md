# Recovering allocator/DFU logger call metadata

The remaining allocator/DFU/platform log aliases target synthetic08002100/20/30. Their canonical callers retain severity/source-line but discard tag, directory, function, format and consumed varargs. This is a real source-completeness gap even though bounded caller regressions pass.

We captured18 fixed source-line callsites at actual original EasyLogger entry4176ce, before the existing lower logger return contract. 1,011 original-only fixture cases (265 allocator,213 task,37 context,496 control; both machines deliberately original) produce88 distinct call/state records. These capture receipts are NOT source comparisons. Original binary/hash/load address and instruction windows are pinned.

Compiled call-site adapters pass88 comparisons of severity,tag,file,function,line,format and only format-consumed argument values. A revised standalone compiled DFU task, linked with these adapters, passes213 original/native task cases comparing full logger arguments and existing task effects. It keeps file/queue/install/reset/handoff as explicit synthetic children and logger output as a synthetic return. Two controls are rejected: include top encoded-size flags in blobSize and discard short-read byte count. The second control initially exposed a verifier bug: its format scanner omitted `%u`/`%zu`, so the altered byte count falsely passed. The scanner was corrected, prior receipts retained with before-u-argument-fix names, and both88/213 corpora rerun successfully; the byte-count mutant now fails.

Recovered values: blobSize uses low24 bits; crcCheck is bit26; crc is header+4; magicNum is the low byte at header+16, not the entire version word; targetRunAddr is header+20. Jump diagnostics read destination vector words0/1; short-read `%zu` consumes the actual read return count. Caller log detail cannot be reconstructed from header RAM alone, so task_with_log_detail.c explicitly passes `got` at line532. The original canonical dfu_task/task.c remains unchanged. The stock typos `updata`, `MallocFaile` elsewhere, original tags and directory strings are retained.

Source bridges in g2/components/bootloader/log_call_adapters are useful source-defined replacements for these declared fixed-line APIs, not recovered standalone stock function bodies. Their default unrecognized-line return is outside the fixed-callsite contract. No original-byte ownership is admitted for adapters. The revised task is not yet installed in an accepted integrated candidate; complete logger transport coupling is a separate step. Other logging families outside these18 callsites are not covered. Native adapters reread documented RAM fields under controlled snapshots; arbitrary concurrent mutation/scheduling is not proven.

Next actionable work is to link the adapters and revised task into the successor, bind printf to an actual verified formatting provider, preserve predecessor source objects except the explicitly superseded task, and validate existing boundary models plus direct original/native logging paths. This does not recover absent resident ROM40/48/0200ff20 or exact IAR compiler/configuration. No devices, commits, index or shared campaign state changed.
