# Startup SPOT and BL009 callbacks

This standalone analysis recovers the four initial callbacks selected by the stock dispatcher at `0x41ce52`. The locked input is `g2/blobs/official/g2-2.2.6.10/ota_s200_bootloader.bin`, SHA-256 `f89a4c4657537cec6bfc572bdb8318866309b90a5d180c4307680d39824167b5`, mapped at `0x410000` in Thumb state. No integrated firmware files were changed.

`handlers.c` contains host-testable portable hypotheses. `native_handlers.c` expresses the same operations with the stock no-argument ABI and direct global memory writes, so calls can observe partial state. The latter and `test_providers.c` were compiled to an isolated Cortex-M33 ELF and compared with the original callback bodies in Unicorn. The tests do not claim a byte-identical build or source closure of the whole bootloader.

The native comparison passed 19 fixtures: success, blocked-gate and each of three INFO failure positions for both profile initializers; eight revision/variant/state combinations for BL009; and the zero-return callback. It compared return values, all 108 bytes of profile state, BL009 output bytes, ordered INFO selector/offset/count calls and destination purpose, ordered MMIO writes, and timer-init call count. It visited **all original instructions** in each callback across the fixture set: 146/146, 350/350, 222/222 and 4/4 bytes. See [comparison.json](comparison.json). `evidence.json` authenticates each body extent/hash and includes bounded original disassembly in [stock-disassembly.txt](stock-disassembly.txt). The host test suite also passes (`startup handler model tests passed`).

The only controlled stock call in the native comparison is `0x421548`, which is the INFO-provider boundary. It validates the selector and forwards valid selector requests to `0x4213e6`; that routine calls the 8-byte thunk `0x41d28a`, whose branch target is resident ROM address `0x48`. The locked image includes the thunk but not the implementation at `0x48`; this comparison uses deterministic INFO response words and statuses and does not claim ROM or physical OTP behavior. The second direct child, `0x41cc04`, executes natively from the locked image during the comparison. It performs the timer-related MMIO sequence; this is not the separate SPOT trim-commit routine at `0x42ae9c`.

`test_providers.c` contains the independent timer-init side-effect implementation on the source side and the scripted INFO boundary. Those providers are explicit test cuts, not proposed firmware integration. The four callback models were newly written from the authenticated original bytes and Ghidra output. Historical `7b36787bb` has earlier files for `42abbc` and `42bdf0`; their ARM target entries are naked inline-assembly wrappers, so they are not treated as source implementations. The historical SPOT updater `runtime_spotmgr_power_state_update_42a878.c` and event dispatcher `runtime_event_dispatch_42f38e.c` have the same limitation: their host-side portable models may be used as hypotheses, but the ARM bodies themselves are assembly. No similarity-based source claim is made here.

## Remaining table-target frontier

These four initial callbacks are distinct from the functions stored in the runtime event/power table. The neighboring target list and historical corpus identify additional work without claiming it is closed by this report:

* Table target `0x42a878` is a 758-byte SPOT power-state update with direct calls to `0x41b8ec`, `0x427e0c`, `0x42a08c`, `0x42a19c`, `0x42a4bc`, and `0x42a550`. Its historical candidate is `g2/components/bootloader/core_overlay/runtime_spotmgr_power_state_update_42a878.c`; its ARM target body is inline assembly.
* `0x42ba00` is a 908-byte state/power handler calling `0x41b8ec`, `0x42ad40`, `0x42aef0`, `0x42b014`, `0x42b294`, and `0x42b6b8`. No exact-address historical source filename was found in the examined commit.
* `0x42d562` is a 96-byte event dispatcher calling `0x42ced8`, `0x42cfe0`, `0x42d104`, and `0x42d3bc`. Historical source files and closure notes exist for the latter three event handlers, but an exact `42d562` source file was not found in the examined historical tree.
* Table target `0x42f38e` is a 76-byte event dispatcher calling `0x42f204` and `0x42f2fa`. Its historical candidate `runtime_event_dispatch_42f38e.c` is a naked ARM assembly wrapper; the children have separate source-closure notes.
* Startup target `0x42d63a` appears in the bounded stored-target frontier. It was not selected as one of the four initial callbacks analyzed here.

The installer may store callbacks beyond those invoked immediately. This report covers the four initial callbacks selected by `0x41ce52`; it does not claim reachability or source closure for every stored event, power, begin/end or TON-hook target. The installed target set and separate immediate-call counts are recorded in `../startup-initialize/runtime-target-frontier.json` and `../startup-initialize/REPORT.md`.
