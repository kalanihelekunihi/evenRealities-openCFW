# Bootloader terminal paths

Recovered five actual stock bodies,96 original bytes: task-return41b390(42), malloc failure41b5f6(10), stack overflow41b600(12), DFU terminal42e1da(18), platform terminal4329c4(14). Independent terminal_paths.c and120 original-instruction comparisons with explicit child contracts. Return/debug path checks rawR0,SP,R4–R11 and masking; noreturn paths compare diagnostic bytes/name, ordered requests and first stopping boundary. Fault-store/BKPT are stopped offline, not exercised on hardware. Static post-fault/post-breakpoint loops are represented in source but not dynamically claimed as covered.

Task-return checks critical nesting200004c4 againstUINT32_MAX. Other values cause interrupt masking, invalid-address zero store and spin. The sentinel branch masks then polls a volatile local at SP-8; a synthetic debugger write releases it and returns that raw value. Malloc failure prints exactUTF8 stock text `MallocFaile：cannot malloc memory\r\n` then spins. Stack-overflow handler prints `task %s stack overflow` with the name passed inR1, then enters BKPT0 loop. These are real firmware diagnostics/fatal actions, not a replacement trap invented for missing code.

DFU terminal signals manager task1 (bit1 through existing signal adapter), then repeatedly calls CMSIS delay(UINT32_MAX), ignoring status. It is a signaling/sleep loop rather than an immediate reset in this body. Delay's recovered finite/guard behavior is separately documented; physical eventual wake and interrupt-context busy looping remain unverified. Platform terminal captures incomingR0 inR7 and calls the real IAR semihost exit repeatedly; the existing native exit implements that protocol. Standalone tests model a returning exit child to verify the loop, so they do not themselves execute the real semihost trap.

These source bodies are not yet installed into an accepted candidate in this report. Five child effects(signal,delay,print,mask,exit) are explicitly controlled in the body corpus; existing native dependencies are available for further coupling. No commits, index changes or hardware writes.
