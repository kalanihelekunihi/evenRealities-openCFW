# Event-flag waiter source evidence

Reference artifact: `g2/blobs/official/g2-2.2.6.10/ota_s200_bootloader.bin`, SHA-256 `f89a4c4657537cec6bfc572bdb8318866309b90a5d180c4307680d39824167b5`, load base `0x410000`.

This component provides source candidates for two manager-relevant paths:

| Address | Range | Size | SHA-256 | Role |
|---|---|---:|---|---|
| `0x41866a` | `[0x41866a,0x4186ce)` | 100 B | `89dc093b46e7e8b5d88e8a2566a523c2ab42397dd14467cd85a23ecd97258526` | Link current TCB waiter node into the event flags waiter anchor. |
| `0x416590` | `[0x416590,0x416610)` | 128 B | `df03eb8655d29e3f5b6a64d2dc42f56c716c83f56f6c6689afd419f7e824d6db` | Public event-flags wait argument/options/status wrapper. |
| `0x4199dc` | `[0x4199dc,0x419af4)` | 280 B | `19889f1080e9ec8d01c4c2baae609d939ef72b4f5477dfcd0048272886d1a8fc` | Match/clear, block, wake recheck, and result handling. |

The 280-byte lower core has no readable Ghidra output in the consolidated corpus; a source candidate is reconstructed from its original Thumb instructions and tested directly against them. The entry/call ABI is `(event_flags, mask, clear_on_exit, wait_all, raw_timeout)`; five arguments place the timeout on the stack. Its working flags path validates event/mask/context, enters the scheduler critical section, evaluates any/all matching, optionally clears matched bits, or builds waiter flags (`mask | 0x01000000` for clear-on-exit and `| 0x04000000` for wait-all) and calls `0x41866a` with the address of the event wait-count word. After blocking it resumes the scheduler, requests rescheduling when needed, reads the current TCB wait result through sourced helper `0x418d7a`, handles bit 25 by returning the low 24 wait-state bits, then enters the kernel critical section to recheck and clear event flags. The raw guard is fatal when runtime mode is zero and timeout is nonzero. Fatal branches mask interrupts, store to `0xffffffff`, and loop.

Stock `0x41866a` receives a pointer to the event object’s waiter-count word (`event + 4`), wait-control flags, and a raw timeout value. The event wait anchor is loaded from `*(event + 8)`. The current TCB pointer is stored at `0x20027134`; the initialized-kernel word used by its guard is at `0x2002716c`. It places wait metadata at TCB offsets `+0x18` (wait mask/control), `+0x1c` (previous), `+0x20` (next), and `+0x28` (event waiter-count pointer), updates the intrusive list links, increments the event waiter count, then calls the scheduler provider with `(raw_timeout, 1)`. No tick frequency is inferred.

`0x416590` rejects a null event object or mask bits in `0xff000000` with `0xfffffffc`. It calls the privilege/thread-state predicate `0x41602a`; a disallowed state returns `0xfffffffa` for timeout zero and `0xfffffffc` otherwise. Option bit 0 selects wait-all. Option bit 1 disables clearing on exit; otherwise clearing is enabled. The wrapper forwards `(event, mask, clear_on_exit, wait_all, timeout)` to `0x4199dc`, then applies the stock bitwise success test; an unmatched result maps to `0xfffffffd` when timeout is zero or `0xfffffffe` otherwise. Timeout arguments remain raw.

`verify_flags_runtime.py` executes original instructions and compiled source in Unicorn for 19 fixtures. Four exercise `0x41866a` with empty and populated waiter anchors and raw timeout values 0, 13, and `0xffffffff`. Nine exercise `0x416590` validation, privilege outcomes, wait-any/wait-all, clear-on-exit forwarding, and status mapping. Six directly exercise `0x4199dc`, including immediate clear, wait-all, zero timeout, waiter insertion, simulated wake, recheck, and wait-state-bit branches, including input wait-state `0x02000002` and result `2`. The comparison covers 454 distinct original instruction bytes. The timeout block request and scheduler/critical-section operations are intercepted at their exact call targets; these callbacks model requests and do not execute scheduling/concurrency.

Build and test: `make -C g2/components/bootloader/flags_runtime verify`. Result: PASS, 19 cases, 432 distinct original instruction bytes. No device is used. Event-list and TCB RAM are synthetic; scheduler behavior, concurrency, timeout expiry, and invalid fatal paths are not demonstrated. Integration depends on connecting the explicit scheduler/critical-section providers to their independently recovered source implementations.


## CMSIS runtime notification wrappers

The same owned component now provides readable candidates for `0x41623a` and `0x4162c4` in `g2/components/bootloader/flags_runtime/cmsis_notifications.c`. `0x41623a(thread, flags)` rejects a null thread or negative flags with `0xfffffffc`; in thread context it calls the recovered notify core first with `(thread, 0, flags, action=1, NULL)`, then with `(thread, 0, 0, action=0, &result)` and returns that prior-value result. In ISR context it calls the raw six-argument helper at `0x418fe8` with the stock two distinct stack argument layouts; if the first reports a transfer it writes `0x10000000` to SCB AIRCR (`0xe000ed04`). The ISR helper remains an explicit provider.

`0x4162c4(mask, options, timeout, opaque)` has a real two-register return ABI: `r0` carries status/flags and `r1` carries the remaining raw timeout (or original options on early validation returns). Option bit 0 selects wait-all; bit 1 clears the mask passed to the lower notify-wait call. It obtains the start tick from `0x41835a`, repeatedly calls the notify-wait core for index 0, accumulates returned notification bits, checks any/all matching, and subtracts elapsed raw ticks from the requested timeout. The fourth argument is saved but unused. `verify_cmsis_notifications.py` compares 10 original/source cases with lower context, tick, notification wait, thread notify, and ISR calls intercepted at the stock provider addresses. Both wrapper source and reference code execute; injected provider behavior is controlled, and no timeout unit is claimed.
