# Existing backup and dump coverage check

Date: 2026-10-06. Read-only inspection of documented and targeted local backup locations, WebFlasher backup semantics, and the G2 emulator artifact/model records. No device command or hardware access was attempted.

## Finding

I found no evidence in the inspected locations of a physical glasses full-flash backup that covers the SBL or an external NOR dump. This is deliberately scoped: the evidence supports “not found in the documented/targeted locations checked,” not “no backup exists anywhere.” Prior successful BLE OTA installs establish write transport only; they do not establish readback. The existing OTA absence of SBL bytes alone is not evidence that a separate backup is unavailable.

## Interpretation and next evidence needed

The “glasses backup” functionality found in WebFlasher is a recovery-bundle archive plus live temple identity snapshot, with installed-memory readback explicitly false. The checked backup elsewhere is for the case MCU. Neither can fill the 64 KiB SBL gap. The emulator’s optional 32 MiB NOR image is a deterministic virtual execution artifact for 2.2.9.22, not a hardware image and not a 2.2.6.10 acquisition.

Thus the honest current status is: **no known physical SBL/full-MRAM/NOR backup is present in the documented and targeted paths inspected; a separately held or differently named backup remains possible.** Before declaring it unavailable, obtain a user-confirmed inventory of any other known backup roots/files or locate an independently documented acquisition. Do not infer that plugging in the glasses permits a safe/read-only dump. The hardware reference says INFOC/INFO0 require read-only debugger acquisition, and describes SBL wired-update prerequisites as device-specific; no acquisition path was invoked here. Any later acquisition must have an explicit supported read-only method, image size/hash, chip/identity provenance, and address map before it can count as SBL or whole-device coverage.
