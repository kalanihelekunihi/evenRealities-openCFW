# Read-only acquisition readiness — no device opened

Current safe observation: `/dev/cu.usbserial-1340` is present. It is not identified as an Apollo debugger, and this check did not open it. `JLinkExe`, `pyocd`, `openocd`, `probe-rs` are not on PATH. Physical debug wiring/authorization, chip-specific no-reset attach support and readable MRAM access are unverified. No supported read-only **glasses full-memory pathway** is established with the connected case and current tools.

Both WebFlasher `src/lib/backup.js` implementations explicitly say installed-glasses memory readback is false. Their serial backup implementation is case flash readback, not Apollo. The case UART bridge documented in `g2/docs/reference/hardware-validation-notes.md:74–100` requires case reset/SRAM installation/PMIC handling; it is not a passive read-only memory reader and was not invoked. An SBL wired updater is not itself evidence of a memory-read command. Prior BLE OTA success is write-transport evidence only.

The documented conditional pathway is **physical Apollo debug access with supported non-reset, read-only attach**, whose availability must be established before acquisition. Configuration evidence needed is narrowly scoped: INFOC UART configuration/boot override/INFO0 selector at offsets 0x250,0x254,0x3fc from base 0x400c2000; active INFO0 UART words 0x28–0x3c, receive-window/config at0x54 and MRAM-recovery control0x68. Active INFO0 bank mapping must be established rather than guessed. `sybilSight-webflasher/src/lib/recoveryConfig.js:124–180` expects complete INFOC/INFO0 blobs for its offline decoder; that interface does **not** authorize dumping provisioning secrets or complete information spaces. Here we read no provisioning bytes or secrets. A later implementation should inspect only authorized non-secret configuration words, with first-party register definitions and identity binding.

Those configuration words can characterize the UART recovery route; they still do not prove that the route reads MRAM. For a real SBL capture the required payload is64KiB `[0x00400000,0x00410000)` with device/address/acquisition provenance and SHA-256. A supported debug access path must additionally prove that no reset, halt-induced state transition, protection bypass or write is needed under the user's constraints. If connection protection or mode requires a change, stop at that exact boundary and obtain explicit instruction. Immutable ROM address range is not established in current consolidated references; first-party mapping/identity is a separate prerequisite, not an address to invent.

This physical gap does not block offline reconstruction of the OTA Even product bootloader at0x00410000. It limits full platform boot/SBL/ROM behavior and hardware validation; exact IAR build inputs independently limit byte-identical reproduction.
