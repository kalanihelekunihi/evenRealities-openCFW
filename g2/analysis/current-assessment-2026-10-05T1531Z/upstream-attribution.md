# G2 upstream attribution: current evidence summary

The six locked payloads have very different attribution depth. There is no defensible all-firmware “percent recovered” from current records. Main has a broad, useful inventory of RTOS, Cordio, LVGL, Ambiq, filesystem, sensor and utility lineages, but most selected commits are compatibility baselines, not the actual private producing checkout. Even application services and closed GoMore/Goodix/NemaGFX code remain outside public-source attribution. The bootloader’s IAR/DLIB, FreeRTOS, littlefs, EasyLogger, TLSF and Ambiq HAL identities are useful but no supported source-coverage denominator exists.

EM9305 is strongest: the recorded archive audit matches 1,494 functions / 157,122 bytes of a 210,888-byte application (74.50%) across 48 archives; its broader function-provenance measure is 167,684 bytes (79.51%). The remainder is not automatically unique app code. Proprietary Packetcraft/EM Bleu source is unavailable publicly, and part of the evidence came from a third-party mirror. Codec matching is much smaller: 102 of 151 eligible NationalChip object sections, 68 symbols, and 5,374 bytes; that denominator is not the firmware.

Touch has a later exact result than its older library summary: the 56-byte `Cy_SCB_ReadArrayNoCheck` body at payload +0x5F18 matches Infineon PDL release-v2.21.0 with GCC 10.3–13.3 at `-Og`. This proves one PDL unit, not broad PDL/ModusToolbox use. Case compiler evidence now points to Keil armclang/armlink/Arm C library; FreeRTOS family/port and one exact handler are identified, but release and application source coverage remain unknown.

Key upstream submodules are pinned but mostly uninitialized in the current checkout; `nationalchip-lvp-kws` is present. Many consolidated library/toolchain claims cite pruned `g2/docs/research/*` evidence, so this pass reports them as documented attribution rather than newly reauthenticated facts. Raw research-corpus outputs remain subject to the workflow’s identity/scope review. No build or decompilation was run. Full details, scoped counts, exact reference paths, caveats, and per-payload findings are in `/tmp/opencfw-current-upstream.json`.
