# Independent review: audio DMA rearm

**Disposition: bounded implementation and evidence accepted with the stated limits.** I reviewed the source, pinned register/source evidence, stock disassembly, final observable comparison, and the accounting narrative. I independently ran 13 representative stock/source/model cases, including RX/TX normal and busy paths, partial RX/TX order, low-byte status/direction behavior, clear readback, IPB service, and two IRQ-prefix cases. Those two IRQ cases captured enabled RX bit 4 (one also included IPB); the stock and source reached the boundary before the real notifier while service returned busy status 9. The final full result independently records PASS for 899 scenarios / 1,019 invocations and 740 unique original bytes.

The extra status-output instrumentation addresses a real observation in the original: it stores raw INTSTAT to the output, reads INTEN, then stores the masked value. The final comparator observes both direct stores. In the actual ISR, the output is a stack-local ordinary word consumed synchronously before notification. There is no need to make that local or the API pointer `volatile` for the exercised call contract. The source reuses the raw value in a register instead of rereading the output RAM word; that is a valid synchronous, nonaliasing stack-local contract, but it is not an equivalence claim for concurrent observers or callers that alias the output pointer to MMIO. The report and verifier now state this distinction.

I found no implementation blocker in the reviewed service semantics. The pinned device declarations support the “NEXT” register interpretation. The code preserves the observed order: TX then RX error handling; RX before TX completion; clear completion before busy test; return 9 before that channel’s slot toggle/programming; earlier RX changes survive later TX busy; and the ISR tests captured bit 4 after service without acting on service’s return. Status low-byte truncation, clear readback, and IPB snapshot/clear ordering also agree with the disassembly. The new ISR seam ends before the actual notifier and makes no full-ISR ABI or queue-delivery claim.

Evidence remains bounded to synthetic MMIO and the Cortex-M4-compatible Unicorn profile. It does not establish physical peripheral transitions, live IRQ scheduling, cache contents/coherence, PCM-buffer ownership or lifetime, or consumer/task execution. Queue and consumer observations are static only. Huge cache inputs are retained as incomplete-prefix diagnostics rather than completed-path credit. The audio batch is not a complete firmware build or byte-identity result.

The representative artifacts and input hashes are listed in `review.json`. The two IRQ-boundary details are in `irq-boundary-rerun.json`.
