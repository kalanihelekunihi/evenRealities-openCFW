# Source-backed I2S DMA rearm and audio handoff

New source: `g2/components/foundation/audio_dma_rearm/rearm.c` and `rearm.h`. Build `make -C g2 audio-dma-rearm-simulator`: a separate O2 ELF links these routines with the **unchanged** existing audio handoff/cache sources. Prior ELFs and campaign state are preserved. The source covers the full stock service 0x5908a0, DMA-error 0x590cf4, IPB 0x5909b6, clear 0x590818 and status 0x590848 bodies. A separately labeled bounded ISR-prefix interface ends before real notification, rather than replacing it with a callee stub.

The important recovered fact is **two-stage DMA**. First-party pinned Ambiq source and a compiled offsetof check of its device-header declaration identify+0x224/+0x220/+0x21c as **RX NEXT address/count/enable**, not current-transfer registers. TX uses+0x22c/+0x228 and next-enable bit 1. The upstream getter's two-stage branch returns its selected slot, matching stock; the alternate single-stage getter returns the opposite buffer and does not match stock. This explains the selected-slot behavior without proving safe task scheduling or how long the buffer stays available. Prior generic descriptions of these registers should be read as staging the next job, not writing a currently active DMA address.

Service first handles TX/RX error bits by zeroing DMACFG and direction-specific status. It then handles RX completion before TX. Each channel clears its completion bit **before** testing next-job busy. Busy returns 9 without toggling that channel or programming a new address/count. If RX succeeded and TX is busy, RX changes persist: return 9 is not rollback or all-or-nothing. Error cleanup does not re-enable DMACFG. The original third configuration argument is not read by this compiled service; the source exposes a minimal handle/status interface. Otherwise it alternates ping/pong, writes the selected handle slot, next address, byte_length>>2 count, then ORs the enable bit while preserving other bits. The raw count write is byte_length>>2, dropping low two bits; physical count-field truncation is outside the raw register model. The getter still publishes 3,200 bytes independent of this field, so changing DMA length alone does not update its contract. No locks, copies, refcounts, allocation or release are introduced.

**ISR evidence:** authenticated vector 0x4380f0 points to 0x57a4d9 and matches header IRQ 44. Stock captures enabled interrupt status, clears it with INTCLR plus INTSTAT readback, calls the full service, then tests the captured bit 4. **It ignores service return 9 and still reaches notification for captured RX completion.** Native comparisons verify that order on busy and error branches. Source seam `opencfw_audio_i2s_irq_prefix` returns captured status; it is not a full ISR or queue implementation. Original notifier-present tests stop at0x53c6b2 with the real frame live; no returning-ABI claim is made there. Synthetic IPSR 60 for IRQ and 0 for getter fixtures is not actual exception entry, NVIC delivery, preemption or scheduler evidence. Emulator uses a Cortex-M4 compatible Thumb instruction profile; the pinned Apollo510 header identifies Cortex-M55 hardware, whose full behavior is not simulated.

**Validation:** 899 scenarios /1,019 stock-source invocations pass, tracing 740 bytes. All 610 new service/helper/ISR body bytes are exercised; 130 bytes overlap existing getter/query/cache evidence. This includes ping/pong alternation, already-selected pong, arbitrary selected pointer, single-buffer sentinels, zero/odd/max byte counts, RX/TX busy and partial success, both errors, IPB RMW order, direction/flag truncation, invalid mapped magic, both instances, incoming mask state, repeated calls and IRQ-prefix-to-getter sequences. Ordered MMIO reads/writes, selected-slot stores, getter publication, instrumented direct status-output stores, final handle/register/output state, guards and returning ABI are checked for the current compiled instance. The original status helper rereads its ordinary output word while compiled C reuses the value; no exact RAM-read identity or asynchronous-observer equivalence is claimed. Actual ISR status output is a stack local. Complete handle reads are not compared instruction-for-instruction; final data/guards and relevant writes are. All callees in scope execute real stock instructions; no executable provider stubs are used.

Two optional fixture actions are explicit: INTCLR clears synthetic INTSTAT, and an external next-slot bit clear allows a second staged job between repeated calls. Neither action is a measured physical peripheral transition. A third call without clearing the slot returns 9 and leaves the selected pointer unchanged. The old handoff regression also passes **282 stock/source cases plus 1,157 separate new checked-policy cases** against this integrated ELF; checked policy still has no stock-equivalence or original-coverage credit. Physical DMA movement, cache content/effects/coherence and borrowed-pointer lifetime remain unverified.

Fresh aggregate and final affected-test results are pinned in validation-summary.json; independent review is in review/. Cumulative deduplication is **6816  + 610  = 7,426** instruction bytes (touch 234, Apollo 7,192), with overlap values agreeing. There are 85 foundation C/header files, including the two new source/interface files; this is bounded source progress, not a complete firmware rebuild or new compiled-byte equality proof. The huge-positive raw-cache cases remain retained execution-budget prefix diagnostics, excluded only from completed-path coverage. Resident-ROM power timing and the optimized-tick emulator blocker remain unchanged.

**Task/transport context, static only:** notifier 0x53c6b2 builds a 12-byte `{type=2,reserved=0,tick=osKernelGetTickCount()}` message;0x53c638 attempts queue put with priority 0/timeout 0 and sets audio-thread flag0x400000 only on success. Consumer0x53c6f2 computes unsigned current_tick-message_tick, drops when >=41 (accepts 0..40 ticks), then calls getter0x57a7e0 and forwards pointer/length to 0x57adf8. The message carries neither PCM pointer nor length nor a buffer-ownership token; the consumer queries the selected buffer later. Timestamp acceptance therefore is not proof that it consumes the buffer belonging to that interrupt. No milliseconds or guaranteed ownership window is inferred. The dispatcher scans eight RAM rows through literal 0x53ceb4 ->0x20073fbc; authenticated initialized table contents and queue/task state are not present in these tests, so queue delivery and exact live dispatch were not executed or verified.

For app/CFW work, preserve the distinction between current and next job; respect busy's partial side effects; record service error/busy diagnostics if designing a changed ISR policy rather than treating notification as success; and do not retain or mutate this borrowed PCM buffer across DMA reuse without a producer/consumer contract. The next bounded contract is **the actual message/consumer handoff0x53c6b2 ->0x53c638 ->0x53c6f2 ->0x57adf8**, starting with queue copy and timely-consume paths. Full lifetime safety additionally requires authenticated initialized DMA/dispatch/queue state and an actual producer/consumer/peripheral scheduling contract or trace. No commits, flashing, deployment or hardware writes occurred.
