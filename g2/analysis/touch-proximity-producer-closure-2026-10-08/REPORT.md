# Widget 2 software raw filters and proximity producer

Independent offline source: ../../components/touch/proximity_producer_offline/proximity.c and proximity.h. Locked identities and reset-derived configuration are in provenance.json; original instruction evidence is in original-disassembly.txt. This is semantic reconstruction, not production integration or a byte-identical rebuild.

Widget2 config0xb218 has one sensor, method1/type6, flags0x3696. CPU filtering order is median of current and two prior inputs, fractional IIR (coefficient64/256), then average of current filtered value and three prior values. History is twelve bytes per sensor; fractional remainder is separate. Histories store each stage's input/output as appropriate, not interchangeable samples. Baseline update runs AFTER filters, then difference calculation, then proximity status. The native raw dispatcher composes sealed independent baseline/difference/IIR source; actual baseline integrity leaf0x4db4 returnszero.

Reset context0x200005c0: proximity threshold160, finger threshold1000, hysteresis10, on-debounce3, noise/negative-noise40, baseline coefficient1/256, negative reset30. Inactive proximity needs difference>170; active proximity is retained above150. Finger bit similarly uses1010/990. Equality belongs to the inactive/reset side. Each sensor has TWO counters, one per mask: bit1 proximity, bit2 finger touch. Nonzero counter decrements before threshold testing. A below/equal-threshold value reloads the counter and clears that bit. Zero counter sets it. Thus three qualifying software processing calls activate factory status; physical duration is unverified.

The producer clears/recomputes widget active bit0, preserving other widget bits. It preserves sensor overflow bit4 and all other unrelated bits. Existing report classifier0x441c tests ANY nonzero sensor status, rather than masks1/2; synthetic overflow-only status therefore remains observable to that consumer. This is a proven software interface, not evidence of an actual hardware overflow event. Saved-baseline numerical overrides still apply. Apps should interpret reported proximity transitions, not infer exclusive status-mask semantics from those codes.

Validation executes ORIGINAL ARM Thumb instructions in Unicorn and independently compiled C on separate synthetic guests:270 raw-filter comparisons;1344 proximity comparisons including thresholds±1, all low-three-bit status combinations, zero/one/two/255 counters and zero/one/two debounce settings;144 composed filter→baseline→difference→proximity comparisons spanning baseline negative-reset and automatic-reset behavior. Memory histories, fractional byte, complete sensor/context records and counters match. No external-call stubs are installed on these selected paths. Inputs and pointer layouts are synthetic. Factory thresholds are separately extracted from authenticated reset data; tests also vary configuration deliberately.

Boundaries: raw acquisition, hardware filter/commonmode, calibrated maximum raw, sensor enable lifecycle, malformed pointers and physical time remain unverified.
