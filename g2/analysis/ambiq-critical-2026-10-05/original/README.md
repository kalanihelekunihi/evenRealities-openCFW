# Apollo PRIMASK and scatter-loaded delay-loop evidence

This bounded packet authenticates the nearby critical-section helpers, the stored delay wrapper, the startup table/decoder, selected direct callers, and the decoded ITCM delay loop. Run `~/.local/share/opencfw/venv/bin/python verify.py` to recheck source-image hashes, Ghidra body records, selected caller hashes/callsites, scatter-table pointers, record fields, input bytes, and the decoder mirror. Its outputs are created exclusively; remove only generated outputs before a deliberate rerun.

The official OTA image is `g2/blobs/official/g2-2.2.6.10/ota_s200_firmware_ota.bin` (3,523,396 bytes, SHA-256 `36c5b0e499a68ac2493a497bdab9740fd3e7027730c26a9094eca47268a27863`). Its 32-byte preamble is excluded from the decoded 3,523,364-byte image (SHA-256 `19044a72bdfeb04c6b1b104d87da7b98e13cc18928528d84d999b6bcc0ba9701`), loaded at `0x438000`, ending exclusively at `0x794324`.

`FUN_00473940` (`[0x473940,0x473948)`, 8 bytes, SHA-256 `720733fcf19a5635fcab0791fcc2b007294712bb27536443ff79490821c168cf`) executes exactly `MRS r0, PRIMASK; CPSID i; BX LR`. It reads the current PRIMASK, sets the interrupt mask, and returns the saved value. There is no privilege check in these eight bytes. `FUN_00473934` (`[0x473934,0x47393c)`, 8 bytes, SHA-256 `6c169e0f7b32e9f34f42114fdbd5292b812805d62399aabd65f2299c040bd120`) executes `MRS r0, PRIMASK; CPSIE i; BX LR`; it returns the old mask while unconditionally issuing the enable instruction. It is not an exact restore helper. The adjacent six-byte `FUN_0047394c` only loads the literal at `0x474474` (`0x00776a3c`) and returns it.

Authenticated consumers confirm the mask pairing. `FUN_00538d18` saves the value returned by `0x473940`, updates queue indices, then executes `MSR PRIMASK,r0` using the saved value. `FUN_0044b0b6` and `FUN_0044b0d6` likewise save and restore PRIMASK around shared-state writes. The metadata lists 72 direct callers of `0x473940`; selected caller bodies and call PCs are hash-verified in `results.json`. The nearby `0x473934` has three direct callers in the corpus. This report states the instructions and observed restoration pattern; it does not assume behavior for unprivileged execution beyond the architecture's instruction contract.

The 80-byte stored delay wrapper at `0x4807a0` (SHA-256 `f95193c502160b469e1579e13223f1cdf488a2d8fab9ec07f686c9101fbed753`) is present in the image. It reads `0x40021000`, extracts bits `[4:3]`, and uses that field to choose a scaling path. The alternate path multiplies by literal `250.0` at `0x4807f0` and divides by `96.0` at `0x4807f4`; the clock-register pointer is literal `0x40021000` at `0x4807f8`. The final branch calls runtime address `0x40` at `0x4807ea`. The complete floating-point conversion and calibration behavior is disassembled, but not reconstructed as a source-level delay API here.

The target `0x40` is not absent: startup copies it from a stored initializer. `FUN_005e42b4` uses relative bounds at `0x5e42d4` and `0x5e42d8` to traverse the table `[0x75d3c8,0x75d410)`. At entry `0x75d3e0`, relative handler word `0xffcdcd3f` resolves to Thumb function `0x43a11e`, the in-image decoder (`[0x43a11e,0x43a19c)`, 126 bytes, SHA-256 `41e4a34428bb2c09774785d474f5209201f6551c823f0286eb66063dedc74a9d`). Its record begins at `0x75d3e4` and contains source offset `0x36f2a`, packed length `0x2c`, and destination `0x40`. The decoder defines input bytes as packed-length shifted right one, so the stored source span is exactly 22 bytes: runtime `[0x79430e,0x794324)`, OTA-file offsets `[0x35c32e,0x35c344)`. The scatter record and compressed bytes are therefore part of the official artifact; this is startup-loaded ITCM code, not a missing ROM implementation.

The decoder's first token (`0x10`) and extension byte (`0x0b`) set a literal count of 14; its pre-decrement copy loop implies 13 literal copies, followed by a 3-byte backreference. The second token yields a complete 24-byte output from all 22 stored input bytes in the statically mirrored decoder, with no implied read at the exclusive image end. The six-byte prefix at ITCM `0x40` is `subs r0,#1; bne 0x40; bx lr`, matching the loop called by the delay wrapper. Unicorn execution was attempted, but the installed emulator skipped the literal-copy loop and faulted on an invalid backreference read; this packet therefore treats the full output as a static decoder-mirror result, not a successful dynamic test. The compressed stream and startup scatter record are present in the artifact. In particular, `0x2c` is the packed length field used by the decoder (22 input bytes), not a 44-byte output size.

Selected static consumers include `FUN_004c0ea8`, which conditionally calls the delay wrapper after checking the MSPI XIP register, plus `FUN_0044ab42`, which calls both the critical helper and delay wrapper. The helper caller index contains 57 direct caller records; selected bodies and exact callsite PCs are recorded in `results.json`. Neither the delay wrapper nor physical hardware timing was dynamically tested.
