## Concrete negative mapping: coefficient does not identify enable

Demo General `LP_RC_IIR_FILTER_EN=true` at line39, with `LP_IIR_RC_N=1`. Existing stock launch6d74 sets CE_CTL `0x80000100`: channel enabled and baseline/signal detection enabled, raw IIR RCF_EN bit0 clear. Thus three equal LP coefficient/update settings cannot imply a matching generated target configuration. The hardware enable discriminator is already explicit and disagrees with the demo. This is a useful shortcut rejection: do not treat numeric frame defaults as a full configuration fingerprint.

Likewise public `LP_WOT_SCAN_INTERVAL_US=62500` (line73) and `LP_WAKE_TIMEOUT=160` (line74) cannot be imported into stock internal interval+40/timeout+74. Prior recovery labels those raw/cycle fields and explicitly lacks established wall-clock units. Application budget160/640 is a different recovered field; equality of the number160 would not link it to LP_WAKE_TIMEOUT.

## What remains absent

No target `design.cycapsense`, generated `cycfg_capsense.c/.h`, generating Configurator identity, exact middleware/PDL dependency lock or target link map is supplied by the example. Missing mappings include enum and bitfield conversion, slot-to-sensor/pin routing, CDAC/clock/autotune choices, LP interval unit conversion, history allocation declaration and target calibration inputs. The target raw maximum0 is runtime-populated; the example's finger-capacitance and autotuning properties cannot establish its calibrated value. Widget2 proximity configuration requires its own already-defined recovery scope.

All newly enabled finite vocabulary comparisons above are now recorded. Further XML generation or parameter-fitting would introduce assumptions absent from the current evidence. Static target table work can continue independently within P2 ownership; this reference does not open a reconstruction gate.
