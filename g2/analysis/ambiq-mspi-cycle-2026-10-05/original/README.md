# Apollo MSPI interrupt API evidence

This bounded evidence bundle authenticates four adjacent MSPI interrupt API bodies from the official Apollo firmware and records three named static callers. Run `~/.local/share/opencfw/venv/bin/python verify.py` from any working directory to recheck official-image hashes, the 32-byte OTA preamble mapping, Ghidra body records, caller hashes/callsites, literal loads, and generate `disassembly.txt`. The verifier intentionally creates `results.json` exclusively; remove only that generated file before a deliberate rerun.

The official blob is `g2/blobs/official/g2-2.2.6.10/ota_s200_firmware_ota.bin` (3,523,396 bytes, SHA-256 `36c5b0e499a68ac2493a497bdab9740fd3e7027730c26a9094eca47268a27863`). Ghidra's authenticated image is the blob after its 32-byte OTA preamble, base `0x438000`, SHA-256 `19044a72bdfeb04c6b1b104d87da7b98e13cc18928528d84d999b6bcc0ba9701`. Thus decoded offset is runtime address minus `0x438000`, and OTA file offset adds 32. Exact body ranges and hashes are in `results.json`.

The four bodies validate a non-null handle by masking its first word with `0x01ffffff` and comparing against literal `0x01bebebe`; invalid handles return 2. Literal `0x40060000` is the MSPI register base, and the second handle word supplies the module index, scaled by `0x1000`. The authenticated register offsets are INTEN `+0x200`, INTSTAT `+0x204`, and INTCLR `+0x208`. Enable reads INTEN, ORs the requested mask, writes INTEN; disable reads INTEN, clears requested bits, writes INTEN. Status reads INTSTAT and writes it to the output pointer; when the low byte of the third argument is nonzero, it also reads INTEN and returns INTSTAT & INTEN. Clear writes the mask to INTCLR and performs a volatile INTSTAT readback before returning success. These are observations from original instructions and are consistent with the pinned SDK source.

In the pinned SDK header, the requested qspi-write mask `0x1a80` is SCRERR (`0x1000`), CQERR (`0x0800`), CQUPD (`0x0200`), and DMA error/DERR (`0x0080`). No claim is made here about IRQ dispatch timing or controller behavior beyond the register operations and header definitions.

Caller evidence is static and bounded. At `0x46f4ea`, status-get is called with enabled-only false, then its output is passed to clear and interrupt-service. `am_devices_mspi_jbd4010_term` at `0x592658` performs the same sequence if its global handle is nonzero. `am_devices_mspi_qspi_write_async` at `0x59ce1e` clears and enables mask `0x1a80` on the handle at structure offset `+0x18`, then submits work and waits on a semaphore; this is only a limited call-chain interpretation, not a runtime trace. The function hashes and exact direct callsite PCs are captured in `results.json`.

Source references are local pinned files: `g2/build/foundation/ambiq-upstream/am_hal_mspi.c` (SHA-256 `5a91ab0c67bda4bd61c7d436b94b5a7c81693b948a331d282ae10e88cc5bf85f`, API implementations at lines 4026–4159), `am_hal_mspi.h` (SHA-256 `2a682bb7c1618982d6a802f3220a38696cd594c89d90e64b1a698d226b0a557b`, interrupt masks lines 120–135), and `apollo510.h` (SHA-256 `b6ca35dc828ef95825c0a22f06e6ca5ed558a6542dc74310515fdc350051a797`, MSPI interrupt register field definitions around lines 45257–45340). The code is source-level behavioral correspondence; no compiler byte match, full SDK build reproduction, or hardware execution is asserted.
