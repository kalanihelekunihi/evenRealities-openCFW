## What changed in understanding

Pool allocation does not malloc each slot: semaphore availability gates a LIFO free list, then a monotonically increasing virgin-slot index into supplied storage. Free writes a four-byte next pointer into the returned block and publishes it before giving availability. No zeroing, slot-alignment test, allocation bitmap or duplicate-membership test exists in the selected free body. Separate synthetic misuse traces accept interior/last-byte pointers and duplicate free while capacity permits; a duplicate can make the same pointer available twice. This is not evidence of a hardware fault or safe malformed use.

The complete control record is **116 bytes**, comprising a36-byte prefix and embedded80-byte semaphore. Constructor array size is `count*((size+3)>>2)*4`, but slot stride remains raw requested size. Use of odd/small sizes is not claimed safe: geometry probes establish this mismatch; full ownership sequences use sizes divisible by4 and at least4. Nonnull too-small/misaligned attribute probes are accepted because classification-1 still flows through static-pointer branches. Apps should enforce adequate control/array storage and exact slot ownership themselves rather than rely on this constructor rejecting every malformed attribute.

Allocation rechecks status after taking availability. Synthetic status invalidation at that point returns NULL without refunding the token; this does not prove a live deletion race. Empty task no-wait allocation returns NULL; positive task wait stops before actual yield. IRQ-style positive wait returns NULL without taking availability. Free can wake a waiting task; task higher-priority wake stops before handover, while ISR wake only requests PendSV. Wait units remain ticks, not verified milliseconds.

Main heap uses8-byte headers/alignment, charged size `n+16-(n&7)`, strict split remainder>16, address-order first fit and two-sided coalescing. The fresh synthetic heap's192504 usable bytes support a maximum request192495 in tested boundary cases, not a guarantee of live available capacity. Stock allocation failure reaches the real failure callback; with logger disabled it self-loops, and with logging enabled tests stop before the opaque formatter. Do not describe exhaustion as a reliably returned NULL or claim the fatal output sink was exercised.

## Exact validation

**484 original-instruction comparisons PASS on one final ELF**:204 pool ownership/ISR/timeout cases;118 static constructor/geometry cases plus48 dynamic constructor compositions;106 direct heap split/coalesce/failure-boundary cases;8 full failure-callback/formatter-boundary cases. These are comparisons, not484 functions. Semaphore/list/mask/task providers are reused. Main heap algorithms and list initializer had prior source attribution; this batch adds independently validated main bindings/current native integration rather than claiming their first discovery.

Final ELF, all source/header hashes and all four result files match receipts; unresolved symbols are zero. Every reached native instruction is source-only except explicit before-entry cuts. No stock instruction, register/flag or helper result was substituted. Source/stock instructions step one-at-a-time to avoid the recorded continuous-Unicorn Thumb IT anomaly. Constructor observation initially compared equivalent original/native heap entry addresses literally; normalized provider identity corrected instrumentation, without source changes. Heap assertion observation initially treated an ordinary scheduler mask call as assertion; LR-based caller discrimination corrected it. Both suites reran and final results pass.

Pure direct pool fixtures use constructed prefixes and semaphore state; constructor compositions additionally validate actual embedded semaphore initialization. Invalid/misuse snapshots are separate from valid lifecycle cases. Dynamic constructor/heap fixtures move synthetic TCB/control/array state outside the recovered heap region to avoid artificial overlap. Passive MMIO, synthetic state, original fatal loops and before-yield boundaries do not establish hardware scheduling, full boot, lifecycle safety or patch safety.

## Remaining bounded leads

The selected pool static/dynamic allocation chain now has native providers through its actual failure/hand-over boundary. Available reference CMSIS source also contains GetCapacity/GetCount/GetSpace/Delete, but no corresponding stock bodies were found in the current symbol inventory; they were not invented as recovered OTA functions. Formatter0x473036 remains an actual opaque provider for enabled fatal logging; installed SDK formatting implementations are candidate sources, not proven bindings. Actual resumed pool waits or invalidation reachability requires current task/queue/tick/pool state plus exception/scheduling trace or a validated scheduler model. Broader whole-image source inference and independent review are not complete.

No production firmware, campaign gates, existing seals, staging, commits or devices were modified.
