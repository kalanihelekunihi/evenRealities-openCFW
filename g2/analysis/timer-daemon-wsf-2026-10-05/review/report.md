# Independent review: bounded timer-daemon receive and callback drain

The final linked comparison is `g2/build/foundation/timer-daemon-wsf-simulator/comparison-final.json`: PASS, 204 cases, 1,714 unique original instruction bytes, ELF SHA-256 `6b9c5383edd7b3dc686a7b8b9936ea538fa25735f284e5ac82c815f8b27b971e`. I independently checked its source manifest against the current files; all hashes match. The linked module contains source-defined queue, event-group, WSF, radio/GPIO, receive, callback-drain, and task-critical routines. Authenticated stock firmware bytes are executed only on the emulator reference side.

`prvCopyDataFromQueue` is the pinned FreeRTOS V10.5.1 helper with only its `static` visibility removed. The helper’s source body and MIT notice are preserved and pinned by the component evidence test. The queue layout continues to use the reviewed 80-byte configured ABI. The nonblocking receive reconstruction follows the relevant pinned branch: scheduler-state query, task critical enter, empty return or copy-out/count decrement, optional blocked-sender removal/yield, critical exit, and success result. Blocking receive is explicitly outside the supplied component.

The drain loop reloads the timer queue handle and reads one item at a time using the actual producer/copy-out helpers. Negative command IDs dispatch the copied callback arguments; positive commands stop at a named external boundary. The verifier now checks callback entry order and each callback’s group/bits/count-at-entry, so the check catches reordering even when final event-bit OR would be unchanged. Receive cases cover FIFO pointer wrap, empty and nonempty queues, item-size zero with both valid null and nonnull output, malformed/null arguments, and 32-bit nesting near wrap. It validates output packet bytes and resulting queue state against the locked original execution.

The source critical helper raises BASEPRI to `0x30`, increments the recovered 32-bit nesting word at `0x2000309c`, and restores BASEPRI to zero when the outermost level exits. The verifier covers nested and empty/nonempty receive paths and compares prior BASEPRI values `0`, `0x20`, and `0x60`, plus prior PRIMASK cases in the WSF path. The valid receive path’s queue writes are checked while BASEPRI is `0x30`; when nesting remains nonzero, final state remains masked.

The stock comparison executes the original receive/copy-out and negative-command daemon instructions; the source side executes the reconstructed nonblocking receive and negative-command drain. The harness enters the drain function directly, rather than waking a daemon task through the scheduler. Scheduler state, blocked-sender removal, task count, yield-side scheduling, WSF application services, and event-group wait-list unblock/resume remain fixtures. The positive-timer command implementation is an external boundary. The preloaded queue is harness state; this does not implement the full blocking `xQueueReceive` path, timer-daemon scheduling, queue creation, destruction, or object lifetime.

Invalid cases stop at branch boundaries. In stock, the `0x5fa0a4` entry is the BASEPRI mask helper on the invalid path; the comparator stops before it runs and before the subsequent fault store/loop. Source-side invalid calls stop at the assert-provider entry. The overflow nesting cases likewise establish entry to an assertion branch only. These cases do not show fatal-path completion or assertion equivalence. The positive-command case has its own distinct marker and is not counted as an assertion.

No concrete correctness blocker found in the bounded valid path. Remaining limits are actual scheduler/daemon execution, real blocked-sender state changes, positive timer processing, object lifetime/quiescence, and physical interrupt behavior. These source-semantic comparisons do not claim whole-kernel completeness or byte-identical firmware output.
