# Independent review: GPIO state-write and radio pin helper

**Result: bounded review passed; no remaining implementation blocker found.** The selected stock state-write function is `[0x480FD6, 0x4810B0)` (218 bytes), and the radio helper is `[0x52DD7C, 0x52DD94)` (24 bytes). The code bounds and hashes agree with the current authenticated firmware and Ghidra function records. The state-write C body and GPIO macros bind to the pinned Ambiq SDK5.1.0 provenance, while `radio_board.c` is correctly labeled as a reconstruction from firmware behavior rather than upstream code.

The physical GPIO layout in the primary `apollo510.h` type is PADKEY at `0x400`, then RD `0x404`, WT `0x420`, WTS `0x43C`, WTC `0x458`, EN `0x474`, ENS `0x490`, and ENC `0x4AC`, relative to GPIO base `0x40010000`. The authenticated pointer literals at `0x481750` through `0x481764` resolve in the same order expected by the selected machine code: WT, EN, WTC, WTS, ENC, ENS. The corrected compatibility view and model now use these offsets. This correction is material: an earlier compatibility layout mapped EN/WTS/WTC incorrectly, and the preserved failed comparison exposed the mismatch. The corrected build uses the right source and ELF; I independently confirmed the emitted WTC/WTS stores and their stock addresses.

I independently reran 208 representative stock/source/model cases using the installed Unicorn environment. The rerun passed against firmware SHA `36c5b0e4…` and ELF SHA `2c4c13b0…`; its full evidence is in `representative-rerun.json`. It covers every operation 0–5 on pins 0, 31, 32, 93, and 223 under both incoming PRIMASK values and both raw-register and synthetic side-effect modes; invalid-bank address diagnostics for pins 224, 255, 256, 257, `0x10000`, and `UINT32_MAX`; raw operation bytes including 256+, unknown values, and `UINT32_MAX`; and the radio helper with authenticated raw configuration 3 plus injected alternate words. Full ordered MMIO state, masks, call order and independent expected outputs matched.

The raw operation adapter has an important, explicit ABI role. Stock machine code starts with `UXTB r1,r1`; a C `uint8_t` parameter alone does not force arbitrary incoming upper register bits to be discarded by the tested compiler. `opencfw_gpio_state_write_raw` performs the cast before calling the byte-typed unchanged SDK body, and the comparator uses that adapter for raw source inputs. The real reconstructed radio caller passes operation 0 and raw pin138 configuration 3. Normal callers should use in-range enum constants; callers modeling arbitrary register values must go through the raw adapter.

The modeled dispatch and side effects match the stock contract: operation 0 writes WTC, 1 writes WTS, 2 performs a PRIMASK-protected read/XOR/write of WT, 3 writes ENC, 4 writes ENS, and 5 performs a PRIMASK-protected read/XOR/write of EN. Unknown operation bytes return success with no MMIO. There is no pin or operation validation at the stock state-write entry. The bank is `(pin >> 5) & 7`, and bit is `pin & 31`. For address-only invalid-input diagnostics, bank 7 aliases the next register family (WT→WTS, WTS→WTC, WTC→EN, EN→ENS, ENS→ENC, ENC→the following block); pin 256 wraps to bank 0/bit 0. These cases are clearly labeled diagnostics, not valid pin or electrical evidence.

The radio helper first clears pin 93 by writing `0x20000000` to WTC2 (`0x40010460`) with incoming PRIMASK unchanged. It then calls the configuration setter for pin 138 with raw word 3, producing the validated PADKEY/config/relock sequence inside the setter's own critical section. The calls are not atomic as a pair; both returned statuses are ignored, and the consumer's void return is intentionally not interpreted as a status. Injected rejected configuration words demonstrate that the preceding clear remains visible and is not rolled back. Those words are test perturbations; stock uses 3.

Limits are explicit: WTS/WTC and ENS/ENC target-register effects use a synthetic host-side device model based on pinned register documentation, and output-active state is supplied as an external mask. Command-register readback latches and alias diagnostics are test abstractions. This proves software register ordering and interrupt-mask behavior only; it does not establish a physical output level, whether the pin is configured for output, pad mux readiness, clock state, electrical settling, complete radio shutdown, or device behavior. The stock consumer and all of its firmware bytes execute in the comparison, but this is not an end-to-end radio lifecycle test.
