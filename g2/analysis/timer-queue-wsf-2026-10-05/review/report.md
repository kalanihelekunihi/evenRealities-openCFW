# Independent review: timer-command queue producer

The corrected final comparison is `g2/build/foundation/timer-queue-wsf-simulator/comparison-reviewed.json`: PASS, 569 cases, 1,554 unique original instruction bytes, linked ELF SHA-256 `87bdca4d3375df611191e52fb7f87221403b4221f802836b9f1124d9384d7f28`. I independently checked all hashes in its source manifest against the current files; there are no mismatches. The upstream queue source SHA-256 and Git blob ID match the pinned `queue.c` entry in `tree.json`; both copied function bodies in `queue_subset.c` match their upstream source text and the MIT notice is retained.

The sparse `Queue_t` declarations and offsets match the V10.5.1 private structure under this compatibility configuration: data pointers and union at 0–15, send/receive list headers at 16 and 36, message count/length/item size at 56/60/64, and lock/config fields through the 80-byte structure. Queue sets are disabled; static allocation and trace fields are retained; actual arbitrary queue creation/configuration is outside this module.

The producer and copy helper execute as linked code on both stock bytes and the source module. The producer writes the callback packet through the reconstructed ordinary C copy helper and the pinned helper’s `memcpy` call, updates count and circular pointers, returns queue status, and conditionally updates the higher-priority output. The explicit consumer later reads the queued bytes and invokes the real timer callback and event-group setter, but the receive/daemon code itself is a fixture. This verifies the producer’s retained packet across stack reuse, not the production FreeRTOS daemon path.

The final verifier checks `BASEPRI == 0x30` on every write into the queue control/storage regions and at every receive-waiter removal, and varies the pre-existing mask across 0, `0x20`, and `0x60` in receiver cases. It checks restoration to the incoming value on valid sends. Both original mask helpers execute; the source helper uses executable MRS/MSR/barrier code. The independent producer model now checks queue counts, back-copy data and wrap, full-send immutability, higher-priority output preservation, and lock count. Front and overwrite cases are compared directly against original execution.

I found and reported a verifier bound bug during review: the initial storage write guard used Unicorn’s per-write width as if it were the queue item size, leaving most bytes of a multi-byte item unchecked. The verifier now uses the queue’s configured item size for the storage bound; the corrected `comparison-reviewed.json` passes and binds that verifier. The write-level BASEPRI assertion therefore covers the full storage array in this final result.

One assertion limit remains material. On stock invalid branches, the comparator stops at `0x5fa0a4`, which is the BASEPRI mask-helper entry used by the subsequent fault path. It stops before the helper executes and before the fault store/endless loop. Source invalid branches stop at the assert-provider entry. These observations show that the paths were entered; they do not demonstrate matching assertion completion or a full fatal path. The result metadata and current implementation report state this limit.

No remaining correctness blocker found in the valid bounded path. Receiver removal, task-count lookup, priority disinherit, queue dequeue, timer-daemon scheduling, event-group unblock/resume, and application context/wait/tick services remain explicit providers or synthetic consumer steps. The result does not establish actual task scheduling, group lifetime/quiescence, hardware IRQ behavior, full queue construction, whole-kernel completeness, or byte-identical firmware output.
