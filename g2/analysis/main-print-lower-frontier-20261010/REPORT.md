# Main FlashDB print lower frontier

This pass examined `g2_flashdb_print_buffer`, `g2_flashdb_print_sink`, and `g2_flashdb_vformat` against the pinned AmbiqSuite R3.2.0 adaptation and authenticated Main `0x473036..0x4733ee` formatter. `receipt.json` pins the sources, existing result receipts, isolated object, and ABI probe. No selected Main or Audio archive changed; Main remains **56 objects and nine unresolved names**, including all three print lower imports.

## Bounded ABI result

`vformat_alias.S` is an **unselected** one-branch source candidate from `g2_flashdb_vformat` to the already selected Audio `audio_heap_formatter`. Cortex-M55 assembly emits only `R_ARM_THM_JUMP24 audio_heap_formatter`. A target C ABI probe compiles with `sizeof(va_list)==4` and itself lowers a three-word formatter call to the same direct branch. The stock print wrapper passes `(buffer, format, ARM vararg word pointer)` in R0–R2; the selected formatter's public signature accepts `(char *, const char *, va_list)` in those registers. This supports an ABI-compatible same-image composition seam. It does not prove complete formatter behavior.

The existing Ambiq adaptation passes **88/88** selected original/source formatter comparisons, including bounded integer, string and finite-float cases. The selected Main print wrapper passes **96/96** original/source public-entry cases with synthetic formatter and sink callbacks, including sink replacement during formatting. Those are **reused receipts, not fresh cases**. They are not a composed public-entry comparison of the current alias plus formatter for all accepted inputs. The prior float oracle ran a DP-capable Cortex-A15 Thumb/VFP model after Unicorn rejected stock `VCVT.F32.F64` on M33/M7; that does not validate M55 trap/interrupt behavior. The formatter has no capacity argument; selected 1024-byte fixtures do not establish the production buffer size or safe output bound. Unsupported/malformed grammar and runtime format producers remain unproved.

## State and admission boundary

The Ambiq adaptation still hardcodes original `0x20074f7f` newline-translation state, `0x2006b930` shared buffer, and `0x200742f0` sink cell. Its `audio_sdk_printf` wrapper reads those directly. The Main wrapper source keeps `g2_flashdb_print_buffer` and `g2_flashdb_print_sink` external, but no retained source declaration, initializer, registration call or final linker placement owns their production bytes and callback target. The stock literal references confirm addresses, not source ownership. An invented zero buffer or no-op callback would exclude real production output and cannot close those imports.

The alias is therefore compiled as an isolated lead only. Archive admission needs a composed original/source public-entry oracle for the actual format grammar and varargs classes used by Main callers, capacity/output effects and FPSCR where relevant, plus source-owned buffer/sink declarations or explicit, independently proven linker/init contracts. Even after formatter admission, the two state imports would stay open until that evidence exists. **Archive delta: zero; new original/source cases: zero; three print imports remain.**
