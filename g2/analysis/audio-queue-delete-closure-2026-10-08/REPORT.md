# Audio queue deletion and allocated heap ownership

**64 PASS original/independent comparisons**, including **8 valid dynamic frees**, with actual context, heap free, free-list insertion, scheduler suspend/resume instructions on the original path. Independent C reuses actual suspend/resume/context peers; no child result stubs. [Reconstruction](../../components/audio/queue_delete_offline/delete.c), [results](results.json), [instructions](original-disassembly.txt).

CMSIS queue delete 0x449BEC rejects ISR context (-6), then NULL (-4). Valid queue invokes kernel delete 0x441EA2 and returns success. The selected kernel body checks allocation marker byte queue+0x46: nonzero (static) returns without freeing; zero calls heap free 0x456210. It contains no queue drain, message destructor, wait-list removal or global-handle clear. These facts do not prove that deleting an in-use queue is safe.

Original heap header size is **8 bytes**, read from authenticated word 0x78F118 through literal 0x45633C. Header at payload-8 has next pointer +0, size +4; allocated size bit31 must be set and next NULL. Original asserts violations; independent reconstruction has an explicit valid-block contract and omits assertion handling. Free clears bit31, suspends scheduler, increases available bytes at 0x20074660, inserts/coalesces by address, increments successful-free count at 0x2007466C, then resumes. Start sentinel is 0x20074158; end pointer global 0x2007465C. Sizes include the allocation header. Static queue success leaves bytes allocated; dynamic success hands the entire containing allocation to the free list.

Fixtures cover optional adjacent left/right free blocks, allocation marker 0/1, NULL/non-NULL, IPSR 0/15 and messages count 0/3. A 128-byte allocated block and coherent sorted free list/end sentinel are constructed. Task count at 0x20074A30 is zero, deliberately avoiding pending-ready/tick processing in actual resume; running flag is 1 for context classification. This is **not observed coherent live audio scheduling**. Queue fixtures provide allocation marker/count only, not full initialized wait lists. Same heap/free bytes, returned status, count, nesting and masks agree; independent expectations check byte-count and free-count increments.

Practical ownership implication: deleting a dynamic queue reclaims its allocation without invoking destructors for pointers embedded in queued messages. Inline message bytes reside in that allocation; separately allocated pointees need a proven drain/cancel policy elsewhere. This batch does not determine the real audio queue's static/dynamic configuration, allocation size, live waiter state, producer quiescence or disconnect/shutdown ordering.
