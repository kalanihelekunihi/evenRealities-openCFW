# DMA cache-maintenance foundation

The new source-backed provider is `g2/components/foundation/cache_maintenance/cache_maintenance.c`, with two exported interfaces: invalidate or clean-and-invalidate, and clean. The actual stock bodies are475014..47510e (250 bytes) and47510e..475194 (134 bytes). Selection follows the ranked Ambiq HAL DMA/cache gap, rather than physical power adjacency: these operations are shared by display MSPI writes and audio DMA receive, and require no missing ROM delay, scheduler callback or executable provider stub.

The source is an MIT reconstruction from instructions, not a copied or attributed Ambiq/CMSIS body. Historical census labels these unnamed bodies as unverified link-order candidates; that label is not used as evidence of authorship. Original hashes and consumers are preserved in original-provenance.json/disassembly. Both functions compile into a callable isolated O2 simulator target with no undefined symbols. Build `make -C g2 cache-maintenance-simulator`.

**Fresh comparison:768 cases, all384 original body bytes traced**, with exact model/source/stock ordered descriptor/register reads, maintenance writes and DSB/ISB instructions. Returning calls preserve SP,R4–R11 and incoming PRIMASK. The tests cover disabled-cache bypass, null whole-cache operations, flag-byte truncation, zero/signed-negative lengths, aligned/unaligned ranges up to3200 bytes, address wrap, inclusive set/way loops and field-truncation probes. There are no executable callee stubs. Large positive-length execution is not proven: a preserved initial length0x7fffffff fixture reached the instruction cap; it is excluded from completed-path PASS evidence and documented in fixture-diagnostics.md.

Recovered behavior that matters for app/CFW integration:

- Both providers first read CCR bit16. When it is clear they issue DSB then ISB, return0, and do not dereference a supplied range. Enabled-cache nonpositive signed length still loads both descriptor words, then returns0 without maintenance or barriers.
- A null range chooses whole-cache maintenance. It selects cache0, barriers, reads CCSIDR, then visits inclusive descending set/way values. Stock encodes set bits using mask0x3fe0 and way bits with shift30; these exact expressions are preserved rather than generalized to guessed hardware geometry.
- A valid range uses32-byte steps. It sends the original address, including its low bits, to the operation register and adds initial misalignment to the length. The instruction contract does not round the raw write value down. The maintenance operation's physical handling of those address bits is outside this emulator model.
- Invalidate selects invalidate-only for zero low flag byte, clean-and-invalidate for any nonzero low byte. Value256 therefore selects invalidate-only. Clean has its own operation registers.

The display write caller59ccdc loads request.buffer at+0x14 and request.length at+0x0c into a local8-byte descriptor, then calls clean47510e at59cd10 before constructing the transfer and invoking the blocking HAL at59cd26. These caller observations are static, not completed consumer execution, producer ownership or validated transfers. They establish why this reusable provider is relevant and where a future source caller can connect it.
