# Apollo MSPI/CMDQ disable and termination evidence

This packet authenticates the MSPI CQ-disable shim, the Ambiq CMDQ disable body it calls, the MSPI CQ-termination shim, and the CMDQ force-termination/index-refresh functions. Run `~/.local/share/opencfw/venv/bin/python verify.py` to check official image mapping, body hashes, selected caller hashes/callsites, and pinned SDK hashes, and to emit `disassembly.txt`. `results.json` is created exclusively; remove only that generated output before an intentional rerun.

The source blob is `g2/blobs/official/g2-2.2.6.10/ota_s200_firmware_ota.bin`, size 3,523,396, SHA-256 `36c5b0e499a68ac2493a497bdab9740fd3e7027730c26a9094eca47268a27863`. Ghidra uses its 32-byte-preamble-stripped image, size 3,523,364, base `0x438000`, SHA-256 `19044a72bdfeb04c6b1b104d87da7b98e13cc18928528d84d999b6bcc0ba9701`. Payload file offset = runtime address − `0x438000` + 32. Exact half-open spans, byte strings, and hashes are in `results.json`.

`mspi_cq_disable` shim at `0x4bfd62` is 12 bytes: it loads the queue handle from the passed MSPI handle at `+0x828`, calls `0x538e8c`, and returns that status. The lower CMDQ function at `0x538e8c` validates a non-null CMDQ prefix against literal `0x01cdcdcd` at `0x53924c`, returning 2 for invalid. If enabled bit 25 is already clear, it returns 0. Otherwise it follows the CMDQ handle's `pReg` pointer at `+0x24`, reaches the `regCQCfg` pointer at `pReg+0`, clears bit 0 of the pointed register, clears CMDQ prefix bit 25, and returns 0. The two bodies contain no wait loop or memory release. Source-level match: `am_hal_mspi.c:mspi_cq_disable` forwards `pMSPIState->CQ.pCmdQHdl` to `am_hal_cmdq_disable`; `am_hal_cmdq.c:am_hal_cmdq_disable` performs the validation, already-disabled success case, CQEN clear, and `bEnable=false` update.

The termination shim at `0x4bfc86` reads module number from passed handle `+0x04`, multiplies by `0x8d0`, and uses literal global state base `0x200523d8` (literal at `0x4c08a4`) to load the queue handle at global-state offset `+0x828`. If non-null, it calls `0x53909a(handle, 1)` and ignores the returned status; it then writes null to that global pointer and returns success. This is distinct from disable's local-handle `+0x828` lookup. The source helper `mspi_cq_term` likewise indexes `g_MSPIState[ui32Module].CQ.pCmdQHdl`, invokes `am_hal_cmdq_term(..., true)`, then clears the global pointer. In this firmware these may name the same state allocation, but the distinct access paths are explicit in both code paths.

CMDQ term at `0x53909a` validates its handle against the CMDQ signature, calls `update_indices` at `0x538d18`, and converts force argument to its low byte. For force=1, it skips the `curIdx != endIdx` error-3 check. It clears CMDQ init bit 24, clears bit 0 in the hardware queue config, clears the configured pause-enable bit, and returns 0. `update_indices` calls the critical-section helper, reads the current hardware queue index and queue address, refreshes CMDQ `curIdx` and `cmdQHead`, applies the wrap adjustment, and restores interrupt mask state. The inspected shim, term function, and index refresh do not wait for queue completion or free the caller-provided queue buffer. The check bypass and lack of wait are bounded to these functions; no behavior is inferred from callees such as critical-section helpers.

Authenticated consumers include `FUN_004c0ea8` (MSPI disable), which reaches both shims conditionally when the MSPI state has a queue buffer; `FUN_004c240e` and `FUN_004c26e0`, which also call the disable shim; and two unnamed `0x55c168` / `0x55c11a` wrappers that call CMDQ disable / forced CMDQ term on a handle at `+0x828`. The mspi termination shim `0x4bfc86` calls CMDQ term directly. Full static callsite PCs and hashes are recorded in `results.json`; these references do not establish runtime execution.
