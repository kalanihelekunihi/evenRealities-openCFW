# Health database startup dependencies

The service task at `0x926dc` calls health-database startup `0x70030` before its cache initializers, and sleep initialization `0x8dd8c` afterward. The health initializer now has a [tested C provider](health-db-startup-c-review.md). The locked instructions and raw REA span are recorded in [crash-time evidence](crash-time-c-review.json); temporary disassembly is under `build/goal-r1-health-db-analysis/`.

The first guard sums six descriptor byte sizes at `0x99bf4 + 16*i + 1`, using 16-bit wrapping addition, adds eight and rejects totals above 128. The 128 is the record maximum, not the database object's allocation size. The recovered/pinned short-enum FlashDB TSDB object is 100 bytes; native startup references it at `0x2001690c`. See [FlashDB ABI evidence](flashdb-abi-review.md).

Successful initialization installs lock/unlock callbacks via native control `0x63694` commands 2 and 3, then calls `fdb_tsdb_init` (`0x63814`) with name `health`, partition `health.db`, get-time callback `0x6a230`, maximum record length 128 and null user data. Lock/unlock read the mutex at `0x200067b0`, skip null handles and otherwise acquire forever/release. The mutex is created only if absent, using attributes at `0x99be4`. The C provider owns the 100-byte DB followed by the recovered 80-byte static mutex buffer; it reuses the existing six descriptor owners and event thread context. The lock/unlock/time callbacks are typed C.

Subscriptions use kind 1 with callback `0x5dce8`, then kind 0 with callback `0x5e698`, both with thread reference `0x20006694`. Both callbacks now have tested C implementations. If the retained marker passes, startup calls the now-C time accessor (`0x589e8`), forwards timestamp and a zero-extended offset halfword to `0x8aeb0`, optionally calls pending setter `0x8aea4`, then clears retained time metadata/CRC through the now-C `0x58960`. Do not assume signed extension where the caller uses LDRH.

Startup obtains current timestamp and UTC offset, converts to the eight-byte calendar at native frame +20, clears hour/minute/second bytes, and converts back to form the day boundary. It allocates/clears 128 bytes, queries with callback `0x88170`, frees the buffer, then calls retained snapshot restore `0x59ee4`. Daily replay `0x88170` and its six daily-cache writers now have a [tested C implementation](health-daily-replay-c-review.md). Snapshot restore `0x59ee4` now has a [tested C implementation](crash-snapshot-restore-c-review.md), including accessor/clear and the shared hourly accumulator restore. The [hour-boundary callback](health-hour-storage-c-review.md) now has a C implementation with six readers and the missing stress/temperature resets. The [time-transition callback](health-time-storage-c-review.md) at `0x5e698` also has a tested C implementation, completing both database subscription bodies. The [four clock-invalid guards and offline enqueues](health-offline-enqueue-c-review.md) now have C implementations and source-owned bounded ring state. Existing time/calendar, allocator, FlashDB-control and iterator C providers should be reused with their established interfaces. Allocation/init failures log and return; no synthetic success path is justified.

The earlier 128-case stock-startup replay validated the retained helpers. The new 465-case stock/C startup and callback replay covers orchestration with explicitly modeled providers and four rejected defect controls. It does not prove complete storage callback behavior, database contents, flash persistence or physical service initialization.

The 417-case startup integration now executes the real replay and six cache writers through the iterator boundary, with the FlashDB blob read and hour provider explicitly modeled. This is still not physical flash or complete storage closure.

Startup integration now executes the actual retained snapshot restore as well as replay and cache writes. The hourly rows, average calculator and overlapping stress prefix share one aggregate C storage owner; kind 5 aliases stress bytes 0..7.

The 447-case integration dispatches the actual hourly function pointer registered by startup, after replay and snapshot restoration. Direct reader tests also cover the clock-invalid paths through explicitly modeled guard/dispatch providers; those four bodies now have the C providers reviewed below.

The 457-case integration now dispatches both actual callback pointers registered by startup. Time-transition cases execute replay and cache resets after startup/snapshot restoration; sync-record read/write remain explicit modeled boundaries. The lower clock-invalid dispatch and enqueue providers now have C implementations. The four packet-flush paths now have [tested C implementations](health-packet-flush-c-review.md); event-post/sync-field providers and broader firmware/hardware dependencies remain unfinished.

The 830-case reader/hour integration executes the actual guards and enqueue paths with shared source-owned rings, including invalid-clock hourly append and midnight clearing. Event-post/sync-field providers, broader source linkage, scheduling and physical persistence remain separate unfinished work.

The [consume/empty and builder-reset C providers](health-offline-consume-c-review.md) now share the enqueue state. They remove records through an inclusive cutoff, stop at the first future head, and preserve builder metadata across reset. The four queue merge bodies now have [tested C implementations](health-offline-merge-c-review.md); the four packet-flush bodies now have C implementations, while event-post/sync-field providers remain unresolved.

The initial merge replay modeled flush effects; the new 612-case integration executes actual C flush packing/reset bodies. Event-post internals and physical transmission remain unproved.

The remaining acknowledgement registry core providers are `r1_ack_record_register` (0x83b20) and `r1_ack_record_remove` (0x83a00). Registry storage, timer behavior and physical delivery remain separate work.
