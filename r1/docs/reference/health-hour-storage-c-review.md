# Hour-boundary storage in C

The database subscription callback `0x5dce8` now resolves to `r1_health_hour_boundary_storage_orchestrator(uint32_t)`. Its six cache readers and missing stress/temperature reset functions are implemented in the same C unit. The startup declaration now uses this argument-bearing callback interface; its compiled instructions remain unchanged. Existing cache, timestamp, descriptor and shared hourly/stress owners are reused.

The [REA descriptor read](health-hour-storage-c-rea.json) matches the six native descriptor records. The callback truncates its argument to a byte before logging/validation, rejects hours 24 and above, and selects the previous-hour slot, with midnight selecting 23. It allocates and clears 128 bytes, stores the offset halfword and timestamp, and invokes each nonnull reader. Unlike record replay, cursor advancement happens even for a null reader, and sizes reload after callbacks.

Append error 3 triggers one FlashDB clean and retry. Other errors log without retry. The buffer is freed before midnight processing. For slot 23, the callback obtains the day boundary and zero-extended offset, logs, then resets each enabled cache. Allocation failure returns before midnight clearing; append failure still permits midnight clearing after the buffer is freed.

Readers preserve native halfword/byte, word/halfword or overlap-aware 24-byte copying. Under the native invalid-clock conditions (status zero, timestamp at or below `0x38640900`, nonempty data), HR, SpO2, HRV and activity may dispatch a guarded record using an unsigned offset-halfword divided by 60, then clear output. Temperature clears invalid-clock output without dispatch; stress simply copies. The four lower dispatch bodies remain explicit unresolved imports. They are not filled with normal-build stubs.
