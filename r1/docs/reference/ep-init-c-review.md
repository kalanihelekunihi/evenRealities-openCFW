# R1 EP storage initialization, cursor scan and ensure wrapper in C

`native_ep_initialize.c` implements storage initialization at `0x5e228`, cursor scanning at `0x3ee34` and the guard's ensure-initialized wrapper at `0x5e0ec`. The latter retains the already-used symbol `r1_ep_plan_initialization`; the lower FAL initializer is `r1_ep_storage_initialize`. This makes the address distinction explicit despite historical inventory names.

Storage initialization immediately succeeds when the ready byte is nonzero. Otherwise it finds `ep.bin`, stores its partition, finds the flash device by the name at partition offset 28 and requires at least 8192 bytes. Failure logging preserves native strings, argument reloads, IDs and mode reads. A missing device clears the partition pointer after logging; an undersized partition clears both pointers after logging. Success sets the ready byte and returns 1.

The scan allocates a 4096-byte buffer and examines two sectors through the actual C storage-read wrapper. A valid record has low header nibble `0xa`. The first invalid slot wins if any exists. Otherwise the slot after the latest nonzero timestamp is selected modulo 1024; equal timestamps favor the later slot. If there are no qualifying timestamps and no invalid slots, the native default latest index is zero, so the selected slot is 1. Rejected sector reads are skipped; reads that do not overwrite the buffer retain its contents. Allocation failure logs and sets cursor zero. Successful allocation is freed after the final diagnostics.

The ensure wrapper creates a missing mutex with type 1, then, only if inactive, runs storage initialization and scanning before setting active to 1. It does not require successful mutex creation to initialize storage, and scan allocation failure does not prevent the final active store. Existing state owners are reused without enlargement.

The three functions and actual existing storage, sector preparation, ring flush and export guard paths pass 1,024 stock/C comparisons. Cases cover ready-state bypass, lookup failures, partition-size boundaries, allocation outcomes, empty/full/single-hole sector fixtures, timestamp ties and unsigned values, retained scan-buffer contents, mutex outcomes, provider mutations and repeated ensure/guard sequences. Checks compare provider order/arguments, storage-initializer return, guarded shared state, modeled flash hashes, preserved registers, stack pointer and interrupt masks. Reconstructed execution may not enter stock instruction addresses. Private scratch, caller-clobbered registers and void returns are excluded.

Eight compiled defects are rejected: wrong ready fast path, wrong partition name, wrong capacity boundary, missing small-partition pointer clearing, wrong timestamp-tie precedence, zero-timestamp promotion, last-empty selection and storing active before scanning. The normal implementation was rerun afterward.
