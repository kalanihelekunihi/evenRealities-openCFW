# R1 charged-notification policy and NFC continuation in C

`runtime/native_pmic_charged.c` supplies charged policy `0x96cc8` and continuation `0x47f10`. Both reuse the existing late-setup byte, retry/post-timer/device callbacks, charge-event policy, touch service, GPIO pulse and ST25 SDK providers. No new state owner, assembly or executable blob is added. The continuation is a real function entry marked only as a label in the legacy census; its prologue, return paths and incoming branch are bound by raw evidence and emulated execution. It is recorded as a supplemental frontier entry, not assumed to be Goodix algorithm code because of a surrounding historical analysis range.

When the shared byte equals 0xa5, charged policy clears it before reading charger state. State zero logs the not-charged event, cancels retry, signals task flag 0x10 and returns. Other paths read ISNS then battery voltage. Only ISNS below 50 and voltage below 4200 increment the live byte; the retry budget tests its previous value at most 12. State zero at that point continues without clearing the incremented byte; state two and exhausted/high-voltage paths clear before continuing. Other states log ISNS and the live counter, pulse the ship pin and schedule retry argument zero at raw delay 0x199. Counter loads after callbacks and inside log gates remain live, including eight-bit wraparound.

The continuation initializes interrupt and enable bytes to zero, reads ST25 interrupt status and, on successful status with zero interrupt and zero charger state, cancels retry, runs charge-event policy zero and returns. Otherwise successful interrupt bit three closes touch source one. It cancels retry, reads raw control to obtain the enable bit, enables the mailbox if needed and reads that bit again, then runs charge-event policy with the observed bit. Finally it schedules the post-timer callback with zero argument/raw delay 0x1400 and installs the post-device callback as GPO completion. Nonzero interrupt-read status skips the early-state and touch checks but preserves subsequent setup. A failed control read does not publish output. Typed SDK register context access avoids imposing stock object offsets on the selected SDK. Successful reads supply the requested byte; initialized C temporaries provide deterministic fallback otherwise.

REA binds both routine windows and callback/string literals to the locked firmware. Verification passes 7200 charged-policy pairs, 150 continuation pairs, 135 live-mutation pairs and 256 seeded cases. Cases cover strict numeric boundaries, old/new counter values, the special 0xa5 path, full-width states/arguments/results, changing states and register-read statuses, raw control combinations, live flag mutation by voltage/log callbacks, ordered publications and callbacks, interrupt masks and poisoned stacks. Actual stock/C SDK interrupt, raw control and enable operations execute with prepared contexts. ADC/state, charge-event, timer/GPO/touch, IO and logging leaves remain modeled.

An additional 96 comparisons execute the actual stock/C GPIO pulse and pin-configuration helpers from the charged-policy path. Expected writes are pin-five configuration 3, output-set 32, modeled osDelay(200), and configuration 2. This proves register-write sequencing in emulation, not physical timing or electrical behavior. Ten compiled defects are rejected: inclusive ISNS/voltage boundaries, shortened retry budget, wrong special flag/state handling, wrong retry/poll delays, wrong interrupt bit, inverted mailbox-enable condition and wrong GPO callback. The normal probe passes after mutation testing.

The open-toolchain build compiles 820 units (738 application, 82 bootloader), retaining the same 70 application imports with no new failures or duplicate strong symbols. These bodies fill dependencies of the still-open NFC flag dispatcher. All 819 prior source inputs remain unchanged; 817 object hashes match and two generated boot objects differ with build paths. No G2 source or qualification selection changes. The dispatcher, final application link, startup placement and device boot remain open.
