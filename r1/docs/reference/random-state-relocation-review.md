# R1 random-state relocation for source link

The stock `rand`/`srand` state word was at `0x20007db0`. `native_libc_primitives.c` retained that fixed address even though the source linker lays out RAM differently. In the preceding strict map, `0x20007db0` belonged to Goodix processing workspace; after this change the map still assigns that stock address to Goodix workspace. Seeding or drawing random values through the old pointer would corrupt the optical engine when the GoMore initializer becomes reachable.

`r1_native_srand` and `r1_native_rand` now share one ordinary static C word. The linker puts it in `.bss.random_state` at `0x20021c74`, within `__bss_start__..__bss_end__`, so source startup clears it and no other C state occupies it. The recurrence and signed-mask result are unchanged: `state = state * 0x41c64e6d + 12345` modulo 32 bits, return `state >> 1`.

The ignored host probe `build/r1-random-state-relocation-20261111/probe.c` links the actual source and checks 128 draws from each of five seeds, including zero, all ones and the high bit, plus reseeding. The R1 source receipt `build/sources-r1-random-state-relocation-20261111-v2/report.json` compiles 943/943 application and 82/82 bootloader units without failures or duplicate strong symbols. The strict bootloader link succeeds. The strict application receipt `build/r1-link-random-state-relocation-20261111-v2/report.json` remains at 10 unresolved functions, 649,160/696,320 flash bytes and no overflow. This fixes a concrete RAM collision; it does not yet prove full GoMore startup or a complete application executable.
