# Motion interrupt notification with compatible C callbacks

The motion interrupt operation slot now has a consistent `void (*notify)(void)` contract. `r1_native_motion_interrupt` and the QMA interrupt wrapper now return void; the only repository caller, the sensor task, ignores their former status. Its declaration is updated. LIS2DW12 and BMA456W already use void no-op notifications. The QMA wrapper still acquires the bus, calls its IRQ boundary and releases the bus regardless of provider statuses. Configuration, probe and FIFO result contracts are unchanged.

`native_motion_stream.c` now calls the captured notification directly in C after its selector/callback guards. The incompatible void/status union and naked `bx r0` result adapter are removed. The obsolete `r1_motion_interrupt_result` export is gone, with no unresolved consumer introduced. The six-word operation table retains its 24-byte layout and interrupt pointer at offset 12. No callback is called through an incompatible return prototype. Incidental R0 values, including QMA release status, are retired from this notification API.

A fresh REA raw-byte read captures the complete 18-byte stock dispatcher at `0x50294`; locked stock execution supplies the behavioral oracle. All 1,216 paired stock/C cases pass. The probe links actual current C product tables and callbacks and verifies each table's interrupt binding. Cases cover missing selectors/callbacks, custom notifications, all three products, arbitrary callback scratch results, successful/failing bus and IRQ statuses, callback mutations of selection/slot state and two interrupt-mask states. Tests compare exactly-once notification, QMA acquire/IRQ/release order and effects, final selection state, preserved R4-R11, SP and masks. Exact callback frame depth and caller-clobbered return registers are excluded.

Four compiled defects fail runtime assertions: losing the callback, selecting an auxiliary operation slot, omitting QMA IRQ handling and omitting bus release. Mutations occur at callback boundaries; instruction-level interrupt races are not modeled. No Unicorn memory-read hooks are used.

Only the motion-stream object's code changes: the dispatcher changes and its obsolete branch adapter is removed. All other instruction sections, named relocations and data are unchanged, including the QMA wrapper/table machine bytes and sensor-task object. Their source declarations/prototypes now express the notification contract. The other 730 R1 object hashes are unchanged. `build/sources-goal-r1-motion-irq-pure-c/report.json` compiles all 731 units and composes both payloads without failures or duplicate strong symbols. Imports remain 157 application / 34 bootloader. `make sources-check` passes.

[Machine-readable evidence](motion-irq-pure-c-review.json) records raw REA bytes, build/harness hashes, results, defects and audit. Probes and positive subset ELF live under ignored `build/goal-r1-motion-irq-pure-c/`. The [earlier IRQ review](motion-c-irq-review.md) describes the superseded machine-result/frame contract. Bus/IRQ boundaries are modeled; physical sensors, timing, asynchronous interleavings and a complete source firmware link remain unverified. The optional source plan is unchanged.
