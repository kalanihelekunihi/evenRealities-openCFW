# GXT310 temperature read and one-shot trigger with C transfer words

`runtime/native_temperature.c` now uses ordinary C entry wrappers for `r1_gxt310_temperature_read` and `r1_gxt310_one_shot`. Each owns an explicit volatile transfer word and calls its existing C body. The two naked push/pop bridges are removed. Fresh REA analysis confirms stock read `0x6f600` and trigger `0x6f738`. Caller-clobbered R3 restoration and exact private frame placement are retired; neither is a C result.

The read body still clears the full word, requests register zero and two bytes, swaps the halfword's byte order, interprets a signed sample and applies the existing floating-point scale. Transfer status remains ignored; no-write/partial writes leave the initialized bytes available. The trigger body still initializes command `0xc101`, requests register one and two bytes, returns 1 for nonzero transfer status, otherwise performs the original short-circuit log-mode reads and returns zero. Callback mutations within the four-byte transfer word remain supported.

The normal read object passes 66,208 paired stock/C cases: all 65,536 halfwords, 160 FPSCR-mode cases and 512 random no-write/partial/full-word transfer cases. An independent signed sample calculation also checks every scalar result. Meaningful transfer arguments, zeroed initial storage, returned value, FPSCR, preserved core/FPU callee-saved registers, SP and interrupt masks agree. No Unicorn memory-read hooks are used.

The trigger passes 8,448 paired cases across log-mode sequences, statuses, addresses and transfer-word mutations. Tests compare initialized command bytes, transfer/log order and arguments, status policy, preserved core registers, SP and masks. Four compiled defects are rejected by runtime assertions: nonzero read initialization, wrong scale, wrong command and reversed status handling.

Only the two entry wrappers' instruction sections change. Their existing C bodies, channel adapters, calibrated pair reader, calibration reader bridge and data sections retain their instruction bytes and named relocations. The other 730 R1 object hashes, exports and imports are unchanged. `build/sources-goal-r1-gxt-read-trigger-pure-c/report.json` compiles all 731 units and composes both payloads without failures or duplicate strong symbols. Application imports remain 157 and bootloader imports 34. `make sources-check` passes.

[Machine-readable evidence](gxt-read-trigger-pure-c-review.json) records fresh REA observations, build/harness hashes, results, defects and audit. Probes and positive subset ELFs live under ignored `build/goal-r1-gxt-read-trigger-pure-c/`. The optional source plan is unchanged; no instruction identity is claimed for these new wrappers. Transfer and log providers are modeled. The calibration reader still has a separate stack bridge; electrical behavior, timing, arbitrary aliases/faults/concurrency, full transport integration and a complete firmware link remain unverified.
