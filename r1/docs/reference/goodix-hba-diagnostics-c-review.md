# R1 HBA diagnostic bridge in C

Stock `0x6ccc0` is called after every HBA calculation, including a failed calculation. The new `native_hba_diagnostics.c` binds the existing typed `goodix_primitives_spo2_input_diagnostics_emit` record emitter to the live HBA context, raw input and Goodix log registration API. It retains the timestamp-zero configuration gate, 17 stock format strings, per-channel PPG and enable-byte loops, formatter then direct-printer order, and separate free-memory queries for both active routes.

The stock logger cells at `0x20007d04`, `0x20007d08` and `0x20007d0c` cannot be used as fixed addresses in the C build: the current linker map places IQS state at `0x20007d08` and `0x20007d0c`. The registration function therefore owns relocatable C cells. The pinned demo configuration sets `__ALGO_LOG_CONFIG__` to level zero, so its `goodix_set_sprintFunc` call is compiled out; the current application map discards that registration function. With no callbacks registered, the diagnostic emits no records, matching the stock callback guards. The source-owned route remains callable if logging is enabled later.

The ignored host probe `build/r1-hba-diagnostics-c-20261111/probe.c` links the actual bridge and typed primitive. It checks all 18 records for a two-channel timestamp-zero input, exact strings and values, both output routes and two independent memory queries. It also checks the nonzero-timestamp direct-only route and no-sink path. This is a C behavior check; it is not a full stock/C instruction replay or physical-device check.

The R1 manifest has 1,025 units and 812 source files. `build/sources-r1-hba-diagnostics-c-20261111-v5/report.json` compiles 943/943 application and 82/82 bootloader units without failures or duplicate strong symbols. The strict application receipt `build/r1-link-hba-diagnostics-c-20261111-v2/report.json` has 10 unresolved functions, uses 649,160 of 696,320 flash bytes and reports no overflow. The bootloader strict link succeeds. The remaining HBA calculation and other missing functions still prevent a complete application executable.
