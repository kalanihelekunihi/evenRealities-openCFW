# R1 touch dispatcher and control adapters in C

`r1/src/application/runtime/native_touch_dispatch.c` supplies fourteen stock entries: dispatcher `0x46650`, configuration queue consumer, IRQ adapter/thunk, recovery callback and flag accessors, factory communication end, and six factory markers. The typed control header owns only authenticated fields: active byte `0x20006654`, six parameter bytes `0x2000665c`, slider flag `0x20007730`, and twelve factory bytes `0x20007750`. Their compiled initializers match authenticated cold RW; final placement remains a linker gate.

Dispatch processes queued configuration and IRQ flags before parking group 9 with the live watchdog. Nonparked paths then handle open, close/recovery, independent error logs, and the first factory flag among bits 6–11. Open preserves a nonzero active byte, acquires power client 2, schedules release at `0x800`, delays one RTOS unit and opens the board. Close clears task activity after logging, consumes board pending work, then tests the live slider flag before canceling and scheduling recovery at `0x66`. Recovery clears that flag, logs, and posts event 2.

The queue consumer clears its 44-byte buffer once, reloads the queue handle for each nonblocking get, truncates type to its low byte and checks payload length before updating byte/halfword parameters. Type 5 invokes pending-tap handling. Factory operations publish their marker before opening the bus, write one zero byte to register `0xff` through command `0x56`, close the bus, then store the captured value for markers 3–6. The delayed-release callback now accepts and ignores the scheduler argument; its object remains unchanged.

All 5,328 direct stock/C comparisons pass: 4,096 nonpark flag combinations, four park-precedence cases, 512 seeded live-state cases, 60 adapter cases, 144 queue-retention cases and 512 log-mode sequences. Another 264 comparisons execute actual C touch bus adapters and device-registry dispatch with changing handles and missing methods. Tests check field/store order and widths, callback identities, timer arguments, live state, queue retention, factory precedence, bus brackets, result retention, stack guards, preserved registers on returning paths and interrupt masks. The actual C worker-park helper executes. Twelve compiled defects are rejected, followed by final unmodified direct and integration passes. REA byte receipts match the pinned firmware image.

The normal build compiles 833 units (751 application, 82 bootloader) without duplicate strong symbols. The dispatcher import closes and three lower dependencies become explicit: IQS IRQ worker, register-write port and pending-tap handler. Application imports rise from 74 to 76. All 830 prior non-generated objects are unchanged; two generated bootloader objects differ. R1 validation passes for 833 units and 619 sources. Repository-wide checking still reports the unrelated G2 `resident_rom_thumb_set.S` manifest omission.

RTOS, port/IRQ, scheduler, board open/close, power and logging services remain modeled; the deeper probe also executes real software bus/registry layers against prepared callback fixtures. Delay values are raw RTOS units, despite stock log wording mentioning milliseconds. Physical I2C/touch behavior, timing, final application linking and boot remain unverified. Byte identity is not required by the current user instruction. [Review receipt](touch-dispatch-c-review.json); experiments are under `build/goal-r1-touch-dispatch-c/`.
