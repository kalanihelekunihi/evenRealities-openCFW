# R1 worker suspension acknowledgement in C

`native_task_suspend.c` supplies stock 0x46a74 as `r1_task_suspend_handshake`. The normal open-toolchain build compiles 807 units (725 application, 82 bootloader), with unchanged 69 application imports and 22 bootloader linker-metadata imports. R1 source checking and strict bootloader linking pass. Global source checking still reports the unrelated G2 unlisted `resident_rom_thumb_set.S` source. The manager worker and full suspension sequence remain unresolved; this is their handshake prerequisite.

The helper sends thread flag 0x800000 and ignores the signal return word. It then reloads the existing volatile `r1_native_sync_event_flags` owner, waits for the ordinal's bit with `osFlagsWaitAll` and timeout 0x5000 ticks, and logs only when the requested bit is absent from the returned word. The bit shift uses the ordinal's low byte and yields zero for counts at least 32, matching the ARM register-shift rules without C undefined shifts. Logging retains full result/ordinal words, two live short-circuited mode reads and the separate SDK mode gate.

The event handle is the same existing cell used by `native_sync.c` for worker acknowledgements. No second handle or replacement acknowledgement implementation is added. Its stock context word at 0x20006540 + 28 is zero in the authenticated decoded RAM data. The new helper uses its source symbol rather than a physical context address; final application layout remains a separate gate.

Raw-stock/C comparisons pass 2688 direct pairs across ordinal boundaries (including 31/32/255/256), acknowledgement/error words, changing log modes, interrupt masks and poisoned stacks. Twelve pairs mutate the event handle during the signal callback and verify the subsequent live reload. The proof checks every signal/wait/log argument, including the fifth formatter argument on the stack, while excluding private frame addresses and incidental void return registers.

Another 1736 pairs execute the actual normal-build CMSIS thread-flag and event-wait functions against raw stock, with FreeRTOS notification and event-group operations modeled. Cases include null handles, scheduler-not-started/running/suspended states, PRIMASK/BASEPRI combinations, timeout returns and handle replacement inside notifications. Twenty-four additional pairs execute the existing acknowledgement publisher, actual CMSIS flag setter and new waiter over one modeled event-bit store. Matching acknowledgements are observed and cleared through the shared owner. These publication pairs run in thread context.

The stock result test is deliberately a bit test: some error words contain the requested bit and suppress the failure log. It must not be replaced by a generic high-bit error test. Eight compiled defects are rejected: wrong signal flag, wrong timeout, stale handle capture, generic high-bit error handling, wrapped shifts, wait-any policy, rejecting extra acknowledgement bits and the wrong secondary logging bit. The final normal probe passes after all mutants.

REA windows at 0x46a74 (172 bytes, including 108 code bytes and following literals/strings) and 0x923a4 (16 bytes including its context literal) match the locked stock application. The audit preserves 804 prior object hashes, including the existing shared owner/publisher. There is exactly one application definition of that handle. Generated boot objects preserve allocated bytes and normalized relocations. The only manifest change is the new unit; imports and the source qualification plan are unchanged.

This is an ordinary C ABI proof. It does not execute full FreeRTOS blocking/scheduling or zero-mask kernel assertions, nor prove physical interrupt timing, complete manager startup, final application linking or device boot. Probe sources, reports and hashes are in [suspend-handshake-c-review.json](suspend-handshake-c-review.json).
