# R1 late NFC/charger setup and IRQ adapters in C

`native_nfc_late_setup.c` supplies six stock entries: late setup at 0x96a7c; YHM IRQ setup at 0x42ec4; its delayed signal callback at 0x42ed8; the GPO callback at 0x42d2e; GPO release at 0x77214; and GPO open/register at 0x77220. Legacy PMIC API names are retained, but the GPO operations use the existing I2C5 NFC resource owner. No opaque executable address, no-op child implementation or handwritten assembly is added.

The normal open-toolchain build compiles 810 units (728 application, 82 bootloader). `r1_pmic_late_init_plan_build` is supplied. Two deeper dependencies become explicit: `r1_st25dvxxkc_initialize_configuration` and `r1_nfc_charge_monitor_callback_00042d40`. Application imports therefore increase from 72 to 73. The battery acquisition initializer and NFC/charging flag dispatcher also remain missing. R1 source checking and strict bootloader linking pass; global checking retains the unrelated G2 unlisted `resident_rom_thumb_set.S` failure.

Late setup clears the accessed byte at stock 0x20006870, acquires the I2C5 resource, calls the delay provider with 50, runs chip configuration and releases the resource. It then releases/reopens the YHM IRQ input and registers the monitor callback, installs that IRQ setup routine as the YHM completion callback, and opens/registers the GPO callback. For configuration value exactly 0x55 it registers the YHM signal callback with argument zero and raw delay 0x400. Return statuses do not skip later setup stages.

The GPO adapter reloads the cached input after opening because a provider can replace it. The GPO callback releases that live device and signals battery task flag 1. The delayed YHM callback releases the YHM IRQ resource and signals flag 2. The latter has the delayed worker's ordinary void callback type; its signal result is discarded. IRQ setup and the other word-return adapters preserve their full result words. The existing I2C5, YHM and battery-thread owners are reused. Only the accessed late-setup byte has a new owner, with its cold zero value checked against decoded stock RAM.

Verification passes 720 direct adapter pairs and 192 complete late-setup pairs against raw stock. Actual I2C5 resource functions execute and their GPIO writes are compared, alongside actual registry dispatch, YHM release/IRQ registration/completion/word storage and battery flag wrappers. Cases cover null devices, missing operation slots, full-word provider statuses, GPO/YHM handle replacement during open, battery handle replacement during release, callback words and configuration values that differ above the low byte. Side guards prove that the late-state reset remains one byte. Numeric delay arguments are compared without a physical timing claim.

Eight four-phase sequences execute late setup, the existing YHM completion path through its installed callback, the GPO callback and the delayed YHM callback. They verify callback use and live owner state after registration. Device operation leaves, delay/OS providers, missing chip configuration/monitor and delayed registration are modeled; the monitor is never silently executed as a stub. The existing calibrated resource delay is bound to raw entry 0x784d0 in this probe. Physical IRQ delivery and delayed-worker execution for this particular adapter remain outside this proof.

Nine compiled defects are rejected: clearing state too late, wrong settling delay, stopping after chip configuration error, stale GPO handle, wrong GPO flag, wrong YHM flag, wrong installed YHM callback, narrowing the configuration gate and wrong delayed interval. The normal probe passes again after the mutants. REA windows bind the setup/adapters and their literals to the locked application.

The audit preserves 807 prior object hashes, including the existing resource, YHM, registry, battery and task code. There is one application definition of each reused I2C5/YHM/battery owner. Generated boot objects preserve allocated bytes and normalized relocations. The manifest only adds the new unit; the source qualification plan and G2 sources are untouched.

The remaining battery acquisition initializer includes a separate diagnostic ABI gate: stock 0x73694 copies device-info words from its 52-byte cached-read frame even when that read leaves prior bytes. That behavior needs evidence-backed treatment before claiming a full C initialization path. Chip configuration, monitor/dispatcher behavior, final application linking, manager startup and physical NFC/charging/device boot remain open.

Reproduction sources, results and hashes are in [nfc-late-setup-c-review.json](nfc-late-setup-c-review.json).
