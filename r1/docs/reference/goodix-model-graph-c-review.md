# R1 native SpO2 graph construction in C

The native graph builder at `0x4387c` and seven descriptor/accessor helpers now have one implementation in `r1/src/application/goodix/native_spo2_model_graph.c`. The [receipt](goodix-model-graph-c-review.json) pins REA reads, native disassembly, source, normal and tested objects, fixtures and results. It supersedes the graph boundary in the [generated model constructor review](goodix-generated-model-c-review.md).

The native ABI accepts an output pointer and model cursor and returns the advanced cursor. It constructs 352 graph bytes while consuming 1,756 model bytes. The existing portable boolean/length API has extra validation and is retained separately; it is not used as a native replacement. The C implementation preserves call order, including the final descriptor at offset `0xf0` after those at `0x108`, `0x120` and `0x138`.

Descriptors preserve eight byte-sized fields, raw float representations, full-width unsigned grouped division before byte truncation, wrapping arithmetic, aligned weight spans, bias/state offsets and cursor-update-before-copy aliasing. Pair and quantizer helpers capture raw words before cursor/output writes. The quantizer retains its null-cursor default of 0.0/1.0. Group divisors must be nonzero, as in the admitted native graph callers.

All 1,605 paired stock/C cases pass with independent complete graph, descriptor, cursor and data oracles. Cases cover overlap between graph output and model input, cursor aliases, dimension overflow, ignored arguments, byte truncation, and active floating-point control/status patterns. Every one of the 1,196 native instruction bytes executes. No function ports are modeled in the direct graph/helper comparisons; the source cannot execute stock code. Eighteen compiled defects are rejected.

All 128 complete C constructor/heap/teardown cases pass with graph construction executing in C. The model resource remains unchanged; the instance and recurrent state allocations coalesce back to the prior heap top. Five external logging/system ports are modeled in this larger fixture. Model pointers are normalized only for heap comparison, never rewritten during execution. Broad memory write hooks remain disabled following the independently established Unicorn discrepancy.

All 885 units compile and compose without duplicate strong symbols. The tested object equals the normal object, 874 prior nongenerated source/object pairs are unchanged, and no writable state was added. One graph import is replaced by seven opaque executor identity data bindings: application imports rise from 67 to 73, boot imports remain 22. All eleven model/graph executor implementations remain unresolved. The identity words do not establish a callable C ABI or numerical inference behavior.

Extreme dimensions establish logical wrapping layouts rather than physically valid large allocations. Invalid pointers, divide-by-zero, cold floating-point activation, concurrency, physical fault behavior, numerical inference, final executable linking/startup and device boot remain open. This is an `ld -r` composition rather than a bootable firmware image. Byte identity is waived for the current goal.
