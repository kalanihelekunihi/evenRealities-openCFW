# R1 task startup and BLE/touch lifecycle in C

`runtime/native_task_startup.c` supplies stock startup `0x46b20`. It initializes the delayed-event system and watchdog, invokes storage creation, obtains the current thread ID and lowers priority to eight. It then invokes NFC/charging, BAE RX, message TX, GTX, BLE and service creation, queries configuration, selects factory only for full-word 0x55 (otherwise sensor), invokes touch creation, obtains the current ID again and restores priority 53. Lifecycle callbacks are reloaded from their existing mutable prefix owners immediately before each call. No initialization or priority return status suppresses later stock steps.

`runtime/native_io_worker_lifecycle.c` supplies BLE create/stop `0x44f20/0x44ec0` and touch create/stop `0x46e7c/0x46e64`. BLE uses name `ble`, 112-byte control block, 4096-byte stack, priority 52 and TZ module one. Touch uses name `touch`, the same reservation sizes, priority 49 and TZ module one. Both have zero attribute bits/reserved word and eight-aligned C storage. Existing service/touch thread-handle owners remain authoritative. Creation publishes the returned handle before the native allocation-fault primitive; stopping a nonnull handle always clears it after termination, including on termination errors or callback replacement. Null stop does nothing.

The two new eight-byte lifecycle prefix owners fill the previously missing BLE/touch create/stop cells. They do not duplicate the existing thread-handle owners. NFC, BAE RX and factory lifecycle declarations now use the shared context header; all three consumer objects are identical after that extraction. Existing event/transmit owners continue to use the same header. The BLE entry at 0x91f54 and touch entry at 0x927c8 remain explicit unresolved imports `r1_ble_io_worker`/`r1_touch_io_worker`; there are no substitute worker loops or success stubs.

REA binds startup/lifecycle code, callback literals and both complete 36-byte native attribute records. Verification passes 32 stock/C startup pairs covering live callback replacement, configuration changes after worker creation, full-word configuration comparison, distinct current-ID queries and ignored priority/init errors. Twelve additional pairs execute the actual BLE/touch constructors from startup with RTOS leaves modeled. Ninety-six lifecycle pairs cover null/nonzero old handles, success/failure creation, termination errors and handle replacement during termination. They compare worker entry identity, names, all metadata fields, storage sizes/alignment, publication order, SP/callee-saved registers on returning paths, masks and poisoned stacks. Real stock/C allocation-fault actions are observed as BASEPRI 64 followed by a zero write to UINT32_MAX; faulting paths do not claim ordinary return or physical exception recovery.

Eight compiled defects are rejected: wrong temporary/restored priority, truncated configuration, omitted delayed initialization, wrong touch priority, wrong BLE worker pointer, publishing after the fault check and retaining a handle on termination error. The normal probe passes after mutation testing. Worker execution, actual RTOS task creation, physical hardware and scheduler preemption remain unverified.

The open-toolchain build compiles 824 units (742 application, 82 bootloader), with 71 application imports and no new failures or duplicate strong symbols. Two real worker imports become explicit; none are hidden or replaced. Of 822 prior units, 820 object hashes match and two generated boot objects differ with build paths. Existing source changes only extract shared lifecycle declarations. No G2 source or qualification selection changes. Manager wiring, final linking, startup placement and device boot remain open.
