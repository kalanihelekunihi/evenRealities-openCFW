# R1 BLE peripheral watchdog in C

`r1/src/application/board/native_peripheral_watchdog.c` implements stock `0x4d024`. It uses the existing connection fields, Nordic connection-count and advertising-start providers, C advertising-availability adapter, scheduler callbacks and diagnostic sinks. A new one-byte owner represents the authenticated zero cold RW counter at `0x200064b1`; final linker placement remains unproven.

The policy captures the SDK peripheral count, increments the byte counter, logs when the old value is divisible by 60, then reloads the counter and clears it if it equals 255. With fewer than two links, either unoccupied handle permits an advertising availability check; an unavailable set cancels the role-sync timer and starts fast advertising. Nonfatal paths rearm the 0x2000 flag callback at delay `0x2800`. Start errors log and continue.

Fewer than two SDK links with both handles occupied is an assertion path. Stock logs the inconsistency, delays 500 RTOS units, emits five retained assertion records, and calls an even stack address. Cortex-M rejects that address's clear Thumb bit before executing its contents. The C implementation calls the even address of an aligned stack object, retaining the deliberate invalid-state fault without retaining an opcode word, inline assembly or a fake successful return. This does not claim a direct system-reset request, physical exception delivery, or identical fault-site/private-stack data.

The differential harness passes 2,048 counter/count cases spanning every byte value and 720 branch/log/live-mutation cases. A further 144 cases execute actual SDK peripheral counting and atomic operations with prepared connected/central masks, plus the actual C availability adapter. Checks include counter reads, connection short-circuit order, callback identities, timer arguments, error continuation, log data, assertion details, stack guards, preserved registers and masks. Fatal cases verify an even stack target and clear Thumb state at emulator instruction rejection. Ten compiled defects are rejected, followed by an unmodified-source rerun.

The normal build compiles all 828 units (746 application, 82 bootloader), with no duplicate strong symbols. Application imports fall from 74 to 73 without adding dependencies. All 825 prior non-generated objects are unchanged; only two generated bootloader objects differ. R1 manifest validation passes (828 units, 614 sources). The known unrelated G2 manifest omission remains outside this change.

RTOS delay, advertising start, scheduler and diagnostic sinks are modeled here. These results do not establish physical recovery, timing, final application linking or boot. Byte identity is not required by the current user instruction. [Review receipt](peripheral-watchdog-c-review.json); experiments are under `build/goal-r1-peripheral-watchdog-c/`.
