# Health backward-time event and reinitialization in C

The shared `native_health_lifecycle.c` unit now also supplies the 86-byte stock event adapter at `0x5dc08` and the 46-byte force-reinitialization entry at `0x4c37c`. The initializer at `0x4bd98` remains in the same unit. These are ordinary C implementations with no inline assembly or executable byte arrays. The existing authorization-state owner now supplies the shared flags directly, avoiding a separate owner for the same RAM.

The event adapter reads the new timestamp at packet +8 before the old timestamp at +4. It ignores null input, unsigned forward/equal time, and backward differences below 180 seconds. A difference of exactly 180 is accepted. Acceptance preserves the short-circuit log-mask reads and both log formats before invoking force reinitialization. Timestamp wrap is treated using the native unsigned ordering, not signed comparison or modular elapsed-time policy.

The force entry tests only bit zero of authorization entry 4's flag byte (native offset 100 from the shared owner). If set, it calls the existing authorization dispatcher with `(4,0)`. It then calls the existing no-op provider, clears the existing 736-byte previous-state owner and invokes the coordinator with raw mode 1. The native no-op's unused incoming R0 has no semantic C parameter. No engine state, recovery size or retry policy was changed.

REA's saved lifecycle dossier includes the initializer and force-entry instruction ranges, although its merged-entry pseudocode drops some initializer branches. The time adapter's complete local instructions are retained in `build/goal-r1-health-lifecycle-c/stock-time-adapter.dis`, and its prior manual-provenance inventory status is retained. This review does not infer new global corpus coverage from that local body.
