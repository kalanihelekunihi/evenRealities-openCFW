# Offline queue merge paths in C

The HR, SpO2, HRV and activity merge functions at `0x40700`, `0x448b0`, `0x41638` and `0x3cb80` now have ordinary C providers. They reuse the existing source-owned rings/cursors, empty checks and builder resets. No queue storage is duplicated. The [REA literal read](health-offline-merge-c-rea.json) confirms the HR cursor/record pair against the locked application.

Each merge returns for null output or an empty queue, samples the clock once, then reads the scan head. It traverses the live byte count with a local wrapped index. Empty payloads are skipped; future day/timestamp entries log and are skipped rather than stopping traversal. The merge does not consume queue entries itself. On builder day/offset mismatch, it calls the existing unresolved flush provider, resets the builder and reloads entry metadata. An empty builder resets without flushing. Provider-time count/head/record changes preserve the native cached scan position and live-count behavior.

HR/SpO2 rows use an index byte plus three payload bytes; their index field is written only for a fresh slot. HRV writes an index plus three halfwords, including index refresh for existing slots. Activity unpacks a word into 12/10/10-bit halfwords, normalizes the slot flag to one and increments the count only for a previously empty slot. Builder counters retain native byte wrap, and the maximum timestamp updates only for accepted entries with a newer timestamp.

The [machine-readable receipt](health-offline-merge-c-review.json) records 612 stock/C comparisons covering empty/null cases, future filtering and equality, duplicate slots, nonzero flags, packed activity fields, byte-count wrap, ring-head wrap and counts through 255. Mixed sequences execute actual C enqueue, merge, consume and empty functions. Flush fixtures also change queue counts/head, grow or shrink traversal, mutate entry data and update reset-preserved metadata. Clock-time head mutation verifies that the head loads after the clock call. Only clock, logging and the four still-unresolved flush providers are modeled.

Eight separately compiled defects fail runtime assertions: wrong future equality, snapshotted count, missing offset boundary, wrong HRV stride, wrong activity mask, wrong maximum-timestamp comparison, duplicate activity counting and a stale head loaded before the clock.

The normal build compiles/composes 667 application and 74 bootloader units with no failures or duplicate strong symbols; `make sources-check` passes. Application imports decrease from 147 to 143 with no new imports; bootloader imports remain 34. All 739 other prior objects are identical. The changed notification-stage object has identical allocated instruction/data bytes and exactly four intended relocation-name replacements.

The tested contract uses mapped, distinct builder/queue buffers, valid queue heads and well-formed queued slot indices. Provider-time mutation is controlled replay, not physical concurrency proof. Packet encoding/transmission, flush bodies, asynchronous interrupt/scheduler behavior, physical persistence and complete firmware linkage remain unfinished or unverified. No exact source-plan selection or image-integration claim is added.
