# R1 IQS register ports in C

The existing `board/native_touch_transport.c` now also supplies IQS read port `0x2fe9c` and write port `0x2feac`. Both are bounded 16-byte stock shims that ignore the first address word and fifth option word, forwarding the complete register, buffer and length arguments to the canonical touch request providers. Those providers retain their existing field-width conversions and boolean result. The public transport header exports both signatures, and the touch dispatcher uses that declaration.

No source unit, manifest entry or state owner is added. The shared 20-byte request and touch-bus owner are reused. Register/length fields still truncate to 16 bits; null pointers, retained fields and callback mutations preserve existing provider behavior. No new interpretation of the retained command field as a wire address is claimed.

The direct probe passes 3,136 sequences of three calls each (9,408 stock/C call pairs), using actual C transport with modeled registry-entry boundaries. It covers ignored arguments, full-width inputs, null and request-alias pointers, raw lower statuses, retained requests and changing bus handles. A further 192 sequences (576 call pairs) execute actual registry dispatch with null handles and missing read/write methods. Another 264 comparisons execute the C factory/control adapters through the new port, transport, bus adapters and registry, consuming the factory zero-byte write in modeled controller callbacks.

Tests compare complete request state, ordered request/bus accesses, callback inputs, boolean results, guard memory, preserved registers and interrupt masks. Eight compiled defects are rejected, then the unmodified probes are rerun. All eight pre-existing allocated sections in the transport object are identical; four allocated sections add only the two functions and their exception metadata. REA byte receipts match the pinned artifact. The write-port frontier extent is corrected from 52 to 16 bytes so it no longer includes the following `IRQ_Context` body.

The normal build still compiles 833 units (751 application, 82 bootloader) without duplicate strong symbols. The write-port import closes, reducing application dependencies from 76 to 75 with no additions. Of 833 prior objects, 830 are unchanged; only the transport object and two generated bootloader objects differ. The manifest is unchanged and R1 validation passes (833 units, 619 sources). Repository-wide checking retains the unrelated G2 `resident_rom_thumb_set.S` manifest omission.

Controller callbacks remain modeled; physical I2C data transfer, timing, final application linking and boot are unverified. Arbitrary pointer faults and private-frame identity are outside the proof. Byte identity is not required under the current user instruction. [Review receipt](iqs-port-c-review.json); experiments are under `build/goal-r1-iqs-port-c/`.
