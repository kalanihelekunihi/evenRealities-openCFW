# R1 ST25 configuration policy and adapters in C

`st25/native_configuration.c` supplies stock initializer 0x77764, security-session adapter 0x44c9c, password adapter 0x44c90, GPO configuration 0x44ce8 and static mailbox-mode reader 0x5d1d8. It reuses the existing `r1_st25dvxxkc_register_provider`, device object and pinned ST C providers. The native mailbox bit-zero read/modify/write at 0x5d1f4 remains explicit as `r1_st25_mailbox_mode_enable_native`; it is not replaced by a no-op or by the contextual registry variant with a different API.

The normal open-toolchain build compiles 812 units (730 application, 82 bootloader). The initializer import closes and the native mailbox boundary becomes explicit, so application imports remain 72. R1 source checking and strict bootloader linking pass. Global checking retains the unrelated G2 unlisted `resident_rom_thumb_set.S` failure. This does not establish a complete running chip-configuration path until that boundary and physical integration are supplied.

The initializer's configured byte is the accessed field at stock 0x20006858 + 3, cold-zero in decoded initialized RAM. The existing active-driver pointer belongs to the separate field at +8; neither that owner nor the device object is duplicated. An already configured byte logs and returns. Otherwise registration retries up to ten times, logging each failure; exhaustion logs again and clears the flag. Success logs and publishes flag one before opening a security session. Later errors do not roll that publication back.

The policy reads static mailbox register 0x0d through address 0xae into an initialized byte. If zero, it performs the native enable operation between delay calls with argument five and reads/logs the byte again. It resets dynamic EH enable, logs reset success only on zero status, then repeats mailbox enable/read, configures GPO1 with byte 0x21 and GPO2 with low two bits cleared, logs the result and closes the security session. The final security close still runs after GPO failure. Both GPO writes retry up to ten times; failed GPO2 reads stop that adapter after logging. The mailbox byte is loaded inside each live log gate, including after callbacks have changed the escaped output buffer.

The security adapter initializes its one-byte session state, reads twice and selects password presentation from the first byte: zero/nonzero request opens with zero words; state one/zero request closes with words 0x12345678 and 0x13245678. Other session bytes do not trigger a password. The second byte value is returned regardless of provider status. GPO, password and mailbox-read adapters retain full result words; null mailbox output returns UINT32_MAX without a bus call.

The pinned C SDK has a register context at object offset 28, while stock uses 24. The source uses `r1_st25_device.Ctx`, one-byte session enums and the eight-byte/four-aligned password type, with compile-time assertions. It does not impose stock offsets on the selected SDK object. Integration prepares valid object/context/IO callbacks for each layout and initializes the source device address as the real RegisterBusIO does. Actual SDK password, security, GPO and EH-reset functions execute. Register and password packet traces match stock, including system/data addressing, the 17-byte password message, validation byte 0x09 and repeated password halves. Full BSP registration itself remains modeled.

Verification passes 1440 direct stock/C pairs, 36 escaped-byte log-mutation pairs and 16 actual ST25-provider pairs. Cases include cached initialization, registration and both GPO retry boundaries, failed/unchanged output buffers, session byte values outside 0/1, full-word errors, null mailbox outputs, log bits and short-circuit changes, masks and poisoned stacks. Actual SDK integration varies register read/write errors, mailbox state and logging; the board mailbox transfer and native mailbox RMW remain modeled.

Ten compiled defects are rejected: short registration retry, wrong configured byte, marking exhausted initialization successful, wrong closing password, wrong GPO2 mask, short GPO retries, wrong mailbox address, unconditional first enable, caching the mailbox log byte and leaving the security session open. The normal probe passes after the mutants. REA windows bind the policy, adapters, strings and password literals to the locked stock application.

The initializer uses a void C API because the existing late-setup caller discards its result. That caller's declaration is updated accordingly; its compiled object is identical. The audit preserves 809 prior object hashes, including all hardware-provider code. Generated boot objects retain allocated bytes and normalized relocations. The manifest only adds the new unit; no source qualification plan or G2 source is changed. Incidental return registers/private frames, physical timing, final application linking, the native mailbox boundary and device boot remain outside this proof.

Reproduction inputs, scripts and hashes are in [st25-configuration-c-review.json](st25-configuration-c-review.json).
