# Sleep-storage FAL binding in C

`runtime/native_sleep_storage_initialize.c` supplies the missing service-startup provider. `r1_sleep_db_fal_bind` implements stock `0x5b0f8`; `r1_native_sleep_database_initialize` implements the service thunk at `0x8dd8c`. Fresh REA raw-byte reads cover the binding, literals/log text and thunk. Raw disassembly of service startup `0x926dc` identifies the call to that thunk after activity-cache initialization. The separate health database startup at `0x70030` remains unresolved.

The binding looks up `sleep.db`, publishes its partition in word 1 of the existing `r1_sleep_sync_context_prefix`, then finds the device using `fal_partition.flash_name`. A compile-time assertion checks the native field offset of 28 bytes. It publishes the device in word 2 and writes only ready byte 0 on success, preserving the upper bytes. The original three-word context owner remains in `native_sleep_sync_status.c`; no duplicate storage is added.

Failure behavior is deliberately specific. A missing partition is stored as null before logging, without clearing prior ready/device state. A missing device is stored as null before logging; the partition is cleared only after those log callbacks finish. Ready state is not cleared on failure. Thus callback mutations and partial prior state retain stock ordering rather than a generic reset policy. Ring and SDK messages, short-circuit live mode queries and metadata `0x001c0001` match the reference, including the original “log flash” text for a missing sleep device.

Both binding and service entries pass 4,320 paired stock/C cases (8,640 executions): 1,440 missing-partition cases, 960 missing-device cases and 1,920 successful bindings. Fixtures vary both lookup results, prior flags/pointers, changing log modes, callback mutations of all context fields and interrupt masks. Checks compare provider arguments/order, context snapshots at every callback, final context/guards, callee-saved registers and SP/masks. The C route links the actual existing context owner; FAL lookups and log providers are modeled. It rejects unintended stock instruction execution.

Four compiled defects fail runtime assertions: wrong flash-name field, clearing ready on entry, clearing the partition before failure logging and omitting device publication. Probe sources and the positive subset ELF are under ignored `build/goal-r1-sleep-storage-init-c/`. [Machine-readable evidence](sleep-storage-init-c-review.json) records raw REA bytes, build/harness hashes, results, defects and audit.

`build/sources-goal-r1-sleep-storage-init-c/report.json` compiles all 732 R1 units and composes both payloads without failures or duplicate strong symbols. The service import resolves, reducing application imports from 157 to 156; bootloader imports remain 34. All 731 prior object hashes are unchanged. `make sources-check` passes. This closes the binding dependency, not the full sleep database/storage subsystem. Actual FAL initialization, flash I/O/persistence, complete service startup, asynchronous concurrency, physical hardware and a complete source firmware link remain unverified. The optional exact source plan is unchanged; no byte identity is claimed.
