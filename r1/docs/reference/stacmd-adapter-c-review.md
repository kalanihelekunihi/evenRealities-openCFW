# Direct C STACMD receive adapter

The read-bit copy adapter at stock entry `0x969ec` is now a direct C body in `r1/src/application/board/native_stacmd_receive.c`. The ten-byte naked bridge and private `stacmd_read_adapter_body` are removed. Three empty compiler constraints retain raw register behavior; they emit no instructions. Fixed register declarations remain, so this is compiler-specific C, not portable ISO C. The actual bit reader's four-NOP timing block is unchanged.

REA read the complete sixteen-byte stock adapter. Raw Thumb decoding shows a push of R3/R4/R5/LR, retention of the destination in R4, a call to the bit reader with the saved R3 word at caller SP minus 16, a copy through R1 and a pop restoring the sampled word into R3. The direct C union provides an eight-byte local extent; recorded Clang and GCC9 each use eight further saved bytes, retaining the sample address and sixteen-byte reader-provider depth. Their private save slots differ.

The sample word starts with incoming R3 so zero/one/two-byte provider writes preserve its remaining bytes. C captures R2 after the reader call, copies the word to the destination, returns that copied value through R1 and reloads the sample word into R3 after the copy. The final reload matters when an unaligned destination overlaps the sample word: the copy can change the value stock pops into R3.

Both recorded Clang and GCC9 pass **2,304 paired cases / 4,608 executions each**: 2,048 modeled-reader cases and 256 cases executing the actual stock/C bit reader with GPIO models. Checks compare R0/R1/R2/R3/R12, sampled-word address and provider depth, shared state, final callee-saved registers and interrupt masks. Cases cover status words, partial writes, full-width incoming seeds, ordinary unaligned destinations and partial destination/sample-word overlaps. Actual-reader cases also compare GPIO sequence, live pin/callback replacement, both timeout phases and 104 delay NOPs.

The full protocol fixture passes **219 paired cases per compiler**, using actual read/write frames, transmit, receive, recovery and delay source units with probe C GPIO callbacks. The GCC run replaces the receive unit; other units retain their normal Clang objects. Cases cover zero-to-three-byte transfers, byte patterns, command rejection, header/data parity mismatch and both timeout phases. Checks include raw status, GPIO operations and samples, NOP counts, output guards, callback RAM, saved registers and masks.

Negative controls reject a zero seed, returning the stale pre-copy value through R3, the wrong sample address, and the old bridge/private-worker provider depth. The actual bit-reader bytes and relocations, and all 575 other source objects, are unchanged. All 576 R1 units compile and compose; imports remain 164 application / 34 bootloader, with no new failures or duplicate strong symbols.

Active provider saved registers, private save slots, aliases into saved registers, raw APSR/return-address bits, arbitrary faults and exceptions are excluded. GPIO callback depth is recorded rather than required equal: stock reaches SP minus 48 and normal Clang C reaches SP minus 40. Equal protocol results and NOP counts do not establish equal cycles, electrical timing or physical-device operation.

Four generic and four GCC9 qualification profiles compile with their normal flags, but select no exact regions. The manifest and source plan are unchanged. The canonical hybrid still matches locked application SHA-256 `0e788d433ea50fd36edb8f21a9c18b6062211e4a36dbc5bd7695ea5827f3aa1a`, with 3,961 source-built bytes (including assembly and data), 642,199 fallback bytes and 248 resource bytes. Source completeness remains false.
