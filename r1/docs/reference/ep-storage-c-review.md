# R1 EP storage read/write/erase wrappers in C

`native_ep_storage.c` implements stock read `0x5e404`, write `0x5e4d8` and single-sector erase `0x5e1fc`. The shared header reuses the already checked FAL partition/flash views from `native_log_bin.h`: partition base at offset 52 and read/write/erase callbacks at offsets 40/44/48. The existing ring flush now includes this typed interface; its compiled object remains identical.

Read and write preserve native admission: bitwise AND of the 32-bit negated ready byte and the data-pointer word must be nonzero, length must be nonzero, and unsigned offset-plus-length must be at most 8192. The bitwise expression is preserved for noncanonical ready bytes. Out-of-range requests retain exact logging strings, IDs, arguments and short-circuit mode reads. Admitted requests add the partition base, invoke the flash callback, then return 1 regardless of callback status. Rejected requests return 0. Erase accepts a nonzero ready byte and sector below 2, calls the erase callback for 4096 bytes at base plus sector times 4096, and likewise returns 1 independently of callback status.

Three narrow RW owners cover ready byte `0x20006948`, partition pointer `0x2000694c` and flash pointer `0x20006950`. Actual stock startup execution, independent RW decoding and compiled-object comparison confirm zero initial contents. No adjacent bytes or existing export/ring owners are claimed. See [startup proof](ep-storage-initialization.json).

The wrappers, actual ring flush/sector preparation, existing export guard/poll/force paths and actual event adapter pass 7,505 stock/C comparisons. Cases cover ready-byte values, pointer-bit admission, zero/exact/beyond-boundary lengths, unsigned arithmetic wraparound, sector limits, logging arguments, callback outcomes and the prior flush/guard matrices. Accepted raw unusual-pointer or large-length calls are recorded by the callback model without dereferencing them; this proves dispatch behavior rather than pointer validity or successful transfers. Comparisons include public wrapper returns, callback order/arguments, record and bounded buffer bytes, guarded shared state, preserved registers, stack pointer and interrupt masks. Reconstructed execution may not enter stock instruction addresses. Private scratch, caller-clobbered registers and void returns are excluded.

Eight compiled defects are rejected: normalized pointer admission, wrong read boundary, wrong address base, propagated read failure, propagated write failure, wrong erase bound, wrong erase length and wrong logging ID. The full normal implementation was rerun afterward.

REA returned all three complete instruction spans and each matches the official raw application. See [read evidence](ep-read-c-rea.json), [write evidence](ep-write-c-rea.json), [erase evidence](ep-erase-c-rea.json) and [structured verification](ep-storage-c-review.json).

All 768 R1 units compile and both payloads compose without duplicate strong symbols. All 767 prior objects remain identical. The three storage imports close with no new imports, reducing application imports from 129 to 126; bootloader imports remain 34. R1 source coverage passes. Global coverage still reports the existing G2 `resident_rom_thumb_set.S` manifest omission.

Indirect hardware flash callbacks, plan initialization, critical sections, queue/semaphore operations, clock, persistence and logging remain modeled boundaries. Physical flash transfers, pointer validity, real semaphore contention, asynchronous IRQ/concurrency, complete image linking and device operation remain unverified. Byte identity is not required for this build route.
