# Native algorithm shutdown controller in C

The [machine-readable receipt](goodix-algorithm-shutdown-c-review.json) pins the source, stock REA bytes, normal build and fixtures. `native_algorithm_shutdown.c` implements `GH3X2X_AlgoDeinit` at `0x29f9c` using typed C providers for every nonzero deinit slot. It reuses the existing frame owner and adds 24 bytes of canonical started/init state, exposed in `native_algorithm_state.h` for future initialization/calculation to share.

An initially null frame owner returns zero without changing the bitmap or flags. Otherwise the controller clears all requested started bits before visiting twenty slots in ascending order. For every selected slot it reloads the frame owner and reads the selected frame word before reading the init byte. An initialized nonnull callback is invoked with that frame. A successful callback is followed by clearing its init byte. The first nonzero signed-byte result stops the walk and is returned without clearing the failed flag. Null callback slots leave their flags unchanged. Callback changes to frame owners, frame entries, flags and the started bitmap remain visible.

The stock callback table starts at `0x9d404`; `0x9d40c` is the first row's deinit column. Its nonzero deinit slots are0,1,2,6,9,15. C stores only that deinit projection, binding the admitted ADT, HR, HRV, SpO2 and shared soft-ADT callbacks. No executable stock address is retained.

Direct verification passes 16,384 request/init-mask cases, 3,072 signed-byte failure cases, 148 live callback mutations, eight initial-null-owner cases and twelve null-frame forwarding cases. Exact read/write order, callback arguments, call-time state, bitmap/flag updates and returned status match. All 96 native controller instruction bytes execute. A callback-induced late null owner reads address4 before the next zero init flag; the two emulator cases establish that access shape, not a physical MCU fault.

A further 512 comparisons execute the controller, all five distinct public callbacks and their descendants with the C allocator across all64 callable-init masks. Another sixteen execute the real `GH3X2X_AlgoMemConfig` caller through the controller and memory initializer. Full RAM and heap writes match outside the private stack region. Source execution cannot enter stock code. The dual-soft-slot fixture uses a null saved allocation to avoid assuming a valid double release of shared live memory. Unrequested initialized algorithms retain their flags and allocations. Seventeen compiled behavioral defects are rejected.

Saved integer/FP registers, SP, masks, FPSCR and caller guards are checked; caller scratch, APSR and private frames are excluded. Integration primes an active FP context, inheriting the reset proof's cold-FPU limitation. Native initialization/calculation, concurrency and physical behavior remain open.

The fresh serial R1 build compiles 877 units (795 application,82 bootloader), with no duplicate strong symbols. `GH3X2X_AlgoDeinit` is removed from the application import set, reducing it from62 to61; bootloader imports remain22. The tested object equals its normal object and all866 prior nongenerated objects remain identical. Two existing generated objects differ with build directory paths. The manifest adds one unit; source plan and the existing cache linker layout remain unchanged. Import records and consumers are refreshed against the new report.

This closes the locked deinit graph in C. It does not establish native initialization/calculation, physical sensors, final executable linking/startup or boot. Relocatable composition is not bootable firmware.
