# R1 configuration-stop sensor-query order

`r1/src/application/goodix/native_config_stop.h` replaces the configuration-stop body in the existing generated Goodix hook unit. It retains the trigger and slot-time calls, then explicitly reads temperature, capacitance and gsensor enable flags before tail-calling `GH3X2X_AlgoSensorEnable(gsensor, capacitance, temperature)`. The pinned upstream file remains unchanged and the replacement contains no inline assembly.

Stock `0x6a4b2..0x6a4d7` calls the getters in that order. Clang previously evaluated the vendor template's argument expressions in gsensor/capacitance/temperature order. C does not specify function-argument evaluation order; separate full expressions now express the observed sequence consistently across compilers. The old compiled template is rejected by the ordered provider fixture. The native capacitance and temperature getters currently return zero, so this is a sequencing correction, not evidence of an observed physical sensor malfunction.

REA reads the complete 38-byte span and individually decodes the three getter calls and final tail branch. Their destinations match the raw locked bytes and explicit native execution. REA has no analyzed procedure at this entry; no whole-procedure or global coverage credit is claimed. Executing the native registration fragment confirms hook position 7 points here.

Validation against the normal source build:

- Clang and GCC9 each pass 256 paired stock/C cases checking provider order, alternate valid-byte getter returns, provider mutations, final arguments, 16-byte provider depth and restored-frame algorithm tail call. The providers are modeled; alternate capacitance/temperature returns test the call contract rather than the current stock getter implementation.
- Each compiler also passes 1,024 paired cases executing the actual driver getters and existing C algorithm sensor-enable setter. These cover every gsensor byte, trigger/slot-time mutations, ordered gsensor reads, ordered three-byte algorithm-state writes and final state. Only trigger and slot-time providers are modeled in this fixture; source globals are placed at recovered addresses under its controlled linker script.
- Integration exposed an existing void-return difference: native sensor-enable leaves R0 as the gsensor argument, while its C setter leaves the last output address. That register is explicitly excluded from the integration comparison. Provider active saved-register values, save-slot contents and flags are also outside this bounded contract; callee-saved restoration and interrupt masks are checked. No full machine-state or byte-equivalence claim follows.
- All 576 R1 units compile and both relocatable compositions succeed without failures or duplicate strong symbols. Imports remain 165 application and 34 bootloader. All 575 other objects and the other 16 hook functions are unchanged. `make sources-check` and `git diff --check` pass.

Four Clang and four GCC9 qualification candidates compile. They rediscover only the four already-admitted empty hooks; configuration-stop is not selected. The exact source plan is unchanged.
