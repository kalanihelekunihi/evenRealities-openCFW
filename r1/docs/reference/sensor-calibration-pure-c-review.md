# Motion and temperature calibration with C record storage

The calibration readers in `runtime/native_temperature.c` and `native_motion_stream.c` now allocate aligned 124-byte C records and call their existing extraction bodies. Their naked push/reserve/pop bridges are removed. Fresh REA analysis confirms stock motion `0x7b9c8` and temperature `0x7badc`: read the shared cached class, store a word followed by a halfword and return the zero-extended halfword. Temperature extracts bytes 62–67; motion extracts bytes 68–73. No new record owner, provider or executable blob is introduced.

The shared `nv_r1` class owner declares a 124-byte payload. These C wrappers require that valid class and a fully populated cached read. They retain ignored read status under that precondition. Stock reads prior stack contents when the cached read fails or writes nothing; those private-frame values and aliases are not reconstructed here. An invalid class can leave the new automatic record uninitialized. This migration therefore does not establish safe handling of corrupt metadata, partial reads or arbitrary failures, and does not invent a fallback calibration. Such failure handling remains unfinished.

All 4,096 paired stock/C comparisons pass (2,048 per reader, 8,192 executions). The C route executes actual `r1_kv_class_read` and pinned musl `memcpy`; only port critical callbacks are modeled. Cases vary patterned records, before/after-copy payload mutations, post-read live-handle changes, aligned/unaligned outputs and outputs overlapping cached payloads or the handle cell. An independent record-slice check validates all six output bytes and the returned halfword. Complete cached storage, output guards, handle-cell effects, preserved R4-R11, SP and masks also agree.

The probe observes word/halfword stores at decoded instruction sites and compares final memory separately. This avoids Unicorn memory-hook IT-state artifacts observed in the initial instrumented memcpy run; no production code change was made for that emulator issue. Both extraction bodies retain their prior instruction bytes and relocations, anchoring the observed store sites. Four compiled defects fail runtime assertions: wrong temperature field, wrong motion tail, wrong packed tail destination and wrong record size.

Only the two entry wrappers' instruction sections change. All other instructions, named relocations and data sections in both modules are unchanged, including temperature channel adapters and extraction bodies. The other 729 R1 object hashes and export/import sets are unchanged. `build/sources-goal-r1-sensor-calibration-pure-c/report.json` compiles all 731 units and composes both payloads without failures or duplicate strong symbols. Application imports remain 157 and bootloader imports 34. `make sources-check` passes. The optional exact source plan is unchanged.

[Machine-readable evidence](sensor-calibration-pure-c-review.json) records REA observations, build/harness hashes, results, defects and audit. Probes and positive subset ELF live under ignored `build/goal-r1-sensor-calibration-pure-c/`. Flash persistence, full calibration consumer execution, physical sensors/timing, interrupt interleavings and a complete firmware link remain unverified. This is a bounded C ABI migration, not a byte-identity claim.
