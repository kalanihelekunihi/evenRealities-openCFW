# Battery voltage and reports with the ordinary C ABI

`board/native_battery_voltage.c` no longer emits the stock NOP prefix before the runtime service call. `native_battery_frame.c` and `native_battery_protocol.c` no longer restore packet or logging words into caller-clobbered R1-R3 with inline assembly. All three units retain their existing interfaces and storage owners; no manifest unit is added. No executable blob or opcode array is introduced.

Fresh REA evidence confirms the NOP fallthrough at `0x31fcc`, voltage getter at `0x91290`, glasses packet at `0x913fc` and protocol packet at `0x8345c`. REA decompiles beyond the four-byte NOP function body into the runtime update, so the wrapper proof uses decoded fallthrough and an explicit modeled boundary at `0x31fd0`; it does not claim to validate that complete runtime.

The voltage getter refreshes only for configuration value `0x55` and reads the voltage afterward. The glasses frame remains a zeroed 12-byte record headed by `00 09 8b 00`, followed by low-byte level/state, with six bytes sent. An initial handle other than `0xffff` triggers a second live handle read before dispatch. The phone packet remains eight zero-initialized bytes with low-byte level and wire state 1 for nonzero charge input, 2 otherwise. Logging uses the full input level, retains short-circuit mode reads and dispatches with arguments 1 and 0. Scratch-register values and exact provider frame layouts are outside the ordinary C contract.

The normal compiled objects pass 1,431 paired stock/C cases: 162 voltage getters, nine service calls, 504 glasses frames and 756 protocol reports. Cases cover configuration boundaries, refreshed voltage, full-width level/state inputs, disconnected and changing handles, live mode sequences and provider return values. Checks compare return results, complete packet storage visible at dispatch, callback order and log arguments, device storage, preserved R4-R11, stack restoration/alignment and interrupt masks. Providers clobber caller-saved registers.

Four compiled defects fail runtime assertions: wrong refresh gate, stale second handle, reversed wire states and wrong glasses payload length. Probes and the positive subset ELF live in ignored `build/goal-r1-battery-report-pure-c/`. The [machine-readable receipt](battery-report-pure-c-review.json) includes fresh REA observations, build hashes, test digest and defect diagnostics.

`build/sources-goal-r1-battery-report-pure-c/report.json` compiles all 729 R1 units and composes both payloads without failures or duplicate strong symbols. Only the three intended object hashes change; 726 objects, strong exports and imports are unchanged. Application imports remain 167 and bootloader imports 34. `make sources-check` passes. Configuration, runtime-update, handle, logging and dispatch providers are modeled. Radio transmission, physical sampling/timing, complete runtime execution and a complete firmware link remain unverified.
