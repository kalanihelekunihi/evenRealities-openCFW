# nv_r1 configuration accessors in C

`runtime/native_device_configuration.c` supplies four previously unresolved factory/sensor configuration dependencies: the byte getter at stock `0x7b9ec`, word getter at `0x7ba08`, byte setter at `0x7c8e4` and word setter at `0x7c910`. Fresh REA disassembly/pseudocode confirms a 124-byte cached-class read, byte offset `0x78` and word offset `0x74`. Setters modify only their field, reload the live handle for the cached write, and call the existing `r1_nv_modules_idle_check` afterward. They ignore cached-operation and idle-check statuses as stock does. The byte setter truncates to eight bits; the word setter preserves the full 32-bit input.

The accessors share `r1_device_info_kv_handle`, whose existing `native_protocol_serial.c` owner declares the `nv_r1` class with payload size 124. No second storage owner, private register ABI, stack-frame bridge, assembly or executable blob is introduced. This module assumes that the handle refers to a valid fully populated 124-byte class. A size-mismatched cached read returns without filling the automatic record; stock likewise ignores the failure and reads previous stack contents. That invalid/partial-read behavior is not reconstructed or validated here, and no default record is invented. These providers do not establish a safe failure policy for corrupted class metadata.

All 2,304 scenarios agree across stock, direct C and the actual C cached-class/memory chain (6,912 executions). Each accessor has 576 scenarios, varying full-width inputs, patterned records, live-handle changes between read and write, post-read payload mutations and idle-check return values. Tests compare meaningful getter results, complete read/write/idle callback order and arguments, all class bytes/flags, the live handle, preserved R4-R11, SP and interrupt masks. Setter R0 and incidental scratch registers are outside their void C ABI. Read/write callbacks fully populate valid records; failed or partial reads are excluded.

The integrated subset executes existing `r1_kv_class_read`, `r1_kv_class_write` and pinned musl `memcpy` as C. Only the port critical callbacks and post-write idle checker are modeled. Four compiled defects fail runtime assertions: wrong getter byte offset, narrowing the word store, omitting the idle check and retaining a stale write handle. Probe sources and positive subset ELFs live under ignored `build/goal-r1-device-config-c/`.

`build/sources-goal-r1-device-config-c/report.json` compiles all 731 R1 units and composes both payloads without failures or duplicate strong symbols. The four imports resolve, reducing application imports from 161 to 157; bootloader imports remain 34. All 730 prior object hashes are unchanged. `make sources-check` passes. The four stock entries' source frontier and ownership evidence now point to this bounded provider rather than an unresolved source route.

[Machine-readable evidence](device-config-c-review.json) records REA observations, build hashes, test digest, defects and audit. Cached dirty writes are not flash persistence. Flash synchronization, complete factory/sensor execution, fault/concurrency behavior, physical hardware and a complete firmware link remain unverified.
