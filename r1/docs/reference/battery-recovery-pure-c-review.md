# Stuck-charge recovery with the ordinary C ABI

`board/native_battery_recovery.c` now implements stock `0x3db70` without fixed registers, empty inline assembly or stack-address helpers. The public interface remains void with state and timestamp arguments. The actual C caller in `native_battery_runtime.c` passes runtime storage at offset 36. Incoming scratch R1-R3 values, private logging stack aliases and a fixed provider frame are no longer part of this C contract.

Fresh REA analysis confirms the recovery sequence and native state offsets. Recovery retains the 64-bit frequency-times-120 threshold, wrapping elapsed subtraction, level/history sentinel handling, recovered flag, minimum voltages, 35 mV rise, initial-curve estimate, upper clamp of 100, timestamp publication and separate live log-mode reads. The reference is captured before callbacks can change it; device/runtime accesses remain volatile. No executable blob or instruction array is added.

The normal product object passes 3,968 paired stock/C cases (7,936 executions). Tests compare callback order and arguments, callback-visible state, complete runtime/device storage, timestamps, preserved R4-R11, SP and interrupt masks. They cover the separate timestamp and actual runtime+36 location, timer wrap, large/zero frequency, voltage/state branches, estimates, live mode sequences and eight modeled callback mutation modes. Providers clobber caller-saved registers. Callbacks must see an aligned stack, but its exact size is compiler-controlled. The distinct adjacent YHM guard remains untouched.

Four compiled defects are rejected by runtime assertions: narrowing the threshold multiplication, removing the percentage clamp, losing the recovered flag and reloading the logged reference after callbacks. Probe sources and positive subset ELF are under ignored `build/goal-r1-recovery-pure-c/`. [Machine-readable evidence](battery-recovery-pure-c-review.json) records REA observations, build hashes, results and defect diagnostics.

`build/sources-goal-r1-recovery-pure-c/report.json` compiles all 729 R1 units and composes both payloads without failures or duplicate strong symbols. The other 728 objects, strong export set and imports are unchanged (167 application / 34 bootloader). `make sources-check` passes. Timer, reset, curve and logging providers are modeled; physical charging, timing, faults/concurrency and a complete firmware link remain unverified. Historical native-frame evidence in the [earlier review](battery-recovery-root-c-review.md) describes a superseded ABI contract.
