# R1 native graph initialization in C

The [graph-family review](goodix-graph-families-c-review.md) supplies both family builders and three additional helpers as C. Full HR lifecycles now execute both builders and prove exact mode0/1 resource extents. Mode6 construction and executor implementations remain open.

The initializer at `0x340a0` now uses C in `r1/src/application/goodix/native_graph_initialize.c`, reusing the existing recurrent/dense descriptor builders and executor getters. The [receipt](goodix-graph-initialize-c-review.json) pins REA evidence, startup decoding, sources, objects and fixtures.

The initializer reads the context header twice, preserves the first value across callbacks and chooses the graph family from the second read. It builds the fixed 8-by-4 recurrent record, vector identity, two per-mode recurrent records and two dense records in native order. Mode 2 stores and returns the softmax identity; modes 0/1 return context plus `0x238`. The constructor now includes a shared unsigned-return declaration, leaving its compiled object unchanged.

The 24-byte dimension schema matches initialized RAM at `0x20007d98`. Running the locked stock RW decompressor agrees with an independent decoder and with the canonical compiled schema. Region guards remain intact. REA's flash-only session could not read that RAM directly; its incomplete read is preserved in the evidence. The literal search finds `0x3418c`, which does not establish absence of indirect references or runtime writers.

All 339 stock/C comparisons pass with independent complete record, cursor, allocation, zero-state and return oracles. Every one of the 236 native instruction bytes executes. Existing C descriptors, getters and memory primitives execute; only the two family builders and malloc are modeled. Cases cover every mode, allocation failures, null/extreme cursors and weights, active floating-point state and callback changes to the context header. Sixteen compiled defects are rejected.

All 128 full HR constructor/real-allocator/complete-teardown lifecycles pass with the initializer and its recurrent-state allocations executing in C. Six state buffers are allocated across the mode 0/1 records. All primary, workspace, filter, graph, queue and state allocations coalesce to the prior heap top. Family builders remain modeled as empty initialized graph records returning their input cursor; the mode 6 record is preallocated through each real allocator and transferred by its modeled provider. Missing family internal allocations and inference are not covered.

The 889-unit build passes without duplicate strong symbols. Tested initializer and constructor objects match the normal build. All 878 prior nongenerated object hashes are unchanged; 877 prior source/object pairs are unchanged and one constructor declaration now uses the shared header. No writable state or resource definition is added. Application imports rise from 74 to 75 as the initializer import is replaced by two family builders; boot imports remain 22. Source-plan and cache layout are unchanged.

Proof uses the authenticated startup schema and modes 0/1/2. Runtime schema mutation, invalid pointers, concurrency, cold floating-point activation, physical fault delivery, caller scratch and private frames remain unproven. Resource pointers are normalized only for comparisons/provider traces; actual memory is not rewritten. The family builders (`0x2874c`, `0x2966c`), mode 6 construction, numerical inference, final executable linking/startup and hardware boot remain open. This is an `ld -r` composition, not a bootable firmware image; byte identity is waived for this goal.
