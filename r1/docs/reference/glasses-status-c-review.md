# R1 glasses wear/display hardware policy in C

`board/native_glasses_status.c` implements four stock routines: the deferred DC/DC callback (`0x6a668`, 64 code bytes), deferred touch-close callback (`0x6a988`, 136), glasses-status command (`0x6a714`, 348) and fast-mode scheduling helper (`0x4e070`, 118). REA readbacks match the authenticated application. The source adds no mutable state or assembly.

The deferred DC/DC callback logs then calls the pinned S140 `sd_power_dcdc_mode_set(1)` API through SVC `0x3f`. The deferred touch callback closes source 0 only when the wear byte was zero before diagnostics. Its skip diagnostics reload that byte as signed, preserving the stock handling of values such as `0xff`.

The status command captures wear/display bits 7/6 from byte 4 when subcommand byte 3 is 1, then acknowledges by writing byte 4 to 1. Wear changes update offset 3 of the existing factory state. Wearing opens touch; with the stored configuration bit clear, it cancels deferred DC/DC enablement and immediately disables DC/DC. Removal schedules touch close at `0x96000`; with that bit clear, it schedules DC/DC enablement at `0x7800`. Both paths cancel the exact callback identities first. Display changes update factory offset 4 and use the live glasses handle for fast or slow mode. Other subcommands send the original record unchanged.

Fast mode clears the existing observer flag at native `0x200064bf`, cancels delayed parameter events for `(handle << 16) + 0/1/2` in order and immediately schedules event 2. The original seven-byte status buffer is returned through the existing bounded-reply helper, including its invalid-handle guard and low-byte transport result.

Cases cover all 256 wear-byte values, all 256 status-byte values and subcommands, configuration settings, display/wear transitions, touch client ownership, logging branches, live backend mutations and deferred/reset lifecycles.
