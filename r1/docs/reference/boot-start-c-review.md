# License-free C startup for the R1 Nordic bootloader

`r1/src/bootloader/runtime/start.c` supplies the `_start` runtime entry required by the pinned Nordic GCC `Reset_Handler`. That handler copies initialized data through the BSS boundary, invokes `SystemInit` and calls `_start`. Its optional assembly BSS-clearing block is disabled in the current compiled object. The new C entry clears the aligned linker-provided BSS word range, calls the existing bootloader `main`, then remains in a terminal loop if main unexpectedly returns.

No initialized data is cleared, and the C runtime does not change interrupt masks or re-run SystemInit. The current bootloader objects have no preinit/init/fini arrays or TLS sections; the probe audits every bootloader object for their absence. Constructor or TLS handling is not silently assumed or claimed for future extensions. The SDK reset and bootloader main objects are unchanged.

Verification executes 640 handoffs across twenty combinations of data and BSS lengths, both through `_start` directly and through the actual SDK reset-handler assembly. It compares initialized data, cleared BSS, surrounding guards, source-flash preservation, SystemInit/main ordering, stack alignment and interrupt masks. SystemInit can update initialized data, dirty BSS or change PRIMASK; main must observe the correct result after C startup. A modeled main return must reach the terminal loop inside `_start` rather than falling through into unrelated code.

Six compiled defects are rejected: leaving BSS uncleared, clearing initialized data, skipping the final BSS word, overrunning BSS, using the wrong word stride and failing to call main. The full normal probe was rerun afterward. SystemInit and main are modeled boundaries, while the pinned SDK reset handler and new C runtime execute their actual instructions.

All 777 R1 units compile: 696 application and 81 bootloader. Both payloads compose without duplicate strong symbols. All 776 prior object hashes are identical. Application imports remain 124. Bootloader imports remain 27: `_start` closes and `__bss_end__` becomes explicit linker metadata. R1 source coverage passes (575 source files, none unaccounted). Global coverage retains the existing G2 `resident_rom_thumb_set.S` manifest omission.

See the [structured verification and source/object hashes](boot-start-c-review.json). This is a custom source runtime satisfying the pinned SDK startup contract; it does not establish stock bootloader instruction identity. The test uses aligned, non-overlapping toy linker layouts, not a qualified production image layout. Physical reset, actual SystemInit/main execution, DFU/cryptographic verification and device boot remain unverified. Byte identity and a paid compiler are not required for this route.
