# FreeRTOS periodic delay in C

`xTaskDelayUntil` now uses the pinned FreeRTOS `tasks.c` body in the existing `rtos/task-wait/task-wait.c` owner. It suspends scheduler changes, snapshots the tick count, applies tick/wake wrap rules, advances the caller's periodic anchor even when no delay is necessary, and shares the existing delayed-list helper. It resumes scheduling and requests PendSV only when resume has not already yielded. The delay passes `pdFALSE` for indefinite blocking, so a full-width period remains a finite timed wait.

The normal compiled API and actual pinned C list routines pass 1,800 ARM-emulated cases: 504 current delayed-list insertions, 252 overflow-list insertions and 1,044 no-delay cases. An independent unwrapped-time calculation checks the delay decision. Coverage includes zero/high/end-of-range ticks and anchors, boundary and full-width positive increments, occupied/empty timed lists, an additional ready task, and zero/positive/negative resume results. Scheduler callbacks clobber caller-saved registers. The suspend mock changes the tick before the snapshot; resume changes it after insertion, testing the intended snapshot boundary.

Checks require updated previous-wake storage before resume, correct list ownership/order, next-unblock updates, no indefinite suspended-list insertion, suspend/resume order and direct PendSV writes. They also check preserved R4-R11, stack restoration/alignment and interrupt masks. Four compiled defects are rejected: missing anchor update, passing an absolute wake tick as block time, permitting indefinite suspension and incorrect yield selection. Valid pointer storage, a positive increment and an initially unsuspended scheduler are preconditions, as in upstream.

`build/sources-goal-r1-delay-until-c/report.json` compiles all 730 R1 units and composes both payloads without failures or duplicate strong symbols. The CMSIS delay-until import resolves, reducing application imports from 164 to 163; bootloader imports remain 34. The original source prefix and all pre-existing task-wait instruction sections and named relocations remain unchanged; the other 729 object hashes are unchanged. `make sources-check` passes.

[Machine-readable evidence](delay-until-c-review.json) records pinned provenance, build hashes, results, defect diagnostics and the audit. Probes and the positive subset ELF are under ignored `build/goal-r1-delay-until-c/`. Scheduler suspend/resume callbacks are modeled; the real list implementation and delayed-list helper execute as C. No mapped stock API identity, full scheduler behavior, physical sampling cadence or complete firmware link is claimed.
