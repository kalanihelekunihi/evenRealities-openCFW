# FreeRTOS task suspension in C

`vTaskSuspend` now uses the pinned FreeRTOS `tasks.c` body in the existing `rtos/notification-tasks/notification-tasks.c` owner. Its established 112-byte native TCB contract includes the single notification state at offset 108, and its existing next-unblock reset helper is reused. The configured nonoptimized ready-priority reset is empty, as in the pinned kernel. No second TCB, scheduler or list owner is added.

The API resolves null handles to the current task, removes state-list and any event-list membership, inserts into the shared suspended list and clears only a waiting notification state. It preserves received/other notification states and the notification value. While scheduling runs, it recomputes the next timed unblock and yields when suspending the current task. Before scheduler startup, suspending the current task either clears the current pointer when the configured task count equals the suspended count or calls the context-switch provider.

The normal compiled API, actual pinned C list routines and existing reset helper pass 1,728 ARM-emulated cases. Coverage includes ready/delayed/already-suspended state membership, absent/pending/other event-list membership, four notification states, running/stopped scheduler, current/null/other handles, occupied lists, another delayed task and both startup task-count branches. Results include 576 current-task yields, 288 startup context-switch calls, 288 current-pointer clears and 576 other-task paths. The context-switch and critical-section providers are modeled; the suite checks the selected call path rather than the switch algorithm.

Checks cover list topology and ownership, event unlink, notification-tail/value preservation, next-unblock reset, current-pointer policy, critical callback order, direct PendSV writes outside the critical section, stack alignment/restoration, preserved R4-R11 and interrupt masks. Callbacks clobber caller-saved registers. Four compiled defects fail runtime assertions: losing notification clear, losing event unlink, omitting next-unblock reset and retaining the bootstrap current pointer. Fixtures represent valid list links and native field layouts; they do not establish a complete scheduler population or interrupt interleavings.

`build/sources-goal-r1-task-suspend-c/report.json` compiles all 730 R1 units and composes both payloads without failures or duplicate strong symbols. The CMSIS suspend import resolves, reducing application imports from 162 to 161; bootloader imports remain 34. The original source prefix and all pre-existing notification-module instruction sections and named relocations remain unchanged. The other 729 object hashes are unchanged. `make sources-check` passes.

Probes and the positive subset ELF are under ignored `build/goal-r1-task-suspend-c/`. No mapped stock API identity, full scheduler execution, physical hardware wake/sampling behavior or complete firmware link is claimed.
