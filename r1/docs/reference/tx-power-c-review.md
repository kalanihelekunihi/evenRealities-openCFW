# R1 BLE transmit-power policy in C

`r1/src/application/board/native_ble_tx_power.c` implements the stock `0x4e150` policy and `0x41800` advertising-address availability probe. It reuses the existing connection fields and typed advertising context. The product policy has no inline assembly; the pinned Nordic S140 headers supply the supervisor-call gateway required to reach the radio controller.

A nonzero full-width argument enables the normal power plan: phone 0 dBm, glasses +6 dBm, advertising 0 dBm. Zero selects −8 dBm for all three. Connections must have a valid handle and SDK status 2. Advertising is eligible only when its address query succeeds. Handles are reloaded after external calls, and controller errors are logged while subsequent targets continue. The advertising context base `0x20007e64` is corroborated by observer record `0xc4578`; the existing type contract places `adv_handle` at byte 84.

The direct differential probe passes 1,728 policy combinations, 256 seeded cases and 16 address-query cases. A second pass repeats those 2,000 cases with the actual C error logger. A deeper integration executes actual SDK connection-state and atomic-flag reads with the C logger: 300 state cases, 12 policy cases, 16 seeded cases and 16 address cases pass. Tests check service arguments, signed power, call/read order, zeroed address output, error continuation, live handle mutations, stack guards, callee-saved registers and interrupt masks. Prepared SDK flag words are test fixtures, not evidence that physical BLE events populate them. Eight compiled defects are rejected, followed by an unmodified-source rerun. REA byte receipts match the pinned firmware image.

The normal source build compiles all 826 units (744 application, 82 bootloader), with no duplicate strong symbols. The application import count falls from 77 to 76 without adding imports. All 823 prior non-generated objects are identical; only two generated bootloader objects differ. R1 source validation passes for 826 units and 612 sources. Repository-wide `make sources-check` still reports the unrelated G2 `resident_rom_thumb_set.S` manifest omission.

The controller services are modeled in these probes; physical RF power, timing, final application linking and device boot are unverified. Byte identity and a paid compiler are not required by the current user instruction. Details and evidence hashes are in [the review receipt](tx-power-c-review.json); probe programs are under `build/goal-r1-tx-power-c/`.
