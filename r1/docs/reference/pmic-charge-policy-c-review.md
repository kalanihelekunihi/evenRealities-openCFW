# R1 PMIC charge-event policy and timer flag adapter in C

`runtime/native_pmic_charge_policy.c` supplies charge policy `0x96ad0` and delayed notification `0x42d28`. It reuses the existing late-setup flag, thread flag wrapper, IRQ adapters, battery/sensor readers and transport providers. It adds only the accessed four-byte charger-setting cache at stock `0x20006874`, cold zero in authenticated decoded initialized RAM. This is adjacent to, and does not duplicate, the existing flag/cursor/suppression owners at `0x20006870..73`.

The policy samples charger state before cancellation. Events other than full-word `0x5a` cancel the post-timer callback with wildcard argument zero. State zero logs through live gates, publishes flag `0xa5`, cancels that callback again, releases the NFC bus, binds the GPO completion, cancels the PMIC retry callback, configures the charger IRQ, signals task flag `0x10`, and installs the IRQ setup callback as charger completion. It preserves the ordered calls even when leaf results report errors. The timer adapter requests flag eight with an ordinary void callback ABI.

For state one or two and event one, the policy reads battery voltage and scaled ADC, releases charger IRQ transport, decodes charge status, clears completion and reads both temperature channels into zeroed halfwords. It initializes a 24-byte packet: type bytes one/two, battery level, two-bit charger state plus six-bit temperature quotient, low voltage/ADC halfwords, configuration/status bytes, and the ten version bytes `2.2.6.0009` at offset 13. Other bytes remain zero. The selected ADC provider has its actual uint16_t return declaration.

The mailbox handler can change the escaped packet, so the policy reloads byte four afterward. Quotients at least 45 release transport, issue the single-wire command and clear completion. Values 1–14 select raw float bits `0x40808312`; values 15–44 select `0x4160f5c3`; zero makes no change. A bit-identical cached setting suppresses the ladder call; otherwise the cache publishes before that call. The mailbox body at `0x77be0` remains explicit as `r1_st25dvxxkc_bounded_mailbox_receive`. It is neither supplied by a success stub nor claimed complete here.

REA binds the full policy, literals, version and settings window to the locked image. Verification passes 1000 policy pairs, 528 temperature/mailbox-mutation pairs, 512 seeded full-word cases and 18 timer-adapter pairs. These exercise state/event selection, cancellation identities/order, initialized partial sensor outputs, six-bit wraparound, zero and thermal boundaries, live logging, full result words, callback identities, packet bytes, float bits and publication order, interrupt masks and poisoned stacks. Hardware and RTOS leaves are modeled.

An additional 36 comparisons execute the real C and stock delayed-cancellation bodies against populated timer tables. Duplicate callback records with different arguments are removed by wildcard zero; unrelated IRQ callbacks survive. Mutex, time, timer and reschedule leaves remain modeled. Nine compiled defects are rejected: wrong cancellation exception, rejecting state two, wrong thermal/low thresholds, wrong temperature scale, caching temperature before mailbox processing, omitting setting publication, publishing after the ladder call and wrong timer flag. The normal probe passes after mutation testing.

The open-toolchain build compiles 816 units (734 application, 82 bootloader), with 71 application imports and no new failures or duplicate strong symbols. The one added import is the real mailbox boundary exposed by this policy. All 815 prior source inputs remain unchanged; 813 object hashes match and two generated boot objects differ with build paths. No G2 source or qualification selection changes. The larger NFC dispatcher, charged-notification policy, mailbox body, final application link and device boot remain open.
