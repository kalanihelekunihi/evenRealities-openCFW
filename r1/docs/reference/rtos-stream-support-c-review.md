# Timeout and notification APIs resolve stream-buffer dependencies

The task-wait and notification modules now include the pinned FreeRTOS `vTaskSetTimeOutState` and `xTaskGenericNotifyStateClear` bodies. They use the existing overflow counter, native tick word and verified 112-byte notification TCB. No duplicate task or scheduler owner is introduced. Timeout records remain eight bytes; the only valid notification index is zero in the configured one-slot layout.

Timeout snapshotting enters the critical section, writes overflow and tick values to the record, then exits. Notification clearing selects an explicit/current task before critical entry, examines its state inside the critical section, changes only RECEIVED to NOT_WAITING, and returns whether that change occurred. The notification value and adjacent allocation bytes remain intact. Pinned assertion statements and current build policy are retained; invalid objects/indexes keep upstream preconditions.

The [receipt](rtos-stream-support-c-review.json) records 128 timeout and 240 notification API checks. Controlled entry/exit mutations verify counter snapshots, output writes before exit, current-task retargeting, state-read ordering and stable return values after exit. Checks include end-of-region timeout records, full-width counter bits, explicit/current task selection, notification-value preservation, stack balance, saved registers and masks. Five defective variants with wrong timeout data, wrong notification state, unwanted value clearing, late task selection or missing critical exit are rejected.

These are pinned upstream compatibility APIs using existing native-layout evidence, not stock API identity claims. Critical callbacks are modeled. Full scheduler operation, hardware timing, physical devices and a complete source-only firmware image remain unverified.

The normal report is `build/sources-goal-r1-rtos-stream-support-c/report.json`: 729 units compile without failures or duplicate strong symbols. Application imports fall from 170 to 168, resolving both stream-buffer references; bootloader imports remain 34. Two objects changed and 727 remain unchanged. All pre-existing instruction sections and named relocations in both changed modules remain unchanged. Their original source bytes are preserved as exact prefixes, including line endings; APIs were appended. Both manifests pass `make sources-check`; no source-plan selection was added.
