# R1 BLE initialization in C

`r1/src/application/board/native_ble_initialize.c` implements bootstrap `0x4df18`, peer-manager configuration `0x4e4b4`, and checked buttonless-DFU initialization `0x4c92c`. Existing C providers supply GATT, advertising, queued-write contexts and BAE8 transport. The worker declaration now reflects the bootstrap's zero return; its compiled object is unchanged.

Bootstrap orders GAP identity, GATT with a null event handler, advertising, all three queued-write instances, BAE8 transport, buttonless DFU, peer manager, DC/DC enable, controller version query and live gated version logs. Checked errors log and continue. DC/DC and version-query status codes are discarded as in stock. The version owner is a six-byte SDK structure, zero in authenticated cold RW at `0x200064b2`; failures and partial writes preserve untouched fields rather than clearing the structure per call. Final placement remains a linker gate.

The queued-write error callback uses the existing C error owner, corresponding to stock's `0x79dc8` tail trampoline. DFU and peer-manager event callbacks remain explicit policy imports. Security parameters are the SDK's five-byte `31 07 10 03 03` layout: bonding, no I/O capabilities, key lengths 7–16 and encryption/identity distribution to both sides. Stock's eight-byte private stack reservation does not enlarge that API type.

All 2,320 direct comparisons pass: 1,536 initializer/error/log combinations, 512 log-mode sequences, 256 seeded partial-service cases and 16 PM/DFU adapter cases. A 53-case integration pass includes 37 bootstrap cases executing actual GATT and queued-write initialization bodies, plus 16 PM/DFU adapter cases. It compares context state, including already-initialized QWR contexts. Tests check call order, callback identities, error continuation, security bytes, full version values and read order, discarded service errors, stack guards, preserved registers and masks. Ten compiled defects are rejected before an unmodified-source rerun. REA byte receipts match the pinned firmware image.

The normal build compiles 829 units (747 application, 82 bootloader) with no duplicate strong symbols. One bootstrap import closes; three lower dependencies become explicit: GAP identity configuration, peer-manager event policy and buttonless-DFU event policy. Application imports rise from 73 to 75. All 826 prior non-generated objects are identical; two generated bootloader objects differ. R1 manifest validation passes (829 units, 615 sources).

Lower initialization services, logging, transport and S140 services remain modeled except for GATT/QWR in the deeper probe. Physical radio initialization, final application linking and boot remain unverified. Byte identity and a paid compiler are not acceptance requirements under the current user instruction.
