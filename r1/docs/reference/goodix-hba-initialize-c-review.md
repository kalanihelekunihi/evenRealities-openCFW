# R1 native heart-rate context initialization in C

The [workspace review](goodix-hba-workspace-c-review.md) supersedes the workspace and four resource-getter boundaries. All now execute as C using canonical numeric data; graph-construction internals remain modeled in full heap lifecycles.

The primary constructor `goodix_hba_init` at `0x6d204`, byte queue initializer at `0x6631e` and library code getter at `0x6a140` now use C in `r1/src/application/goodix/native_hba_initialize.c`. The [receipt](goodix-hba-initialize-c-review.json) pins REA reads, sources, tested/normal objects and fixtures.

The constructor checks the configuration pointer, 36-byte size and `pv_v1.1.0` interface string, then allocates 336 bytes. Stock neither clears this allocation nor checks allocation failures. Unknown modes preserve the prior window word unless an override is supplied. Sample rate defaults to 25 and truncates to 16 bits before division. Batch minimum uses a signed-positive clamp followed by byte truncation. Full-word window overrides, unsigned candidate cap, padding and terminal defaults are preserved.

Native initialization clears four workspace-owner words at `0x200377a4`. The existing canonical owner therefore grows from a pointer to a four-pointer array: 4 to 16 bytes, adding 12 owned bytes. The destructor consumes cell zero and retains native dangling-owner behavior after freeing it. No second owner is introduced. The primary constructor reloads the context owner after callbacks and preserves callback mutations to later graph parameter records, null graph returns and native call order. Two byte queues allocate 3 bytes each; the existing C float records allocate 12 bytes each.

All 830 direct comparisons pass with independent primary-field, queue and call-order oracles. Every one of the 440 native instruction bytes executes. Cases cover field truncation/defaults, untouched allocated bytes, invalid entry guards, graph parameter mutation, owner replacement at every external callback and allocation results. Twenty-two compiled defects are rejected. Registers, stack, masks, active floating-point status, complete arena contents, provider snapshots, owner words and guards agree.

All 128 real allocator/complete teardown lifecycle cases pass. Graph provider records are preallocated using each real allocator, transferred through modeled graph returns, and released by the actual type 0/1/6 destructor paths. Workspace internals are modeled as an empty initialized workspace. All primary, workspace, graph and queue allocations coalesce to the prior heap top. These cases prove ownership transfer and cleanup, not the internal graph/workspace constructors or their allocation timing.

The 886-unit build passes without duplicate strong symbols. The tested constructor and processing teardown objects match the normal build; 874 prior nongenerated source/object pairs are unchanged. The constructor adds no writable state; the canonical owner expansion adds 12 bytes. Application imports increase from 73 to 78 as one constructor dependency is replaced by workspace initialization, graph construction and four resource getters. Boot imports remain 22. Source-plan and cache layout are unchanged.

Allocation failure one is compared as a logical unmapped-write fault; physical fault details are unproven. Null workspace allocation is covered only through its modeled provider. Invalid addresses, concurrency/reentrancy, cold floating-point activation, inference, final executable linking/startup and device boot remain open. This is an `ld -r` composition, not a bootable firmware image. Byte identity is waived for this goal.
