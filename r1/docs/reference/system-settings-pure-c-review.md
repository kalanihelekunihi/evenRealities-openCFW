# C settings accessors and table-routed regulator command

`r1/src/application/runtime/native_system_settings.c` replaces three naked private-frame bridges and their workers with ordinary C: cached bit getter `0x73750`, bit-one setter `0x73800` and settings handler `0x84524`. The existing table name `r1_system_settings_plan_command` now defines the canonical four-argument callback. Its legacy handler name aliases the same body. The module's declaration is typed accordingly; its compiled object and table bytes/relocations are unchanged.

Successful reads retain stock behavior: bit-one extraction, masked update of byte 24, full-record write and idle query. The handler retains a zero-filled 12-byte query response with setting byte five, write acknowledgement before payload lookup, live logging queries and packet reloads. Raw requested byte equality is retained: request two differs from cached bit one, even though both request an enabled regulator. The SDK SVC 63 boundary remains architectural assembly; this change removes private-frame assembly from the source unit.

Failed reads have explicit C policies. A getter with a destination reports zero; without a destination it returns the cached-read status. A setter returns the read error and skips writing or scanning idle state. As in the established handler control flow, the handler ignores setter return status and still applies the requested regulator setting. This does not prove persistence or hardware success. The shared getter's other consumer, the glasses-status reporter, consequently reports zero for an unavailable setting.

REA bytes match the locked official artifact. Direct execution passes **9,912 stock/C comparisons** and **48 failed-read cases**. Tests exercise all record-byte values and requested bytes, raw setter values/statuses, query/write branches, modes, getter-null destination, wrapping advertised lengths, and callback changes to packet type, requested state and sequence. Actual C accessors and payload lookup execute; real `svc #63` instructions execute with a modeled backend result. Return words, records, responses and provider traces agree for the stock comparisons.

A further **25,856 cases** execute the actual system command table/lookup, callback, cached-class accessors, memory routines, checked-send and flag/header helpers. They verify the canonical table target, complete cached record, dirty flags, balanced critical sections, outgoing wire bytes, full-word invalid-handle rejection, and regulator request value. Invalid class sizes check the failure policies. All 256 record-byte values are also queried across logging modes. Modeled callees overwrite caller-saved integer/FP registers; both fixtures check caller stack, callee-saved integer/FP registers, SP and interrupt masks.

Five compiled defects are rejected: wrong response offset, booleanizing the raw equality check, wrong persisted bit and ignoring either cached-read failure policy. Critical-section callbacks, logging, final response and regulator backend remain modeled. Physical DCDC state/timing, KV flush/persistence, faults/concurrency, incomplete packet buffers and final application linking/startup remain unverified.

The open-toolchain report `build/sources-goal-r1-system-settings-pure-c/report.json` compiles all **855 units** and completes both relocatable compositions. The settings route import closes: **61 application imports / 22 bootloader imports** remain. All **844 other nongenerated objects**, including the module table object, are unchanged. R1 manifest validation passes and source-plan selections remain unchanged. Byte identity is not claimed.
