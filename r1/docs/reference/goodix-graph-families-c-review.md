# R1 native graph-family construction in C

The [mode6 review](goodix-mode6-c-review.md) closes the remaining modeled HR constructor. All three HR graph paths now execute in C through successful constructor/allocator/teardown replays, with no called function ports. Executor implementation and inference remain open.

The family-zero (`0x2874c`) and nonzero-family (`0x2966c`) builders and three packed descriptor/accessor helpers now use C in `r1/src/application/goodix/native_graph_families.c`. The [receipt](goodix-graph-families-c-review.json) pins fresh REA reads, source and normal/tested objects, fixtures and results.

The builders reuse the existing C aligned/convolution, quantizer, pair, pool, operator and vector helpers. They preserve the four-byte gaps at `0x74`, `0xdc` and `0x1a4`, the native pool dimension bytes, and late descriptor order `0x15c/0x174/0x18c/0x144`. The older portable model's whole-buffer clear and abbreviated packed headers are not used as native replacements.

Family zero uses the exact private quantizer constants 0.0/1.0 without consuming model data. Nonzero families consume an input pair and index the native eight-byte output table `8/4/8/0/0/0/0/0`. All eight indices are covered. Cursor advances are 6,856 bytes for family zero and 3,808, 4,368 or 3,248 bytes for nonzero families with four, eight or zero outputs. Three new helpers pack exactly three configuration bytes, pack four truncated argument bytes, and return an executor identity word.

All 710 stock/C comparisons pass with independent complete graph, cursor, gap-preservation and packed-field oracles. Every one of the 1,838 native instruction bytes executes. No function ports are modeled in these direct comparisons: all descriptor and memory helpers execute in C. Cases cover input/output overlap that changes later input headers, helper aliases, full argument truncation, active floating-point state and wrapping cursors. Twenty compiled defects are rejected.

All 128 full HR constructor/real-allocator/complete-teardown lifecycles pass with both family builders executing in C. Completed mode 0/1 records independently reach the exact ends of their 6,660-word and 2,979-word canonical resources. All primary, workspace, filter, graph, queue and state allocations coalesce back to the prior heap top. Only mode 6 construction is modeled beneath this ordinary lifecycle, using a record preallocated through each real allocator. Executor identity words do not execute inference code.

The first heap comparison exposed an instrumentation bug: a broad resource-range normalizer treated packed scalar `0x01010e1b` as a relocated pointer. The final fixture normalizes only explicitly typed descriptor, remap and coefficient pointer fields. It leaves dimension/flag/scale words unchanged and asserts preservation of eight real packed-scalar/resource-address collisions. No firmware source changes were needed for this correction. Actual memory is never rewritten by normalization.

The 890-unit build passes without duplicate strong symbols. The tested object equals the normal object, 879 prior nongenerated source/object pairs are unchanged, and no writable state is added. The eight-byte width table and C shape metadata are readonly data. Two family imports are replaced by three opaque executor identity data bindings: application imports rise from 75 to 76; boot imports remain 22. Source-plan and cache layout are unchanged.

Mode 6 construction and fourteen executor identity imports remain open. Numerical inference, family indices outside the eight-byte table, invalid/unaligned pointers, physical fault behavior, concurrency, cold floating-point activation, caller scratch and private frames remain unproven. High-address wrap cases establish logical layout rather than an entire physically valid model span. Final executable linking/startup and hardware boot remain open. This is an `ld -r` composition, not a bootable firmware image; byte identity is waived for this goal.
