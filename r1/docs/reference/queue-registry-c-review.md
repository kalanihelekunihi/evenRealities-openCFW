# FreeRTOS queue registry in C

The pinned kernel `vQueueAddToRegistry`, `vQueueUnregisterQueue` and `pcQueueGetName` bodies now share one `xQueueRegistry` storage owner in `rtos/queue-registry/queue-registry.c`. The public configuration selects two eight-byte entries. The unit is registered in `r1/src/sources.json`; its upstream MIT notice is retained.

The existing native queue-delete module deliberately has a scoped registry size of zero, matching its verified stock route. The registry therefore has a separate owner using the public configuration, rather than changing that native delete path. CMSIS mutex, semaphore and message-queue deletion explicitly unregisters before calling the native delete provider. The initial attempt to append the registry to the native module was rejected by the configuration assertion; that source was restored byte for byte before the final build.

An isolated ARM subset links without any symbol bindings. Tests exercise empty, full and vacant-before-existing registries through every four-action sequence drawn from seven add/rename/null-name/remove actions. All 7,203 sequences pass, including 28,812 mutations and 86,436 name queries. An independent model checks replacement before vacant-slot selection, capacity exhaustion, null-name no-op, removal of both name and handle, absent handles, repeated deletion and slot reuse. Tests compare complete registry contents and guards, read-only lookup behavior, preserved R4-R11, SP and interrupt masks.

Four compiled defects fail runtime assertions: accepting null names, losing existing-handle replacement, leaving stale handles after removal and returning null for existing names. Probes and the positive subset ELF are under ignored `build/goal-r1-queue-registry-c/`. The [machine-readable receipt](queue-registry-c-review.json) records provenance, build hashes, test digest and defect diagnostics.

`build/sources-goal-r1-queue-registry-final/report.json` compiles all 730 R1 units and composes both payloads without failures or duplicate strong symbols. Both CMSIS registry imports resolve, reducing application imports from 166 to 164; bootloader imports remain 34. All 729 prior object hashes and the native queue source are unchanged. `make sources-check` passes. Tests assume valid nonnull handles and sequential execution; debugger concurrency, complete CMSIS/scheduler execution, physical device behavior and a complete firmware link remain unverified. No stock API byte-identity claim is made.
