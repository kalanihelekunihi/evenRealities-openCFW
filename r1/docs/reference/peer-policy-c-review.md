# R1 peer-manager event policy and bond diagnostic in C

`board/native_peer_manager_policy.c` implements the registered Peer Manager callback at `0x7f2b0` (1,052 instruction bytes in two ranges) and its bond diagnostic at `0x8216c` (352). It calls the pinned SDK event and flash-clean handlers in stock order before reading the event type. The SDK's short-enum event layout is checked at compile time.

Security success saves the current peer ID, narrows the peripheral count to a byte and preserves the time-notification sequence at raw delays `0x66`, `0x400` and `0x800`. With fewer than three peripherals and no glasses handle, it reports the current record flag and schedules role sync. When phone and glasses are both present, it cancels role sync and stops advertising. Bond-load status, a fresh phone slow-mode request and the late shared control flag retain stock ordering. A successful first load invokes the diagnostic, which performs its own independent load.

Security failure captures its procedure, error and source before diagnostics and schedules the time callback with argument 1 at `0x800`. Error `0x1101` adds the SMP-timeout report. Security configuration requests reply with `allow_repairing=true`. Peer-data update success runs the diagnostic only for changed bit 0 and data ID 7. Peers-deleted completion restarts advertising mode 3; storage-full and garbage-collection diagnostics retain their distinct paths after the SDK prelude.

The bond record is **80 bytes**, as both the SDK type and stock load helper establish. The stock's 84-byte stack allocation includes padding. The diagnostic preserves its exact invalid-peer guard, failure reports, MAC/identity/LTK dumps and two live eight-byte key formats. Its final mode test is equality with 2, rather than a bit test. Existing BLE control and connection owners are reused; the sole new state is the two-byte last-secured-peer owner at native `0x200064fa`, matching the authenticated cold initializer `0000`.

**4,775 stock/C comparisons pass**, covering all **1,404 native instruction bytes**. Cases cover all 256 event IDs, count narrowing, handle/control combinations, independent bond-load statuses, security errors, update gates, log modes and live backend/buffer mutations. All **18 compiled defects** are rejected. A further **56 registration/delivery comparisons** execute the existing registration body, check security parameters `3107100303`, capture the actual policy pointer passed to modeled `pm_register` and invoke that pointer with an event.

SDK event/flash handlers, storage loads, repairing replies, scheduler, record/count queries, advertising controls, slow-mode policy and logging are modeled. Registration storage and error-boundary returns are also modeled. These fixtures perform no physical pairing, flash writes, radio encryption or time-based queue delivery. Callee-saved integer/FP registers, masks, SP, stack/input/state guards and public traces/state are checked; source execution cannot enter stock code. Incidental void-callback scratch results, private stack/padding, partial records and asynchronous concurrency are outside the proof.

The normal build compiles **850 units**: 768 application and 82 bootloader. The registered policy import closes without new imports, leaving **68 application imports** and 22 bootloader linker imports. All **839 prior nongenerated objects** remain identical. No assembly is added. R1 manifest checking passes; repository-wide checking retains the unrelated unlisted G2 `resident_rom_thumb_set.S` issue. Final source placement, firmware linking, boot and physical security/storage behavior remain unverified. Byte identity and paid compiler availability are not requirements.

See [peer-policy-c-review.json](peer-policy-c-review.json) for exact contracts, REA readbacks, hashes, replay groups, registration checks and proof limits. No commit or device write was performed.
