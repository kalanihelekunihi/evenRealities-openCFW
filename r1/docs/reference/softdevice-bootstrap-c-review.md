# R1 SoftDevice resource bootstrap in C

`native_softdevice_bootstrap.c` supplies the previously unresolved stock 0x539b8 routine in the normal source composition. The open-toolchain build compiles 806 units (724 application and 82 bootloader), with 69 application imports and 22 bootloader linker-metadata imports. R1 source checking and strict bootloader linking pass. Global source checking retains the unrelated G2 unlisted `resident_rom_thumb_set.S` failure. The manager worker remains unresolved; supplying this prerequisite does not establish complete startup.

The routine requests SoftDevice enablement, zeroes the RAM-base word, applies SDK defaults for connection tag 1, then supplies a zeroed 12-byte `ble_cfg_t` with tag 1 and a GATTS notification queue size of four. The configuration ID is `BLE_CONN_CFG_GATTS` (0x22). It is not a role-count configuration. The routine logs the RAM value under the stock live mode gates, enables BLE through the existing SDK provider and sets the zeroed eight-byte extended-connection-event option to enabled. Header assertions pin the union sizes, parameter offset and numeric IDs. Calls use the pinned SDK API; the new source has no handwritten assembly.

Every nonzero setup status is passed, at full width, to the existing `r1_adc_error` helper. That helper logs and returns. Later configuration stages still run after failures, matching stock behavior rather than treating its diagnostic label as a reset or halt. The RAM value can be changed by the default/configuration providers before later stages read it.

Raw-stock/C execution passes 4512 direct pairs across setup failures, partial RAM writes, all three log bits, changing mode sequences, masks and poisoned stacks. Another 144 pairs mutate the escaped RAM word while mode checks execute, verifying subsequent live reads. Actual error-logging helper code executes in both reference and candidate; formatter and frontend outputs are modeled and compared with their strings and argument words. All configuration and option bytes are checked.

The 128 integration pairs execute the actual normal-build SDK default-configuration and BLE-enable providers. Their seven configuration requests match raw stock in order, IDs, RAM bases and all 12 descriptor bytes, including the product notification-queue override. Cases include failures in all six default configuration requests, enable/option errors, changed RAM requirements and prior enabled state. The enabled-state byte is checked. Enable-request and SoftDevice SVC implementations remain modeled. This integration deliberately uses log mode zero: the selected SDK configuration disables its own diagnostics, so these runs establish configuration/state behavior and do not claim diagnostic equivalence for nonzero modes.

Eight compiled defects are rejected: wrong default tag, short notification queue, stale RAM base, stopping after an enable error, wrong secondary log bit, disabled extended events, narrowed error codes and nonzero initial RAM. The final normal probe passes again after the mutants. REA's 268-byte window at 0x539b8 matches the locked application and includes the 162-byte routine, its literals/strings and adjacent bytes; it is not a claim that all 268 bytes are executable code.

The audit preserves 803 prior object hashes and the allocated bytes/normalized relocations of generated boot objects. The only manifest change is the new C unit; import sets remain unchanged. No source qualification plan or G2 source is changed.

Physical BLE operation, interrupt timing, final RAM placement, `__data_start__`, a final application link and device boot remain unverified. Private frames, exact local descriptor addresses and incidental void return registers are outside the ordinary C ABI proof. Reproduction inputs, probe scripts and hashes are in [softdevice-bootstrap-c-review.json](softdevice-bootstrap-c-review.json).
