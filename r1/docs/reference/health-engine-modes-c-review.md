# Health engine mode and profile activation in C

`native_health_engine_modes.c` now supplies mode dispatch `0x8ec7c`, profile application `0x916c8`, threshold setter `0x723ec`, signed-value setter `0x72410`, code predicate `0x72650`, code commit `0x726fa`, checked state setter `0x7271c` and slot transition `0x8ecd8`. REA dossiers establish all eight local bodies. The unit contains no inline assembly or executable byte arrays and reuses the existing `r1_gomore_native_context` owner.

Dispatch narrows values to a byte only for modes 0 and 1. Modes 2 and 3 retain the complete incoming word. The signed-value setter admits negative words and values below three; the checked setter tests the old signed state, then stores the complete new word. Nonzero helper results map to raw -1 at the dispatcher. The code predicate admits only 0..3 and 100..105. The threshold setter retains both stock binary32 encodings.

Profile application writes the incoming profile word before validation, caches that first write address for invalid-profile rollback, and reloads the live context for every slot operation. Profiles 0, 1 and 2 perform the native ordered slot updates. Profile 11 selects requested state 4 for selector 0, 5 for selector 1, or the full fallback word otherwise. A frozen state 4 transitions to 1 only for full-word request 5, not merely a low byte of 5. The existing checked slot API moved from the vendor unit and shares the same core, retaining its null guard and byte/bool contract. The lifecycle caller now includes the shared typed header and passes an explicit unused fallback zero for its fixed profile-1 call.

All 9,852 direct production-object stock/C pairs pass, including 7,168 slot cases, 1,150 dispatch cases and 734 profile cases. Inputs cover every byte state, high-bit/full-word values, native signed comparisons, selectors and fallback values, and FP control/status seeds. Overlapping context-owner cases make real stores retarget later context loads; no provider mutation is required to test reload behavior. There are 43 logical-fault pairs. Raw R0, final RAM, ordered external writes, FPSCR, masks, SP and callee-preserved registers agree for the tested boundaries. Fault comparison does not establish full CPU exception frames, unwind state, CCR variants or physical device behavior.

The checked slot API passes another 48 comparisons and 12 null guards; its void return is excluded. Four compiled defects are rejected: narrowing modes 2/3, treating request 0x105 as request 5, caching the profile context across calls, and accepting code 106.
