# R1 touch release callbacks in ordinary C

The assembly entry bridges in `native_touch_release.c` are replaced with C calls and local arrays. There is no inline assembly left in that translation unit. The normal build still compiles 805 units, with 69 application imports and 22 bootloader linker-metadata imports. R1 source checking and strict bootloader linking pass. Global source checking still reports the unrelated G2 unlisted `resident_rom_thumb_set.S` source.

The timer callback at stock 0x934e4 clears a 44-byte local message, stores type 5 at offset 4 and zero at offset 8, then calls the existing shared task-message frontend. That frontend's diagnostics identify NFC/charge; its use does not establish an exclusively touch task. The synthetic release at 0x93424 retains the active-byte gate, delayed cancellation, subsequent live-state reads, slider direction/distance/velocity policy, synthetic flag ordering and final 100-byte contact clear. Each emitted four-byte gesture record is initialized in full before the consumer reads it. The active return remains the end of the contact-state span; inactive returns retain the actual active byte.

The proof accepts ordinary C ABI behavior. The normal C service-close caller uses a typed no-argument call and ignores the result; the delayed worker invokes the timer through its typed one-word callback. Saved scratch registers and exact stack addresses are not outputs of that contract. The existing gesture consumer reads only the four assigned record bytes. Its actual code executes in integration probes, including delayed rescheduling, direction state, logging gates and BLE packet formation. Stack content outside those records is not treated as an input.

Raw-stock/C execution passes 2400 direct pairs, 24 mutation pairs and 240 actual-gesture integration pairs, plus 160 actual service-close caller pairs. Direct tests independently check all 44 message bytes, the emitted four-byte records and complete contact clearing. Cases cover active values 0/1/2/255, slider modes, timer values 0/1/255, endpoint deltas, sign fallback, zero velocity, masks and poisoned stacks. Callback models exercise contact changes during cancellation, gesture-side flag changes, queue-side thread-handle replacement and provider failures. Integration varies logging modes, connected/disconnected handles and short/full BLE packet selection. Real EABI/memset, gesture code and queue frontend execute; RTOS queue/thread, delayed scheduler, logging and BLE providers are modeled.

Six compiled defects are rejected: partial message clearing, wrong message type, dispatching inactive contacts, partial contact clearing, reversed slider direction and zero velocity. The final normal probe passes again after the mutants. REA instruction windows for both entries and the gesture consumer are bound byte-for-byte to the locked stock application, with hashes in the receipt.

The audit preserves 802 prior object hashes. The synthetic-release kernel, contact-clear result helper, state sections and their relocations are unchanged. Only their entry adapters and the timer's fully initialized message construction change. Generated boot objects retain allocated bytes and normalized relocations. The manifest and import sets are unchanged.

Physical touch behavior, RTOS scheduling, radio timing, final application memory placement and device boot remain unverified. The normal application output is relocatable composition, not a complete firmware image. Reproduction inputs, scripts and hashes are listed in [touch-release-pure-c-review.json](touch-release-pure-c-review.json).
