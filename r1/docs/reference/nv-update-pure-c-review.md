# R1 persistent-record updates without inline assembly

`runtime/native_nv_update.c` and `board/native_kv_device_fields.c` now express four stock operations in ordinary C: bit-two setter `0x73834`, peer-address writer `0x738a8`, clear-peer protocol command `0x844b0`, and device-field setter `0x73710`. Four naked assembly wrappers and their superseded private body helpers are replaced in place. Public strong symbols, manifest units and state owners are unchanged. Both edited source files contain no inline assembly or naked function attributes.

Each modifying operation reads a 52-byte cached record into a zero-initialized private C buffer. Complete read output preserves stock updates. Read/write statuses are still ignored where stock ignores them. Failed or short reads retain deterministic zeros for unfilled bytes rather than private stack residue; those fallbacks are tested separately from stock equivalence. Ordinary C API behavior is the target: private stack addresses, incidental R1–R3 preservation and callers that designate a callee-private frame are outside the contract. No compiler-specific register reservation is needed.

The bit setter replaces only bit two of byte 24 using input bit zero. Peer writing copies optional six-byte addresses into offsets 8 and 14, preserves order and writes marker 0x484d4143 at offset 20. Both reload the live handle before writing and run the existing idle check. Clear-peer command first checks the payload getter; a missing payload returns zero. Otherwise it replies with command 130/state one and the live packet identifier, clears bit two, then writes one all-FF address buffer into both peer slots. Its unused scratch/seed arguments remain accepted under the existing C prototype. Device-field setting accepts null input, copies the first word to offset 36, and updates the low 16 bits at offset 40 through ordered kind/voltage reads while preserving the upper word half.

REA binds all four routines and literals to locked firmware. Verification passes 432 stock/previous-C/current-C triples across full-word inputs/statuses and live handle/input/packet changes; 48 null, alias and command triples; and 1024 all-byte bit-mask triples. Another 72 short-read cases verify zero fallback independent of poisoned stack contents. Direct tests model cached operations and dirty scan at its established constant return one. Fabricated alternative scan results are not part of the stock contract; the ordinary compiler can correctly fold its caller's XOR result to zero.

An additional 128 triples execute the actual stock and C cached-record read/write, memory copying and seven-class dirty scan with prepared valid objects. Tests compare all class bytes and critical-section/store/flush order, including both complete seven-class write/flush passes made by clear-peer command. Port callbacks, persistence backend writes/flush and protocol replies remain modeled; these are cached-RAM and call-sequencing checks, not physical flash persistence proof.

Eight compiled defects are rejected: wrong enable bit, wrong preservation mask, wrong peer offset/marker, wrong acknowledgement code, clearing upper field bits, nonzero initialized fallback and caching the write handle across the read callback. The normal probe passes after mutation testing. The audit confirms unchanged public strong symbols and identical dirty-scan/idle-check code and registry/log data sections. Other source inputs are untouched.

The open-toolchain build still compiles 821 units (739 application, 82 bootloader), with 69 application imports and no new failures or duplicate strong symbols. Of 821 prior units, 817 object hashes match; the two edited units change, and two generated boot objects differ with build paths. No manifest, G2 source or qualification selection changes. Final application linking, startup placement and device boot remain open.
