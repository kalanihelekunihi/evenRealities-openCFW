# Daily health-record replay in C

The daily-record replay callback at `0x88170` now has a normal-build C provider. The six cache writers at `0x706a4`, `0x90e4c`, `0x91954`, `0x91158`, `0x4832c` and `0x7073c` are implemented together, using the existing cache accessors and storage owners. The missing stress accessor at `0x5bccc` reuses the existing stress prefix, and the temperature accessor at `0x5be5c` replaces its naked assembly body with C. No duplicate cache allocation is added.

The [REA descriptor read](health-daily-replay-c-rea.json) matches the locked binary's six 16-byte descriptors at `0x99bf4`. Replay reuses their existing kind/size owners and pairs them with the six typed writers. It rejects null arguments, builds the native 20-byte blob view, reads from the shared health database and truncates the returned read length to 16 bits before checking for 128. It reads timestamp word +4, maps midnight to slot 23 and other hours to `(hour-1)&255`, then starts payload dispatch at byte +8. A missing callback skips both the call and cursor advance; the descriptor size is reloaded after each callback.

The four three-byte writers preserve halfword-store then byte-read/store ordering. HRV preserves word-store then halfword-read/store ordering. Activity preserves the stock `0x2775c` copy routine's backward byte copy for overlapping destinations, aligned forward word copy and unaligned forward byte copy. These are ordinary C SRAM accesses; MMIO and arbitrary faults are outside the tested contract.

The [machine-readable review](health-daily-replay-c-review.json) records 1,620 stock/C comparisons across all valid daily slots, alignments, partial aliases, cache accessors, read lengths (including values whose low halfword is 128), hour values, callback masks and synthetic post-callback size changes. The actual six C writers, accessors and existing storage owners execute in the source subset; FlashDB blob make/view/read and the hour provider are explicit modeled boundaries. Synthetic writes to descriptor flash in the harness test control flow, not device flash mutability.

A further 417 startup comparisons execute the stock or C replay through the modeled iterator boundary, with actual retained helpers/CRC and six cache writers. Four separately compiled defects fail runtime assertions: removing read-length truncation, changing the midnight slot, advancing past null callbacks and removing backward overlap copying.

All 732 other prior objects are identical. Within the one changed prior object, the temperature accessor is the only changed implementation; the fixture's other allocated contents and named relocations remain unchanged. `make sources-check` passes. The normal R1 build compiles/composes 660 application and 74 bootloader units with no failures or duplicate strong symbols. Application imports fall from 159 to 158; bootloader imports remain 34. No additional import is introduced.

The hour-boundary and time-transition storage orchestrators and retained crash-snapshot restore remain unresolved below database startup. Physical flash reads, persistence, interrupts/scheduler behavior, the remaining inline assembly providers and the complete firmware link remain unverified or unfinished. No exact source-plan selection or image-integration claim is added.
