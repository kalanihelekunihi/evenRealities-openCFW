# Typed C LIS2DW12 configuration

`r1/src/application/runtime/native_lis_configure.c` replaces its naked entry and generic four-register call/capture adapter with one typed C configuration function. Address-only assembly declarations and the private worker are removed. SDK and native helper prototypes now describe the actual calls. The existing ST profile `r1-application-12` supplies the pinned header and aliasing configuration; this unit's profile selection is the only manifest change.

The sequence still writes the default transport callbacks, initializes identity/reset outputs, admits ID `0x44`, requests reset and polls in read → delay 2 → limit check → reset-byte check order. The twelfth poll times out even if it first reports reset complete. All existing helper statuses remain ignored. Register-17 enable, data update, full scale, filter path/bandwidth, FIFO watermark/mode, native power and data-rate calls remain ordered. Rates 50/100/150-or-200 map to 4/5/6; all others map to 3. The final delay is 100 and five samples are discarded into owned 30-byte storage.

Identity/reset bytes and discard storage are initialized C locals. Private frame addresses and helper R1–R3 residue are no longer inputs or outputs. The existing context's delay and handle fields are preserved, including provider changes. Live logging queries retain their short circuits. Authenticated log sections remain byte-identical.

REA bytes match the official artifact. Direct execution passes **32,921 stock/C comparisons** across every identity byte, rate boundaries, helper error words, reset completion and timeout positions, missing writes, scratch seeds, live mode sequences and context mutations. Tests compare meaningful helper arguments/order, returned success, callback installation and retained context fields. Caller stack, callee-saved integer/FP registers, SP and interrupt masks remain intact while modeled callees overwrite caller-saved registers.

Another **378 stock/C comparisons** execute the typed configuration with actual C register entries and field/transport logic. The configuration-reachable subset of the 22 register entries executes; the preceding entry receipt covers all 22 individually. This graph models identity, FIFO output, bus callbacks, delays and logging. Five compiled defects are rejected: early timeout, wrong poll delay, wrong watermark, wrong rate-150 mapping and wrong identity admission.

The open-toolchain report `build/sources-goal-r1-lis-config-pure-c/report.json` compiles all **855 units** and completes both relocatable compositions. All **844 other nongenerated objects** remain unchanged. The normal configuration object equals the directly executed probe object. Imports remain **61 application / 22 bootloader**. R1 manifest validation passes, and reversing the one profile selection exactly reproduces the previous manifest hash. Source-plan selections remain unchanged.

[Machine receipt](lis-config-pure-c-review.json) binds sources, REA, reports and ignored probe evidence under `build/goal-r1-lis-config-pure-c/`. Physical sensor/reset behavior, bus/delay timing, faults/concurrency, provider overruns, private-frame aliases and final application linking/startup remain unverified. Auxiliary/FIFO assembly remains elsewhere. Byte identity is not claimed.
