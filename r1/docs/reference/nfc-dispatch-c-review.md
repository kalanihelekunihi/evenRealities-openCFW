# R1 NFC/charging flag dispatcher and native adapters in C

`runtime/native_nfc_charge_dispatch.c` supplies dispatcher `0x461cc`, battery status reset `0x31fac` and native charging-event policy `0x350e0`/veneer `0x50614`. It reuses the existing task queue/watchdog, battery storage, service thread flag wrapper and PMIC/service/event providers. There is no new state owner, assembly, opcode array or trap replacement.

Flags execute independently and in stock order: bit 22 drains the 44-byte queue; bits zero and one run charged/IRQ processing; bit four runs not-charging handling and ID checks; bits two/three run PMIC retry/charge policy; bit six logs and optionally samples battery eight times; bit five updates battery once; bit 23 parks the worker. Queue gets use priority NULL and timeout zero, clear the message once, and reload the live queue handle until any nonzero status. Other high bits are ignored. The two battery reports each fetch level separately. Charger-state queries occur separately within enabled log gates and for the sampling decision.

IRQ handling acquires NFC resources, publishes event 0x100b byte one, logs, requests retry, signals the existing service thread with 0x800, sends the two battery reports and opens touch source one. Not-charging handling clears charger tracking and battery bytes 46 then 45, publishes event byte zero, signals 0x1000, reports battery with charge flag zero and closes touch. It reads both GXT IDs at most three times, requires each to equal 0x50, and delays argument 100 after every failed attempt, including the third. Success stops immediately. Three failures log the stock watchdog/reset text and set mask 0x08 in register three through the native YHM policy; no direct watchdog-reset call is inferred from that message. ID bytes reload inside log gates after callbacks may mutate the escaped buffer. The actual ID provider supplies all three bytes; zeroed C private storage removes reliance on native stack residue for malformed providers.

The native YHM policy initializes its byte to zero, ignores read status, sets mask 0x08 and returns the full write status. It replaces the unconsumed contextual bool API, which incorrectly stopped on read failure. That superseded implementation and declaration are removed under the one-implementation rule. The audit verifies no normal-tree consumer, only that function's C definition removed, all remaining function sizes and read-only data retained, and no new imports. Removal changes vendor object layout; no byte-identity claim is made for that object. Other existing source inputs remain unchanged.

For suspension the dispatcher reads the live task watchdog and calls the existing C worker-parking helper with group one. That helper arms the watchdog, signals suspension and loops on osDelay(UINT32_MAX), matching stock. Emulation observes the first indefinite wait rather than pretending the function returns. Normal return paths preserve the ordinary C ABI.

REA binds code, strings, reset bytes and YHM read/modify/write to the locked artifact. Verification passes 6144 flag-combination pairs (all 512 combinations of nine relevant flags across ID/log scenarios), eight live queue/ID/watchdog mutation pairs, 19 adapter pairs and 256 seeded full-word cases. Tests compare calls and ordering, queue buffer history, byte publications, retry limits, full statuses, log payloads, independent level/state reads, live handle changes, masks and poisoned stacks. Hardware/service/RTOS children are modeled. An additional 30 cases execute the actual C and stock worker-to-dispatcher paths, including startup queue publication, worker flag filtering, resuming the wait loop and suspension. The real C parking helper executes; bootstrap, synchronization, timer/event, hardware and watchdog leaves remain modeled.

Ten compiled defects are rejected: mutually exclusive flags, two ID attempts, omitting the final failed-attempt delay, wrong IRQ payload/ID byte/YHM mask/service event/suspend group, seven battery samples and caching the queue handle. Normal probes pass after mutation testing. The dispatcher object is unchanged by the subsequent vendor-copy retirement.

The open-toolchain build compiles 821 units (739 application, 82 bootloader), with 69 application imports and no new failures or duplicate strong symbols. The dispatcher import closes and none are added. Of 820 prior units, 817 object hashes match; the vendor object changes only for the retirement and two generated boot objects differ with build paths. No G2 source or qualification selection changes. Final application linking, startup storage, physical hardware operation and device boot remain open.
