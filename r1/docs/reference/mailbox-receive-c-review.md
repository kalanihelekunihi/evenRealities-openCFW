# R1 mailbox receive gate in C with isolated storage

`st25/native_mailbox_receive.c` implements stock `0x77be0` over the selected ST25 C providers and existing device object. It reads mailbox mode, requires nonzero mode, reads raw dynamic control and requires byte `0x85`, reads the length byte, clears the first 20 receive bytes, requests length plus two at mailbox offset zero, and dispatches the dock-frame parser only on successful data read. The parser receives the original length, receive pointer and unmodified caller output pointer. No executable blob or assembly is introduced.

The stock dynamic-control provider has an extra raw-byte output absent from the selected SDK's decoded-control API. C uses the SDK register API `ST25DVxxKC_GetMB_CTRL_DYN_ALL` with the typed context at offset 28 (stock 24). A failed control read stops before using its output, including if the backend filled a byte before returning failure; this matches the stock wrapper's failure path, which does not publish that raw byte. Mode and length outputs start at zero. A failed mode read therefore stops deterministically; stock leaves that private mode byte uninitialized. Failed length reads retain zero and request two bytes as stock does. The public API is void because callers discard the incidental result.

Stock receive storage begins at `0x20016b40`, clears 20 bytes and can receive 257 bytes from an eight-bit length plus two. Its immediate neighbor at `0x20016b54` is the seven-timestamp IRQ monitor owner. The new C owner is an independent 257-byte buffer, keeping every native request length while preventing the receive operation from overwriting adjacent task/IRQ state. It continues to clear only the first 20 bytes per call. The larger storage and initialized mode fallback are deliberate improvements, not claims of preserving native memory corruption or private stack residue.

REA binds the 112-byte receive window and object literal to the locked application. Verification executes the actual source SDK mode, control, length and data providers, and the actual native stock providers, with prepared valid IO/context objects. The source object uses its real SDK layout and address field. Register callbacks and dock parser remain modeled. There are 480 normal-path pairs, 512 all-length pairs covering every eight-bit length with success/failure data status, three error-output pairs and 16 initialized fallback cases. Tests compare register/address/count traces, full received data, parser arguments and caller-output mutation, including null forwarding, no-output data reads, raw control/status values, guards, interrupt masks and poisoned stacks. The source ELF buffer extent is checked to cover all 257 bytes. Large native reads are exercised only in emulation; preserving their bus requests does not claim adjacent native state remains valid.

Seven compiled defects are rejected: wrong control byte, short data request, missing clear, parsing a failed read, wrong parser length, undersized storage and ignoring control-read errors. The normal probe passes after mutation testing. Complete BSP registration, the parser body, electrical transactions and physical hardware remain outside this proof.

The open-toolchain build compiles 817 units (735 application, 82 bootloader), with 71 application imports and no new failures or duplicate strong symbols. The receive import closes and the real dock-frame parser becomes explicit. All 816 prior source inputs are unchanged; 814 object hashes match and two generated boot objects differ with build paths. No G2 source or qualification selection changes. Final application linking and device boot remain open.
