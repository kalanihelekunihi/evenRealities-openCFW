# License-free C runtime providers for the R1 bootloader

The normal build now composes six C provider units into the bootloader: shared EABI memory wrappers, pinned musl memcpy/memset/strlen, a shared comparison unit and pinned LLVM compiler-rt `ashldi3.c`. They resolve seven imports: `__aeabi_llsl`, `__aeabi_memclr4`, `__aeabi_memcpy`, `memcmp`, `memcpy`, `memset` and `strlen`. The generic EABI memcpy wrapper is added to the existing canonical memory-wrapper file; no implementation is forked.

The unchanged comparison algorithm and its standard API wrapper move from the application libc files into `native_memory_compare.c`, used by both payloads. This avoids introducing unrelated application string routines and their fixed RAM cursor into the bootloader. Application and bootloader objects for the shared comparison and EABI memory units are identical. In the three changed application objects, existing unrelated allocated sections and normalized relocations remain identical; only the extracted comparison functions and added generic EABI entry differ.

Verification executes 3,551 runtime calls. It covers guarded copy/clear/fill boundaries, alignments, return pointers, signed byte-comparison results, string lengths, legal 64-bit shift counts and ABI preservation. The extracted comparison is checked through both C entry points against a model, with 512 corresponding calls to the stock application comparison routine. REA confirms that stock routine's complete bytes; this is application comparison evidence, not bootloader instruction identity.

Another 209 calls execute the bootloader's actual pinned Nordic nanopb decoder with these C providers. Fixtures include small and full-width values, truncation, continuation overflow, trailing data, high-bit cases and deterministic random 64-bit values. The expectation follows the pinned decoder's loop, including its legacy truncation behavior, rather than imposing a different protobuf validation policy. Input consumption, result/failure output and output guards are checked.

LLVM's shift helper is used only under its valid 0–63 count precondition. The actual nanopb consumer checks `bitpos >= 64` before shifting; counts outside the helper's contract are not claimed to reproduce the application's extended Arm runtime behavior. Callee-saved core registers, stack pointer and interrupt masks are checked. Normal C callee-saved VFP registers are checked, and EABI memory helpers additionally preserve all VFP registers. Private stack, caller-clobbered registers and void returns are excluded.

Eight compiled defects are rejected: EABI copy overrun, nonzero EABI clearing, reversed comparison, lost comparison sign, wrong copy return pointer, wrong fill byte, string-length off-by-one and shifted-result corruption. The full normal probe was rerun afterward.

All 776 R1 units compile: 696 application and 80 bootloader. Both payloads compose without duplicate strong symbols. Of the 769 prior objects, 766 are identical; the three changed application units are audited as described above. Application imports remain 124. Bootloader imports decrease from 34 to 27 with no new imports. R1 source coverage passes (574 source files, none unaccounted). Global coverage retains the existing G2 `resident_rom_thumb_set.S` manifest omission.

See the [structured verification and source/header hashes](boot-runtime-c-review.json) and [stock comparison evidence](boot-runtime-compare-rea.json). The existing DFU signature-verification and CC310 calls are preserved; no verification bypass or cryptographic replacement is introduced. Native boot execution, complete image linking, physical hardware and DFU validation remain unverified. Byte identity and a paid compiler are not required for this route.
