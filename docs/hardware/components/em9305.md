## Separate chip or in-package controller?

The Apollo510B datasheet describes an integrated BLE controller (BLEC):
"48 MHz" 32-bit co-processor with DSP and FPU, "64 kB ROM for secure boot",
"512 kB flash", "64 kB data/instruction RAM", "SPI HCI Transport Layer",
BLE 5.4, −20 to +6 dBm, −97 dBm at 1 Mbps, 48 MHz crystal, `BLE_ENABLE` on
GPIO93 [DS]. The EM9305 datasheet lists the same memory sizes and clock
[DS]. The G2 firmware ships and loads an EM9305 ARC image.

Conclusion [INF, Medium]: the "EM9305" is most likely the Apollo510B's
in-package BLEC (an EM9305-class die), reached over an internal SPI HCI
link, not a separate package on the board. Confirm by board inspection
(open question 1 in the [README](../README.md)).

## Key specifications (DS)

| Item | Value |
|---|---|
| Core | ARC EM7D 32-bit, 48 MHz, DSP + FPU |
| Memory | 64 kB ROM (secure boot), 512 kB flash (+32 kB info area), 64 kB RAM (up to 36 kB usable as IRAM), 2 kB cache |
| Radio | BLE 5.4: 2M, Coded PHY, PAwR, ISO; TX up to +10 dBm standalone EM9305 (+6 dBm as Apollo510B BLEC); RX −94 / −97 / −103 dBm |
| Host interface | Standalone: SPI or UART HCI, plus I2C, I2S/TDM, USB FS, ADC. As BLEC: SPI subordinate HCI with flow control, powered down in sleep; wake-to-HCI-ready ≈1.34 ms |
| Package (standalone) | WLCSP23 1.8 × 1.8 mm or QFN28 4 × 4 mm; 1.1–3.6 V |

## Firmware layout in G2 (FW)

| Address | Content |
|---|---|
| `0x00300000` | 224-B record |
| `0x00300400` | 656-B record |
| `0x00302000` | FHDR (56 B), entry `0x00302028` |
| `0x00302400` | Application, 210,888 B |
| `0x0080xxxx` | RAM (callback slots `0x0080FE04..0x0080FE1F`, stack limits `0x0080E978` / `0x0080F978`) |

Payload wrapper: 124-B record table `{total, count, {file_off, size, addr}…}`
plus 29 erase-sector IDs (`g2/tools/open_cfw.py` validate_em9305).

Host-side HCI facts: Cordio `hci/ambiq/` port, blocking driver, 8 × 260-B TX
records, 256-B RX, 10 s heartbeat, vendor commands `0xFCC4` (RF power),
`0xFC43` (BD address), `0xFFF2` (8-byte local-supported-feature mask) [FW,
`g2/docs/research/cordio-hci-driver-source-recovery.md`].

## Relevance to decompilation

- Disassemble as ARCv2 EM (little-endian) with base addresses above.
- The Apollo side HCI transport is the Ambiq `am_devices_em9305` driver
  family; which IOM (if any) carries it is open (IOM6 is not pinned out on
  Apollo510B, INF Low).
