# Repository layout

Each device owns everything that is specific to it. Shared dependencies,
tooling and cross-device documentation live at the root.

```
openCFW/
├── AGENTS.md, Makefile, make.sh    work instructions and the unified entry point
├── docs/                           roadmap, tooling, methodology, build, hardware/
├── tools/bootstrap/                pinned, fail-closed installer for analysis tools
├── third-party/
│   ├── upstream/                   submodules a rebuild compiles, at exact commits
│   ├── reference/                  comparison-only submodules (update = none)
│   ├── tools/                      analysis-tool submodules
│   └── fetched/                    archive pins with no Git upstream (nRF5 SDK, ...)
├── g2/
│   ├── workflow/                   active procedure, target lock, gates, prompts, task records
│   ├── blobs/official/             versioned MIT firmware mirrors and provenance
│   ├── manifests/                  reference EVENOTA manifest
│   ├── docs/reference/             formats, memory map, toolchains, libraries, protocols
│   ├── symbols/                    naming seeds per payload
│   ├── config-recovered/           recovered upstream configuration and patches
│   ├── research/                   retained Ghidra corpus (hash-indexed)
│   ├── tools/, tests/              container tools, Ghidra pipeline, their tests
│   └── components/em9305/source_image/record_package.py
└── r1/
    ├── blobs/official/             versioned MIT firmware mirrors and provenance
    ├── docs/                       references plus correlation/, boundaries/, closures/, reference/
    ├── config-recovered/           SDK/RTOS/linker/bootloader configuration seeds
    ├── reconstructed/              reference pseudocode for binary-only vendor libraries
    ├── research/                   decompilation corpus, rebuild oracle, source correlation
    └── tools/                      Ghidra export and verification scripts
```

## Where new work goes

| Work | Location |
| --- | --- |
| A newly identified upstream library | a submodule under `third-party/upstream/` at the exact commit, with its row in `third-party/README.md` and the evidence in the device's library/toolchain reference |
| Recovered configuration or a vendor patch to an upstream | `<device>/config-recovered/<library>/`, listed in its README with a SHA-256 and evidence |
| A hardware fact | `docs/hardware/`, cited and tagged with a confidence level |
| G2 campaign outputs (raw exports, reviews, frozen corpus) | `g2/build/pseudocode-first/<campaign>/` locally; admit to a versioned evidence location only through the workflow's freeze step |
| R1 decompilation outputs | `r1/research/`, regenerated by `r1/tools/` |
| Byte-matched C (after the freeze) | a per-payload `src/` tree defined in the C phase of `docs/roadmap.md` |
| A new analysis tool | pinned in `tools/bootstrap/versions.json`, or added as a submodule under `third-party/tools/` |

## Why it is shaped this way

The G2 and R1 devices share no firmware code, so each keeps its own tree. The
dependencies they do share (FreeRTOS, CMSIS, CmBacktrace) are pinned once, in
`third-party/`. The versioned G2/R1 mirrors under `blobs/official/` are tracked
with metadata and checksums. Other local captures remain ignored. See the root
`LICENSE` and `NOTICE` for license terms. Directories removed in the
2026-09-29 cleanup are in Git history at commit `832137ec`. The reference
documents cite them there.
